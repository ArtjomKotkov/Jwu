# Changelog

Раньше история версий жила только в релизах GitHub; дальше — и здесь.

## 3.0.0.dev3

- **Утренняя сводка убрана** (кнопка «⏰ Утренняя сводка», настройка `brief.time`, отправка из
  демона). Доска «что делать» по-прежнему — кнопкой «🗂 Что делать» в меню бота.

## 3.0.0.dev2

- **`jwu update`.** `--check` — есть ли новый релиз на GitHub и что в нём; без флага —
  обновиться: копия БД → `pipx install --force` (из тега релиза или из папки, откуда jwu стоит)
  → аддоны из `pipx inject` обратно с теми же источниками → `jwu install` → перезапуск демона с
  прежним интервалом. Шаг упал — стоп.
- Демон раз в день смотрит релизы; новая версия — в бот «что нового» с кнопками «⬆️ Обновить»
  и «⏰ Отложить на 3 дня». Сам не обновляется.

## 3.0.0.dev1

Начало 3.0: ядро jwu отвязывается от конкретных мессенджеров и рабочих фич — они уезжают в
аддоны. Промежуточные шаги идут версиями 3.0.0.devN без релизов; что сломается и как перейти —
будет в заметках к 3.0.0. Этот шаг ничего не ломает.

- **Аддоны: зависимости и вкл/выкл.** Аддон объявляет `REQUIRES = [...]`; без нужного аддона
  (нет, выключен, сломан) он не подключается — по цепочке. `jwu addons list | enable | disable`:
  выключенный аддон даже не импортируется; от которого зависят другие — только с `--force`.
- Новые хуки аддонов: `agents_dir` (субагенты ставит `jwu install`), `bot_commands` +
  `bot_command` (свои команды бота, попадают в меню «/»), `callback_prefixes` + `bot_callback`
  (свои inline-кнопки), `daemon_tasks` (периодическая работа в демоне со своим интервалом).
- Публичный `jwu.addon_api` для аддонов: store для CLI и MCP, контуры с ботом, отправка с учётом
  тихих часов, лог демона.
- Демон: периодическая работа (место на диске, тихие часы, допуски git и т.п.) идёт в общем
  цикле `jwu-ticks`, а не в потоке Matrix; падение одной задачи не мешает остальным.
- Документация: [docs/addons.md](docs/addons.md).

## 2.15.0

- **Сквош ветки: `jwu_git_squash`.** Склеивает коммиты ветки после базы в один. База по
  умолчанию — точка ответвления от целевой ветки репозитория (после мержей целевой сдвигается,
  чужие коммиты не попадут), или `onto`. Сначала `dry_run` — база, коммиты, файлы, сколько уже
  на origin; потом сообщение и «да» (операция `history` политики).
- Перед сквошем — backup-ссылка (`jwu_git_undo` вернёт) и видимая ветка
  `backup/<ветка>-<время>` со старой историей. После — сверка дерева с исходным; разошлось —
  ветка возвращается, ошибка. Было на origin — пуш только force после отдельного «да».

## 2.14.2

- Зависимость `typer` ограничена `<0.29`: в 0.29 убрали `click_type`, и свежая установка
  через pipx падала при запуске любой команды.

## 2.14.1

- **Бот `/today`: «сегодня» — по часам Мака.** Раньше день считался в поясе трекинга
  воркспейса (для Jira), и при разнице с местным временем часть сегодняшней работы не
  попадала в список. Пояс трекинга для ворклогов не изменился.
- Ежедневный бэкап БД больше не оставляет рядом файл `-shm` (так делают свежие SQLite).
  Чистка бэкапов принимала его за ещё одну копию и могла удалить настоящую.

## 2.14.0

- **Номер работы — свой в каждом воркспейсе** (#1, #2… отдельно в каждом контуре) вместо
  сквозного на всю базу. Инструменты, CLI, бот, доска и тексты показывают и принимают этот
  номер; воркспейс берётся по папке (или `workspace=`). Существующие работы пронумерованы по
  порядку создания; очередь, допуски и журнал git, вопросы дежурства и воркеры переведены на
  новые номера. Старые ссылки «#N» в заметках, Jira и PR остались со старыми номерами.
- Номер выдаёт триггер в БД — его получают и работы, созданные MCP-сервером на старой версии.
  Но старый сервер понимает номера по-старому: после обновления переподключи jwu (`/mcp`) во
  всех открытых сессиях.
- Docker-метка, compose-проект и папка копии работы — по внутреннему id (их разбирает уборка
  по всем воркспейсам). Имена отдают `jwu_job_start`, `jwu_job_resources` и `jwu_job_ports`
  (`docker.label`, `docker.compose_project`) — агент берёт их как есть, а не собирает из номера.

## 2.13.5

- Снапшоты синка хранятся 3 дня вместо 30, чистка — уже с 64 МБ (было 256). Синк пишет полный
  снапшот каждой задачи и PR на каждом проходе, а читаются только последний по каждой
  задаче/PR и прогоны, на которых держатся дельты (их чистка не трогает), — за месяц база
  дорастала до гигабайта. Смена срока не ждёт завтра: отметка о чистке хранит и срок.

## 2.13.4

- БД больше не залипает в блокировке. MCP-сервер живёт днями на одних соединениях: запись,
  упавшая посреди транзакции, держала блокировку до конца сессии, и демон с другими сессиями
  получали «database is locked». Теперь после каждого инструмента MCP недописанное
  дописывается, а если вызов упал — откатывается.
- БД в режиме WAL: чтение не ждёт запись.
- Ежедневный бэкап БД снимается через API бэкапа SQLite (с тем, что ещё лежит в `-wal`).
  Потерянные пустые страницы («Page N: never used») бэкап больше не останавливают: это место,
  а не данные; предупреждение подсказывает `jwu db vacuum`.
- Занятая БД в логе демона — «занята другим процессом», а не «повреждена».

## 2.13.3

- `jwu_git_worktree_remove` убирает копии субагентов, на которых висит замок Claude Code
  («claude agent … (pid …)»: harness не снимает его, пока жива сессия). jwu снимает такой замок
  (`git worktree unlock`) и пишет об этом в ответе (`unlocked`) и в журнале работы. Замок без
  причины на копии в `.claude/worktrees/` снимается так же. Замок с другой причиной jwu не трогает:
  отказ с причиной замка, до бэкапа. То же при уборке (`jwu sweep`) и в `jwu_job_cleanup`.

## 2.13.2

- Доска: одна задача — один пункт. Непрочитанное упоминание по задаче, которая уже на доске,
  приклеивается к её пункту («↩ автор: текст»), а не стоит отдельной строкой в «Ответить».
- Несделанная задача с таким комментом берётся с целью «Разбор возврата QA» (jwu-qa-triage).
- Пункт, задачу которого ведёт работа по другому её пункту, помечен «взято (через №N)».
- `jwu_todo_take` возвращает в ответе тот номер, которым пункт попросили, а не номер на свежей доске.

## 2.13.1

- Один инструмент пуша: `jwu_git_push(job_id=…)` пушит ветку рабочей копии работы (папку
  находит сам, проверяет ветку работы, `force` — как у обычного пуша). `jwu_job_push` — устаревший
  алиас, оставлен для сессий на старых скиллах; скиллы, доки и подсказки хука — на `jwu_git_push`.

## 2.13.0

### Доска `jwu todo`
- Номера значат то, что показали сессии: взятие не перенумеровывает доску; `for_worker` берёт
  по доске оркестратора; `keys=[…]` — номер теперь значит другое, и это отказ, а не соседний пункт.
- Работа ревью чужого PR не попадает в «закрыть работу»: «ушло» — PR смержен/закрыт или я больше
  не ревьюер.
- Задачи на мне в любых незакрытых статусах видны: Backlog — в «сделать», статус вне настроек —
  тоже там, с пометкой; в `--json` поле `statuses`.
- После действий jwu (пуш, переход статуса, коммент/ревью/задача/правка PR) доска дотягивает
  затронутое точечно, без синка; пункт помечен «🔄 обновлено jwu ЧЧ:ММ». Дельты и уведомления
  по-прежнему считает синк.
- Старые упоминания (старше 14 дней) не всплывают в «Ответить» новыми.

### Telegram
- Резервный бот: `jwu configure --telegram-backup-token …`. Основной не отвечает — сообщения,
  кнопки и команды идут через резервный; меню резервного помечено, кнопка «Проверить основной бот».
- Длинные сообщения режутся без разрыва HTML-тегов (сводка тихих часов не уходила с ошибкой 400).
- Тихие часы — по местному времени компьютера, а не по поясу ворклогов.

### Git
- Запрос допуска не теряется: ошибка отправки — в журнале, демон досылает; не больше 3 попыток,
  дальше запрос снимается.
- `jwu_job_push`: отказ политики — ответ с причиной, а не пустая ошибка.

### Прочее
- `jwu jobs --on <дата>` / `jwu_jobs(on=…)`: день работ по местному времени (скилл трекинга
  больше не режет UTC).
- План `jwu_worklog_chain` — общий бюджет 60 с на все запросы, дальше понятная ошибка.
- Даты Jira с «+0300» разбираются и на Python 3.10.
