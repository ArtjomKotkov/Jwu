# Триаж возврата с тестов

Сценарий из аддона `webim-work`; для базового разбора достаточно jwu с доступом к Jira, PR и разрешённому локальному коду. Настроенный SSH необязателен, обработка записи экрана требует `ffmpeg` и `ffprobe`. Не устанавливай или перенастраивай интеграции по ходу. Если источников не хватает, назови пробел, запроси материалы и остановись на доказуемом выводе; не имитируй доступ или воспроизведение.

Сначала загрузи `jwu-session-init` через `skill_view`, если контур и правила этой папки не проверены. Укажи `terminal.workdir` явно, проверь `jwu workspace current --json`: без ошибки, `source=cwd`, непустой `slug`. CLI — `jwu --workspace <slug> …` с тем же `workdir`; MCP jwu — только при совпадении `source`, `slug`, `cwd`, передавай `workspace=<slug>` там, где он есть в схеме. Остановись без подтверждённого контура и правил. Не вызывай Jira для `provider=local`, не подставляй другой контур. Для чтения git бери только подтверждённую папку воркспейса как явный `workdir` и правила её тега. Неоднозначные ключ, PR или комментарий уточни через `clarify` либо в чате.

## Разбор и черновик

1. По точному ключу прочитай локальный `jwu_context(key, workspace)` (кеш и последняя работа) и свежую карточку `jwu_task(key, workspace)` / `task <KEY> --json`. Найди комментарии QA после передачи на тестирование и привязанные вложения (`referenced_by`); сформулируй для каждой претензии «ожидали / получили». Данные из кеша помечай как кеш.
2. Прочитай нужные вложения через `jwu_attachments(key, download=true, kinds=…, dest=…, workspace=…)` или `attachments <KEY> --download --kind <вид> --no-extract --dest <scratch> --json`. Видео заказывай явно `kinds=["video"]` / `--kind video`. Скриншоты загрузи через `vision_analyze`, логи через `read_file`. Для видео: `jwu_video_frames(path, every=5)` / `video-frames <path> --every 5 --json` → контактный лист `sheets`, затем отдельные кадры. Уточни фрагмент с `start`/`end` (CLI `--from`/`--to`) и шагом `0.5–1`. Не запускай вложения, не извлекай архивы автоматически и не раскрывай секреты из них.
3. Из `pull_requests` возьми точный PR и его репозиторий. Сверь `jwu_pr(pr_id, project, repo, workspace)` и `jwu_pr_diff(pr_id, path, project, repo, workspace)` либо `pr <ID> --project <проект> --repo <репо> --json` / `pr <ID> --project <проект> --repo <репо> --diff --path <файл>`. Для локальной версии — `branches <KEY> --json`; если PR недоступен, используй подтверждённые локальные ревизии или назови пробел. Не меняй рабочее дерево. При доступном и разрешённом SSH используй `jwu_ssh_servers` для выбора стенда, логи за время проверки — только чтение.
4. Если доступен `delegate_task`, передай в отдельный разбор принцип «ничего не писать», проверенный контур, правила, ключ, ожидания, комментарии QA, релевантные вложения и дифф. Загрузи проектный скилл через `skill_view`, если он имеется; без делегирования проведи ту же проверку в текущей сессии. По каждой претензии дай вердикт и доказательство (версия/коммит, `файл:строка`, свидетельство из задачи или вложения): **наш баг** (где и как чинить), **старый баг/регресс целевой ветки** (уже без PR), **не баг** (сверка с договорённостью), **нужны данные** (какие именно) или **не воспроизводится** (в каких условиях; «по коду» не означает прогон). Не меняй код в этой работе.
5. Подготовь технический черновик на 3–6 строк. Для внутреннего ответа загрузи `jwu-voice-rewrite` через `skill_view` и выполни чтение существующего профиля без создания. Если профиль и `delegate_task` доступны, используй отдельную редактуру, при необходимости с `jwu_voice_examples(channel="jira_comment", audience="qa", workspace=…)`. Не запускай строку `agent` как имя инструмента; редактор меняет форму, не факты. Покажи весь текст блоком `text`. Если профиль или редактор недоступен, пометь текст техническим, не отправляй как готовый персональный ответ. Для повтора передай предыдущую версию и замечание; сохранение feedback только по отдельному согласию.

## Записи — отдельно от разбора

Разбор не разрешает комментарий, смену статуса или локальную фиксацию. Для внутренней Jira покажи точный ключ/аудиторию и весь финальный комментарий, для смены статуса — доступные сейчас переходы (`jwu_issue_transitions(key, workspace)` / `issue transitions <KEY> --json`) с целью и вариантом «не переводить». Можно спросить в одном `clarify` или сообщении, но решение по комментарию и по переходу должно быть явным и отдельным; при правках покажи снова. Клиентский Support — только отдельная просьба, отдельный клиентский текст и явное согласие, что его увидит клиент; загрузи `jwu-task-comment` через `skill_view`. Если он недоступен, не публикуй клиентский ответ.

- **Комментарий:** до подтверждения обязательный `jwu_comment(key, text, dry_run=true, workspace=…)` или `comment <KEY> --file <файл> --dry-run --json`. Покажи точный текст и аудиторию из предпросмотра; если он указывает на клиента, прекрати внутренний сценарий. После согласия — `jwu_comment(key, text, client_facing=false, dry_run=false, workspace=…)` для внутренней Jira или `comment <KEY> --file <файл> --yes --json` с тем же текстом. Для Support только по его отдельному процессу с явным `client_facing=true` / `--to-client`. Прочитай карточку заново, сверь ID опубликованного комментария и текст. Не заменяй неудавшуюся проверку повторной отправкой.
- **Статус:** перед действием перечитай переходы. Если выбранный переход/цель изменились, снова покажи варианты и спроси. Только на явное «да» — `jwu_issue_transition(key, target, workspace)` / `issue transition <KEY> <target> --yes --json`. Перечитай карточку и проверь фактический статус. Если были согласованы оба действия, построй порядок без зависимости от неподтверждённого результата и отчитайся отдельно по каждому; при неожиданном исходе остановись.
- **Локальная заметка:** предложи короткое «вернули с тестов: …». Только по согласию — `jwu_note(key, text, kind="status", pin=true, workspace=…)` / `note <KEY> <текст> --kind status --pin --json`; проверь через `jwu_notes` / `notes <KEY> --json`. Новая/переоткрытая работа для исправления или закрытие работы по разбору — отдельный выбор, затем соответствующий `jwu-start-job`, `jwu-continue-job` или `jwu-close-job` через `skill_view`, если доступен. Не меняй работу автоматически.
- **Правка стиля:** после отдельного согласия запиши `jwu_voice_feedback` с `channel="jira_comment"`, `audience="qa"`, `verdict="edited"` или `"rejected"`, `before`, `after`, `reason` и проверенным `workspace`. Перечитай профиль и проверь запись; не копируй в профиль приватные данные задачи.
