# jwu: разбор падения CI в Hermes

Диагностика сборки не разрешает исправление. Если пользователь просит исправление, перейди к разделу «От анализа до первой правки» в **jwu-start-job**: согласуй объём работ и проверки до первой правки. Диагностика не разрешает sync, коммит или пуш; допуски git проверяй отдельно по этому же скиллу.

Сначала загрузи `jwu-session-init` через `skill_view`, если правила и контур ещё не проверены. При `prs_enabled=false` не вызывай CI: сообщи, что интеграция PR в этом контуре выключена. Для Jira jwu читает Bitbucket/Jenkins, для GitHub — checks/Actions.

1. Определи числовой `pr_id` и при необходимости репозиторий / проект. URL можно передать как `url` для конкретной сборки, но он не заменяет обязательный `pr_id`. Не угадывай репозиторий или целевую ветку. Если запрос нельзя разрешить по известным данным, уточни в чате или через `clarify`.
2. Для текущего head запроси MCP `jwu_builds(pr_id, project, repo, workspace)` (обычно `mcp_jwu_jwu_builds`) или `jwu --workspace <slug> builds <pr_id> [--project P] [--repo R] --json` в проверенном `workdir`. Отдели `kind=other` от тестов, запущенные и ожидающие прогоны — от упавших; если красный только старый прогон, не называй текущий head красным.
3. Для упавшей сборки запроси `jwu_build(pr_id, project, repo, url, workspace)` или `jwu --workspace <slug> build <pr_id> [--project P] [--repo R] [--url URL] --json`. Опциональные параметры передавай только когда они известны. Покажи конкретный упавший кейс или шаг, ссылку и короткую выдержку из отчёта. Отсутствие отчёта/логов не равно зелёной сборке.
4. Раздели подтверждённую причину и гипотезы (изменение PR, регресс целевой ветки, инфраструктура). Для сравнения используй только доступные данные; не делай `git fetch`, checkout или запуск CI автоматически. По умолчанию разбирай в текущей сессии. Если независимый анализ длинных логов полезен, можно передать проверенные факты Hermes `delegate_task`, если доступен, без секретов и без разрешения на изменения. Не требуй установленного агента Jenkins для Claude Code.

Итог: какая сборка и какой head/прогон, что упало, что подтверждено, чего не хватает и что проверять дальше. Не меняй код, CI, статусы и комментарии без отдельного запроса.
