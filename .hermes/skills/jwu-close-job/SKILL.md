# jwu: закрыть работу в Hermes

Сначала `skill_view` → `jwu-session-init`, если нет подтверждённых `source=cwd`, `slug` и правил. Прочитай правила задействованных тегов, соблюдай ⛔. MCP только в совпавшем контуре/cwd; `workspace=<slug>` где поддерживается. CLI ниже — `jwu --workspace <slug> …` с проверенным `terminal.workdir`. Выбор — через `clarify`, если доступен и подходит, иначе пронумерованные варианты в чате; дождись ответа. `provider=local` — без внешних задач и PR; при `prs_enabled=false` — без PR/CI.

1. **Проверь цель и ID.** Текущая работа или `job show ID --json`; по ключу `jwu_jobs(task=…)` / `jobs --task KEY --json`, без якоря `jwu_jobs(status="active")` / `jobs --status active --json`. Несколько кандидатов — спроси. Сверь журнал, незакрытые `todo`/баги, а там, где запрос и провайдер позволяют, — живые PR и CI. Не принимай кеш за актуальный статус.

   | Цель | Что значит «готово» |
   |---|---|
   | Сделать задачу | Правки, тесты и ревью выполнены; коммит/пуш и PR созданы или обновлены, если требуются |
   | Конфликт PR | Целевая ветка учтена, конфликт разрешён, результат запушен, PR мержится |
   | Красный CI | Причина устранена и новая сборка зелёная либо доказано и записано, что сбой вне изменений работы |
   | Правки по ревью | Правки запушены, относящиеся к цели замечания закрыты или на них ответили |
   | Анализ | Вывод получен, записан и показан пользователю |

   Цель не достигнута — что осталось; без явного «закрывай всё равно» не закрывай. При уходе на другое запиши следующий `todo` и оставь открытой или по запросу `jwu_job_status(job_id, status="paused")` / `job status ID paused`.
2. **Подготовь безопасное закрытие.** Итог `summary` одной простой строкой за весь цикл, без хешей, путей и номеров сборок (для сводки и учёта времени). Зафиксируй исходное место (`jwu_disk()` / `disk --json`) и запусти `jwu_job_cleanup(job_id, dry_run=true, force=false)` / `job cleanup ID --dry-run --json`. Проверь ресурсы (`jwu_job_resources` / `job resources ID --json`): только копии, compose-проект, помеченные или явно зарегистрированные этой работой контейнеры/сети/тома/образы/пути и порты. Чужое, общие кеши и Docker prune не трогай. Ошибка превью, сомнение в принадлежности или доступе к Docker — стоп. Пустой `kept` сам по себе не доказательство: в каждой существующей копии отдельно успешно прочитай ветку/HEAD и `git --no-optional-locks status --porcelain`; проверь достижимость HEAD из подтверждённой сохранённой удалённой ветки, если есть локальные коммиты работы. Не считай ошибку git, detached HEAD или сомнительные/устаревшие refs доказательством, что потерь нет. Для удаления копий проверь политику `worktree` для нужного пути и ветки (`git policy check worktree --path REF --branch BRANCH --where job`); получи требуемое согласие, при `deny` или неразрешённом `grant` остановись. Hermes не гарантирует git-хук, cleanup не должен обходить политику.
3. **Собери решение.** Если `kept` пуст и отдельная проверка подтвердила безопасность, покажи только типы удаляемых ресурсов, не длинный список. Если отдельная проверка расходится с превью — не закрывай и не используй force до выяснения причины. Если `kept` не пуст — **стоп**, покажи точные копии и риски (незакоммиченное/незапушенное). Предложи защищённый коммит/пуш из `jwu-start-job`, оставить открытой или отдельно подтвердить потерю перечисленных данных. Обычное согласие на закрытие или удаление не разрешает `force`. Повтори превью после любых изменений.

   Для стандартного закрытия предложи «Закрыть и взять следующее с доски» (если применимо, первым, если работали с доской), «Закрыть», «Оставить открытой». В вопросе — ID, итог, что уберётся/останется. Явное «закрой» на уже показанный точный итог и безопасный объём не требует дублирующего вопроса. Выбор следующего — только после подтверждённого закрытия, через `skill_view` → `jwu-todo`, первое свободное по приоритету, по его правилам.
4. **Закрой и проверь.** Только после выбора: `jwu_job_close(job_id, summary=…, cleanup=true)` / `job done ID --summary TEXT --cleanup`. Это пишет локальную handoff-выжимку на задачу и PR, не публикует комментарий. При явно подтверждённой потере, неизменившемся списке и разрешённой политике сначала `jwu_job_cleanup(job_id, dry_run=false, force=true)` / `job cleanup ID --force --json`, проверь результат, затем закрывай. `closed=false`, ошибки или `cleanup.kept` — разберись, не утверждай `done` и не повторяй вслепую. Проверь `job show ID --json` (`done`, итог), ресурсы и заметку, где применимо; `jwu_disk()` / `disk --json` на том же пути для оценки освобождённого места. Если измерение ненадёжно — не выдумывай число.
5. **Оставшиеся внешние действия — единым списком только применимого.** Переход задачи (`jwu-task-status`), закрыть выполненные задачи PR (`jwu-pr-task`), ответить в треды (`jwu-pr-comment`), записать время (`jwu-track-time`), шаги активных аддонов из `jwu_addons()` → `after` для `jwu-close-job`. CLI `addons list --json` не возвращает `after`; используй только известные по проверенной документации подсказки активных аддонов. У GitHub нет таймтрекера jwu. Не предлагай сделанное на финише. Через `skill_view` загружай только нужные скилы; если аддон/интеграция недоступны, скажи. Тексты подготовь в доступном согласованном стиле, покажи перед отправкой. Выполняй только одобренные шаги, перечитывай точный внешний объект после записи. Если ничего не осталось — не спрашивай. В итоге: ID, статус, что убрано/осталось, место и подтверждённые ссылки.

## Полное удаление, не закрытие

Только по запросу удалить точную работу. Покажи ID, что журнал и связи исчезнут навсегда, и если итог использован для учёта времени — что потеряется история. Пройди то же превью, проверку принадлежности/политики и защити `kept`. После явного согласия на удаление — `job delete ID --yes`; `--force` только после отдельного явного согласия потерять конкретные непушенные/незакоммиченные данные. Проверь, что `job show ID --json` возвращает именно «не найдена» в подтверждённом контуре, а не ошибку доступа или связи; отчитайся о частичной уборке, если удаление не состоялось.
