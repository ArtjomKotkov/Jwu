# Отчёт за день из ворклогов Jira

Нужен включённый аддон `webim-work` с `reportbot`, недельная ссылка нужного проекта и авторизованный сервер Jira в сервисе отчётов. CLI даёт статус и предпросмотр; для отправки **точно согласованных** отчёта и плана нужен MCP `jwu_reportbot_send`. Наличие CLI не подтверждает наличие MCP или доступ. Не устанавливай аддон, не меняй настройки интеграции и не открывай конфиги/хранилище секретов ради обхода.

## Контур и черновик

Если контур и правила ещё не проверены, загрузи `jwu-session-init` через `skill_view`. Установи папку проекта: `terminal` с явным `workdir`, `jwu workspace current --json`, результат без ошибки, `source=cwd`, непустой `slug`. CLI: `jwu --workspace <slug> …` с тем же `workdir`. MCP — только при совпадении `source`, `slug`, `cwd`, в каждом вызове `workspace=<slug>`. При неподтверждённом контуре, отсутствии правил или не-Jira контуре остановись: не выбирай другой контур автоматически.

1. Определи конкретный день `YYYY-MM-DD`; по умолчанию сегодня, проверенное в часовом поясе отчёта. Если из запроса и правил нельзя однозначно определить день, проект или Jira, уточни через `clarify` или в чате. Не отправляй автоматически после трекинга времени.
2. На каждый день нужна ссылка его недели. `jwu_reportbot_status(workspace=…)` / `reportbot` показывает состояние (детали по дням текущей недели); для запрошенного дня ориентируйся на `draft`. Если ссылки нет, попроси добавить её через доверенный канал сервиса/бота. Когда пользователь явно просит привязать присланную ссылку, сначала подтверди контур и доверенный сервис; затем `jwu_reportbot_link(url, workspace=…)` или `reportbot link <url>` через канал, не раскрывающий секрет в логах/выводе. Если такой канал недоступен, пусть пользователь добавит её напрямую. Это отдельная запись в локальные секреты и запрос к сервису, не согласие на отправку. Сверь диапазон недель в статусе, применимость к дню — в `draft`; не меняй выбор проекта при неоднозначности.
3. Вызови `jwu_reportbot_draft(date, workspace=…)`: `from_jira.report` и `from_jira.plan` — предлагаемые, `saved` — уже сохранённые. CLI-предпросмотр: `reportbot draft <дата>` (показывает новый текст и предупреждает о перезаписи, не возвращает сохранённый текст). Если ворклогов нет, предложи отдельно затрекать время, загружая `jwu-track-time` через `skill_view`, если он доступен; не трекай и не отправляй сам. При ошибке доступа или отсутствии данных не сочиняй отчёт.
4. Покажи целиком дату, проект, отчёт и план в блоках `text`, отметь, если сохранённые данные будут заменены. Учти правки пользователя и снова покажи полный итог. Предпросмотр, присланная ссылка и просьба «заполни» не заменяют явное «да» на показанные дату, цель и текст. Для подтверждения используй `clarify`, если доступен, иначе чат.

## Отправка и проверка

После явного подтверждения убедись, что цель не изменилась; если сохранённый отчёт/план изменился с предпросмотра, покажи конфликт и получи новое согласие. Вызови `jwu_reportbot_send(date=…, report=…, plan=…, user_approved=true, workspace=…)` с точным согласованным текстом (включая пустой план, если так согласовано). **Не заменяй его `reportbot send <дата> --yes`**: CLI заново собирает ворклоги и не принимает показанные `report`/`plan`. Если подходящего MCP нет, остановись на черновике и предложи пользователю отправить вручную.

Повторно вызови `jwu_reportbot_draft` для той же даты/цели и сравни **`saved.report` и `saved.plan`** с одобренными: `ok`, `filled` и ссылка сами по себе не подтверждают содержимое. При ошибке или расхождении сообщи, что сохранение не подтверждено, не отправляй повторно вслепую. Сообщи результат и дату; ссылку отдавай только если она не содержит секрета. URL недели из MCP содержит токен: не эхоируй его (даже в Markdown-ссылке), укажи открыть свой отчёт из уже имеющейся ссылки. Не показывай токены, приватные URL и сырые ответы в сводках.
