# jwu: контекст задачи, PR или ветки в Hermes

Сначала загрузи `jwu-session-init` через `skill_view`, если в контексте нет проверенного контура и правил этой папки. Используй выбранный там транспорт, явный `workspace` и тот же `workdir` для CLI.

- **Чтение:** вызови MCP `jwu_context(key, workspace)` (обычно `mcp_jwu_jwu_context`): это локальные заметки, последняя работа и кеш задачи/PR. CLI-фолбэк: `jwu --workspace <slug> notes <key> --json`; он показывает только заметки, не выдавай их за полный отчёт. Пустой кеш не доказывает отсутствие задачи. Покажи статус, важные решения и следующий открытый вопрос; отделяй кеш от свежих данных. Не ходи в Jira/Bitbucket/GitHub без соответствующего запроса.
- **Ключ:** точный ключ задачи, `PROJ/repo#42` для PR Bitbucket (предпочитай `pr_note_key`, если уже получен) или точное имя ветки. Голый `#42` без контекста не разрешай догадкой: только если реально неоднозначно, уточни сущность в чате или через `clarify`.
- **Запись:** только по явной просьбе сохранить заметку. Вызови `jwu_note(key, text, kind, pin, workspace)` или `jwu --workspace <slug> note <key> <text> --kind <kind> --json` с корректным shell-экранированием обоих аргументов. Виды: `status`, `decision`, `gotcha`, `todo`, `context`; `status` — одна строка, используй `pin=true` / `--pin`. Сверь результат повторным чтением. Не создавай и не закрывай работу ради заметки, не пиши комментарий во внешний сервис вместо неё.
