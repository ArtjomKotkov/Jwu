# jwu: трекинг времени в Jira

Загрузи `skill_view(name="jwu-session-init")`; без проверенной привязки и правил пройди его. Требуй `source="cwd"`, непустой `slug` и совпадающий `cwd` из `jwu workspace current --json` с явным `terminal.workdir` проекта. Соблюдай ⛔ и правила тега. Ниже CLI-команды идут после `jwu --workspace <slug>` с тем же `workdir`. MCP необязателен: только если `jwu_workspace_current` подтверждает тот же `source`, `slug`, `cwd`; передавай `workspace=<slug>` в поддерживаемые вызовы. Если чтения не хватает, уточни через `clarify`, если доступен, иначе спроси в чате.

Только `provider=jira`. В другом контуре предложи локальную заметку в существующей работе (`job add JOB_ID TEXT --kind note --no-git`), не записывай без просьбы. Если нужна только выжимка, остановись на плане.

## Собрать день

1. Зафиксируй дату `YYYY-MM-DD` (по умолчанию локальный день компьютера, а не UTC, проверь его инструментом). `jwu_jobs(on=DAY, tz=…)` / `jobs --on DAY [--tz ZONE] --json`: `summary` — основа описания, `today` — записи дня. Не режь UTC timestamp вручную. У открытой работы без итога посмотри записи дня: если есть признаки завершения, предложи закрыть отдельно через `skill_view(name="jwu-close-job")`, если доступен; иначе кратко опиши сделанное за день. Без рутины коммитов/пушей и внутреннего ревью, тесты — если это отдельная работа; конфликты и слияние упоминай по существу.
2. Список ревью из `prs --mine-reviews --on DAY --json`: статус пользователя `APPROVED`/`NEEDS_WORK`, дата из ленты активностей, только OPEN PR. Найди ключ Jira в заголовке, сгруппируй по ключу, не задваивай с работой «Ревью PR». Покажи кандидатов и запроси длительность; описание ровно «Ревью». Отсутствие результата не повод добавлять ревью; уже смерженные пользователь может продиктовать.
3. Добавь продиктованные строки к найденным, если пользователь явно не сказал «только это»/«вместо». Уточни дополнительные встречи/работы, реальный ключ Jira и длительность для каждой строки. Не выдумывай время; формат `2h 30m`, `45m`, `1d 4h`.
4. Проверь точные ключи и имеющиеся записи: `jwu_worklogs(on=DAY, keys=[…])` / `worklogs --on DAY KEY… --json`. Дополнительно без ключей видны записи по найденным через JQL задачам (для сверки всего дня). Прочитай карточки непроверенных ключей. Некоторые ошибки чтения пропускаются реализацией worklogs: пустой ответ при проблемах доступа не доказывает отсутствие записей. Покажи имеющееся время и не добавляй повторно без явной просьбы о добавлении сверх.

## План и запись

1. Пояс `jwu_worklog_timezone()` / `worklog-tz`; если пусто, спроси один раз. Используй пояс явно в плане; сохраняй как локальную настройку только по согласию (`jwu_worklog_timezone(tz=…)` / `worklog-tz ZONE`, затем прочитай). Возьми указанное пользователем начало (`HH:MM`) или применимое правило. Если начала нет и известно `existing_ends_at`, предложи его в плане; уточни только когда время нельзя определить. Порядок строк — порядок непрерывной цепочки.
2. Без записи: `jwu_worklog_chain(items=[{"key":…, "time":…, "comment":…}], start=…, on=DAY, tz=…, dry_run=True)` / `worklog-chain --start HH:MM --on DAY --tz ZONE --item 'KEY|1h 30m|описание' … --json` **без `--yes`**, один `--item` на строку. `confirm_required` здесь означает план, не ошибку. Покажи точный payload, дату, пояс, интервалы, длительности, полные комментарии, итог и уже записанное; CLI обрезает пробелы по краям сегментов `--item`, сверяй текст из фактического плана. При `overlaps` предложи сдвиг; уточни, если проверка дублей не удалась.
3. Явное «да» на это точное превью, в том числе уже полученное для неизменных интервалов и текстов, разрешает тот же `dry_run=False` / CLI с `--yes`. Любая правка параметров или изменения существующих записей — новый план и новое «да». Не запускай по одной записи вместо цепочки без просьбы. `failed` останавливает цепочку; для `written` перечитай затронутые ключи за соответствующие даты и сопоставь начало, длительность, текст и доступные ID сравнением с исходным списком. Сообщи, что проверено и где остановилось; остаток — новый план с конца записанного, без повтора уже сделанного.
4. Дай `jwu_worklog_links(date=DAY, keys=[…])` (Jira и Support, если есть) при доступном MCP. Отдельной CLI-команды для этих ссылок нет: дай проверенные ссылки на задачи, если доступны, либо ключи с оговоркой. Если `jwu_addons()` (без `workspace`) показал активное продолжение `after` для этого скилла, предложи его; при просьбе загрузи названный скилл через `skill_view`, подтверждение любой внешней записи отдельное. CLI `addons list --json` не показывает `after`, не угадывай продолжение.

## Одна запись, правка, удаление

- Только по отдельному запросу на одиночную запись: `jwu_worklog(key, time, comment=…, started=…)` / `worklog KEY TIME --comment TEXT --started ISO --json`. `started` — ISO 8601 со смещением. **У CLI нет `--yes`/dry-run, он пишет сразу**; не запускай даже для предпросмотра. Сначала сверка дублей, точное превью и отдельное свежее «да».
- Правка и удаление своих записей: найди точный ID в `worklogs` за нужную дату, покажи «было → стало» или удаляемую запись, получи новое явное «да». `jwu_worklog_edit(key, worklog_id, time=…, started=…, comment=…)` / `worklog-edit KEY ID [--time TIME --started ISO --comment TEXT] --yes --json`; `jwu_worklog_delete(key, worklog_id)` / `worklog-delete KEY ID --yes --json`. Перечитай по точному ключу и дате (старой и новой при переносе), сверь ID, поля или отсутствие. При неясном результате не повторяй запись вслепую.
