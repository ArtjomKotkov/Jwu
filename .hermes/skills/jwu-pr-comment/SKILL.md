# jwu: комментарии и ревью PR

Загрузи `skill_view(name="jwu-session-init")`; без проверенной привязки и правил пройди его. Требуй `source="cwd"`, непустой `slug` и совпадающий `cwd` из `jwu workspace current --json` с явным `terminal.workdir` проекта. Соблюдай ⛔ и правила тега. Ниже CLI-команды идут после `jwu --workspace <slug>` с тем же `workdir`. MCP необязателен: только если `jwu_workspace_current` подтверждает тот же `source`, `slug`, `cwd`; передавай `workspace=<slug>` в поддерживаемые вызовы. Если чтения не хватает, уточни через `clarify`, если доступен, иначе спроси в чате.

Любая внешняя запись: точное превью цели и всех аргументов, полный текст в блоке кода, новое явное «да» на это превью. При правках — новое превью. Только после согласия `--yes`/пишущий MCP. Перечитай точную цель; не повторяй запись вслепую при неясном исходе. Без изменений в git, без обязательного клона; Bitbucket и GitHub, не `local`.

- Карточка: `jwu_pr(pr_id, project=…, repo=…)` / `pr ID --project PROJECT --repo REPO --json`. Найди автора, ID, текст и якорь в `comments`, связанные `open_tasks`. Вложение треда по `comment_id`: `jwu_pr_attachments(pr_id, download=True, dest=…)` / `pr ID --download --dest DIR`; читай из разрешённого scratch (`vision_analyze` для картинок, `read_file` для текста).
- Дифф: `jwu_pr_diff(pr_id, path=…, numbered=True)` / `pr ID --diff --path FILE --numbered`; большой дифф читай по файлам. Inline: правый номер строки новой версии, для удалённой — левый номер и `side="FROM"`. Строка должна быть в диффе, тип выводится из него. Во всех вызовах PR передавай проверенные `project` и `repo` (CLI: `--project` и `--repo`).
- Создание: общий комментарий, ответ в тред или inline. `jwu_pr_comment(pr_id, text, reply_to=…, path=…, line=…, side=…)` / `pr-comment ID -m TEXT [--reply-to CID | --path FILE --line N --side SIDE] --yes --json` (`-F FILE` для текста из файла). Укажи в превью автора и ID треда или файл, строку, сторону. По карточке проверь ID, текст и привязку; при `anchored=false` скажи, что комментарий ушёл, но не виден в диффе. Удаление и повтор — отдельные согласия.
- Свой комментарий: проверь авторство, покажи «было → стало» или удаляемый текст и ID. `jwu_pr_comment_edit(pr_id, comment_id, text)` / `pr-comment-edit ID CID -m TEXT --yes --json`; `jwu_pr_comment_delete(pr_id, comment_id)` / `pr-comment-delete ID CID --yes --json`. Bitbucket не удалит комментарий с ответами. Перечитай по ID. Свой PR: заголовок и/или описание через `jwu_pr_update(pr_id, title=…, description=…)` / `pr-edit ID [--title TITLE] [-F FILE] --yes --json`; проверь поля по карточке, ревьюеров не меняй.
- Ревью — отдельное «да», даже если комментарий уже согласован; не предлагай апрув заодно. `jwu_pr_review(pr_id, status, text=…)` принимает `APPROVED`, `NEEDS_WORK`, `UNAPPROVED`; CLI `pr-review ID approve|needs-work|unapprove [-m TEXT] --yes --json`. Снять апрув можно только в Bitbucket. У GitHub `needs-work` требует текст отзыва; Bitbucket отправляет текст отдельным общим комментарием, покажи оба эффекта. Сверь свой статус в `reviewers` карточки и отдельно текст, если виден в `comments`; сообщи, если часть не проверяется.
- После проверенного ответа: для связанной задачи загрузи `skill_view(name="jwu-pr-task")`, закрытие — отдельно. Локально уточни судьбу замечания: `jwu_pr_review_history(pr_id, project=…, repo=…)` / `review history ID --project PROJECT --repo REPO --json` → опознай тред в `findings`, `F<ID>` → `jwu_review_fate(["F<ID>"], fate, reason=…, ref=…, commit=…)` / `review fate F<ID> --fate FATE --reason WHY --ref REF [--commit SHA]`. `ref` — ID ответа, `fixed` — с реальным коммитом, для `rejected`, `out_of_pr`, `fabricated` — краткий довод.

## Голос пользователя

Сначала технический черновик с фактами. Загрузи `jwu-voice-rewrite` через `skill_view`: используй его правила чтения существующего профиля без создания, выбора точной роли (включая штатный fallback) и отдельного прохода формы. Если профиль недоступен, оставь нейтральный технический черновик. Если доступен `delegate_task` и инструкции роли, передай их, профиль и необходимые примеры вместе с черновиком, контекстом, ограничениями и каналом (`pr_reply`, `pr_comment`, `pr_review_body`, аудитория `colleague`). Делегируй только форму, без записей; иначе вычитай сам по профилю. Примеры: `jwu_voice_examples(channel, audience=…)` / `voice examples CHANNEL --audience AUDIENCE --json`. «Не похоже на меня» — пересмотри с прежним текстом и замечанием, сверяясь с примерами. Если при сжатии что-то опущено, назови это отдельно от копируемого текста. Локальная запись правки только по отдельному согласию: `jwu_voice_feedback(channel, verdict, before, after, reason, audience=…)` / `voice feedback --channel CHANNEL --verdict VERDICT --before OLD --after NEW --reason WHY --audience AUDIENCE`.
