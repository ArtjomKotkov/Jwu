# jwu: контекст сессии Hermes

Перед действиями через jwu установи реальную папку проекта Hermes. Для `terminal` передавай её явно как `workdir`; не используй cwd из предыдущего проекта. Запроси `jwu workspace current --json` в этой папке и проверь `source == "cwd"`, непустой `slug`, отсутствие ошибки. При несовпадении остановись: активный, единственный или заданный через окружение контур не подтверждает привязку папки. Не выполняй `jwu init` автоматически.

Если доступен MCP `jwu`, вызови `jwu_workspace_current` (обычно `mcp_jwu_jwu_workspace_current`). Используй его только если `source`, `slug` и `cwd` совпадают с проверенным контуром и папкой проекта. MCP-процесс может работать из другой папки даже после смены проекта в Desktop; тогда оставайся на CLI для этой сессии. Для последующих MCP-вызовов передавай `workspace=<проверенный slug>`, если параметр поддерживается. Для CLI — `jwu --workspace <slug> …` с тем же `workdir`.

1. Прочитай общие правила из `rules_md` или `jwu --workspace <slug> rules --json`. Когда известен тег репозитория, дотяни `jwu_rules(tag=…)` / `rules --tag <tag> --json`. Если правило ссылается на инструкцию, открой её по имени, а не угадывай процедуру.
2. Проверь активные работы (`jwu_jobs(status="active")` / `jobs --status active --json`) и планы (`jwu_plan_now` / `plan now --json`). Для `provider=local` посмотри `jwu_features` / `feature list --status open --json` и `--status in_progress`; задачи и PR из внешних трекеров не запрашивай. Для `jira` / `github` не обновляй доску и не ходи во внешние сервисы без отдельного запроса.
3. Коротко сообщи контур, провайдер, существенные запреты, активные работы и планы. Не создавай jobs, не меняй статусы и не запускай воркеров. Повтори проверку при смене проекта или если подтверждённые правила выпали из контекста.

Это не замена git-хуку jwu: наличие MCP и скила не означает, что shell Hermes автоматически блокирует пишущие git-команды.
