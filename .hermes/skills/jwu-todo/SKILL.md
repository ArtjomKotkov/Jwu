# jwu: что делать и раздача по сессиям

**Work Main показывает доску, но не берёт работу.** На «покажи доску» используй штатный показ ниже, на «обнови» — штатное обновление. Сохранение технического снимка (`session`, номера, ключи и разделы) — часть показа, не бронь. Для поручения по номеру бери точный ключ и раздел только из снимка, показанного пользователю. Не обновляй доску для расшифровки старого номера. Снимок потерян — попроси точный ключ/PR или покажи новую доску и дождись нового выбора. Передай через **jwu-orchestrator** ключ/полный PR, раздел и ограничения пользователя. Взятие, журнал и закрытие — только в чате воркера; доставка брифа не подтверждает взятие.

Если контур и правила не подтверждены, загрузи `skill_view(name="jwu-session-init")`. Бери подтверждённый MCP с `workspace=slug` или CLI `jwu --workspace SLUG …` с явным `terminal(workdir=<проект>)`; параметры через argv или `shlex.quote` по одному. Это доска jwu, не внутренний `todo_list` Hermes. Без запроса на взятие не заводи работы. В `local` не ходи за внешними задачами/PR, используй кеш (`refresh=False` / `--no-refresh`).

## Показ

- `jwu_todo()` — кеш jwu, автосинк через демон при возрасте >30 минут; по «обнови» — `refresh=True`. Укажи, что обновление может занять несколько минут; если синк уже идёт, не запускай параллельный, тот же `refresh=True` ждёт проход. Если `refreshed.ok=False`, покажи кеш с его возрастом и ошибку одной строкой. CLI — `todo [--refresh]` для готовой отрисовки и `--json` для структуры (JSON CLI не содержит `markdown` и `refreshed`; не скрывай stderr). Не запускай `jwu sync` вручную параллельно демону.
- `markdown` из MCP покажи целиком дословно, без изменения таблиц, колонок, номеров и порядка. Для CLI покажи исходную отрисованную доску как есть, а не пересказ; для структурной сверки используй тот же `-s`, `--no-refresh --json`, проверь соответствие номеров. Собственная строка максимум одна. «Давно: закрыть или продолжить?» — `jwu-close-job` / `jwu-continue-job`. «Взято через №N» — смотри связанную работу в №N, не бери дубль.
- Имя не спрашивай: jwu выдаёт `session`/имя в шапке. MCP держит имя на уровне процесса; если endpoint один на несколько сессий Hermes, не полагайся на него как на разделение сессий: сохраняй отдельное имя каждой сессии и явно передавай его вместе с `keys`; при неподтверждённой изоляции не делай взятия. CLI одноразовый, сохраняй выданное при первом показе имя и используй то же `-s SESSION` до конца сессии. Пользовательское имя передавай, только когда пользователь сам его задал; не переиспользуй имя другой сессии.

## Взятие (локальная запись) и работа

`simple` — мои конфликты/красные сборки без замечаний; `build` — нет сборки для head, очереди CI и идущих автотестов в репо с ожидаемым CI (`todo.build.required`); `fixes` — NEEDS_WORK, открытые задачи PR, возврат QA, включая их конфликты/сборки; `demo` — Dev at stand / Demo (`todo.statuses.demo`); `todo` — не начатые/активные задачи на мне без открытого моего PR, до In Review; `review` — чужие PR на мне.

1. Воркер проходит «Вход по поручению с доски» в **jwu-start-job**: проверяет контур, находит точный ключ в том же разделе под собственным `session`, проверяет прежние работы, берёт свободный пункт по своему номеру и `keys`, затем сверяет `taken`/`skipped` и владельца. Например, «P/r#42 из review, только черновик» не разрешает взять другую строку или опубликовать результат. При нескольких выбранных строках номера и ключи идут в одном порядке. Только по прямой просьбе воркер берёт всю группу: `jwu_todo_take(group=…, session=своя_сессия, workspace=slug)` (свободные пункты; для аддона сначала проверь защиту от двойного взятия). При пропуске не переходи ко всей группе.
2. Среди взятых `todo` в Jira ещё не в работе (Open / To Do / Selected for Development) — один множественный выбор «Перевести в In Progress?» (`clarify`, иначе пронумерованные варианты в чате). Сам выбор явно указанных задач и перехода — согласие на запись; только выбранные — через `jwu-task-status`, без повторного вопроса при неизменном превью. Остальные не трогай.
3. Работы уже заведены: загружай `jwu-continue-job`, проходи по одной начиная с первой, прочитай план фаз из `jwu-start-job`. Правки только с согласия по правилам. По достижении цели — `jwu-close-job`; следующую начинай после закрытия или фиксации паузы записью `todo`. При наличии `↩ автор: текст` прочитай непрочитанный комментарий в начале любой работы. «Разбор возврата QA»: прочитай замечание, найди подсказку поддерживаемого аддона (`jwu_addons()` / `addons list --json`, не предполагая равенства полей), ответ QA — только с «да». Для исправления сначала сверь план и проверки по `jwu-continue-job`; согласие на ответ не разрешает восстановление копии, стенда или правки.
4. Маршруты:
   - `simple`: влить target и/или `jwu-build-failure`, затем ревью, коммит/пуш по фазам с «да».
   - `fixes`: `jwu_pr`, задачи PR, коммент QA; правки, ревью, коммит, ответы в тредах только по согласованным действиям.
   - `build`: `jwu_builds(pr_id, project, repo)` / `builds ID --project P --repo R --json`; независимые чтения можно батчить. Если CI/автотесты queued/running или head уже собран, повтор не нужен. Есть источник автотестов — покажи точный запуск, после «да» `jwu_pr_autotests_run(pr_id, project, repo, user_approved=True)` / `pr-autotests-run ID --project P --repo R --yes`. Иначе `jwu_rules` / `rules --json` и `guide show NAME`, запуск принятым способом (коммент/коммит/кнопка только после «да»). Неизвестно как — спроси и предложи записать правило, не запускай наугад. Перечитай CI; подтверждённый запуск запиши и закрой работу итогом «запустил сборку PR #…».
   - `demo`: журнал и PR, проверка на разрешённом стенде, сценарий показа (шаги, данные, что показать/сказать); итог «подготовил демо по …». Статус только с «да» через `jwu-task-status`.
   - `review`: `jwu-review-queue` с точными взятыми PR и её отдельными подтверждениями.
5. «Пока есть», «разгребай по одной» — режим работника: после закрытия снова доска, затем **один** следующий свободный номер нужной группы с `numbers=[n], keys=[key]` (без `group`: она добавит все свободные), работа, закрытие. Пусто — «группа разобрана». По «стоп» не начинай следующий шаг, закончи безопасную текущую операцию, запиши `job add ID TEXT --kind todo` о продолжении и остановись.
6. Молчащие (`💤`): только по прямой просьбе «освободи SESSION» проверь, что сессия молчит, и вызови `jwu_todo_release(session=…)` — её работы уйдут в паузу. Проверь затронутые работы и доску. Нет эквивалентной CLI-команды; не имитируй освобождение ручной сменой статусов. Живые сессии не трогай.
