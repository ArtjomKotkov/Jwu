# jwu: оркестратор Hermes

Оркестратор разбирает запрос и распределяет работу, не выполняя её за воркеров. Сначала **jwu-session-init**: проверь фактический `workdir`, `source: cwd`, ожидаемые `cwd`/`slug`, правила и пути. Передавай дочерней задаче абсолютную папку нужного репозитория, требуй заново сверить привязку; не считай cwd дочернего процесса или MCP наследуемым. В Hermes используй обнаруженные схемы (обычно `mcp_jwu_jwu_*`); MCP только при совпадении `jwu_workspace_current()` с CLI. Фолбэк: `jwu --workspace <slug> …` с явным `terminal(workdir=…)`.

1. Нужны точные ключи задач/PR/работ и число воркеров. «Одному» — один список по порядку, «каждую своему» — отдельные дочерние задачи; при неоднозначности спроси. Не бери чужую занятую работу. Для номера доски покажи соответствие номер → ключ и статус. `jwu_todo(session=…, refresh=False, workspace=slug)` / `jwu todo --session <имя> --no-refresh --json` читает кеш без синка, **но сохраняет отображение номеров** (MCP может также зарегистрировать сессию): согласуй получение/запоминание снимка доски до вызова. Если нужен лишь разбор известного ключа, доску не трогай. MCP: `jwu_context(key=…, workspace=slug)`; для известной работы — `jwu_job_handoff(job_id=N, offline=True, save=False, workspace=slug)` / `jwu job handoff N --offline --json`. У `jwu_context` нет одноимённой CLI-команды: используй проверенные части фолбэка **jwu-context**, не выдумывай синтаксис.
2. Подготовь brief: ключи и порядок, вид работы, одна подходящая **доступная** проектная инструкция на этап, проверенный репозиторий, существенные решения/грабли и критерий готовности. Например, красная сборка — **jwu-build-failure** с PR и номером запуска; повторное ревью — **jwu-review-queue**, если доступен; существующая работа — **jwu-continue-job**, если доступен, с выжимкой handoff. Не выдавай отсутствующий скил за загруженный. Передай точные ограничения пользователя, не передавай секреты, его согласие на выполнение конкретной операции или выводы вместо фактов. Независимые задания можно делегировать параллельно, пересекающиеся — последовательно.
3. После явного согласия на число, brief, область и инструменты, если `delegate_task` доступен, используй живую схему Hermes: `delegate_task(tasks=[{goal: …, context: …}, …])`, в том числе для одного задания. Давай минимальный доступ и ограничивай этап анализом/черновиком. `delegate_task` — конечный подагент, не интерактивная сессия и не долговременный воркер; в Hermes Desktop выдача результата может произойти после завершения текущего ответа. Нет инструмента — верни готовый brief или согласуй отдельный ограниченный этап; не подменяй запуск внешним клиентом. Для долговременной/интерактивной работы обсуждай отдельно Hermes-сессию или настроенную Hermes Kanban, не обещай автоматическую связь с доской jwu.
4. Захват доски и запись brief **не происходят** от одной делегации. Не захватывай по умолчанию. Если отдельно одобрены конкретные номера, их ключи и имя владеющей сессии, для неё `jwu_todo_take(numbers=[…], keys=[…], session=…, workspace=slug)` — передай оба списка из показанного снимка; не выделяй `for_worker` под `delegate_task`. CLI `jwu todo <номера> --session <имя> --json` не принимает ожидаемые `keys` и не эквивалентен безопасному захвату MCP: при требовании привязки к точным ключам оставь пункты нетронутыми. Проверь `taken`/`skipped` и каждую работу; отдельно согласуй запись brief, если нужна. Не пиши статусы, PR, комментарии, commits или push из делегированного этапа; на каждом таком шаге родитель показывает точный объект/изменение, получает согласие и проверяет результат.
5. По результату сверь критерий, журнал или кеш; различай «делегировано», «получен черновик», «подтверждено». Если нужно уточнение, спроси здесь и создай следующий bounded этап после согласия; не обещай доставку сообщений, остановку по имени или возобновление уже завершённого `delegate_task`. Не перезапускай упавшие задания сам.

Только если пользователь спрашивает про **существующих внешних воркеров jwu**, покажи `jwu_worker_list(workspace=slug)` / `jwu worker list --json` отдельно от результатов Hermes. `jwu_worker_start(name, task, cwd, jobs, permission_mode, user_approved, workspace)` запускает **Claude Remote Control**, не Hermes; не используй как фолбэк и не запускай здесь. Остановка существующего внешнего воркера — отдельно согласованная операция: `jwu_worker_stop(name=…, force=False, user_approved=True, workspace=slug)` / `jwu worker stop <имя> --yes`. `force=True` / `--force` только после явного согласия на паузу конкретных открытых работ. Перечитай список и состояние этих работ; не трогай чужие процессы.
