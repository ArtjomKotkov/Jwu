# jwu: оркестратор Hermes

Оркестратор разбирает запрос и распределяет работу, не выполняя её за воркеров. Сначала **jwu-session-init**: проверь фактический `workdir`, `source: cwd`, ожидаемые `cwd`/`slug`, правила и пути. Передавай дочерней задаче абсолютную папку нужного репозитория, требуй заново сверить привязку; не считай cwd дочернего процесса или MCP наследуемым. В Hermes используй обнаруженные схемы (обычно `mcp_jwu_jwu_*`); MCP только при совпадении `jwu_workspace_current()` с CLI. Фолбэк: `jwu --workspace <slug> …` с явным `terminal(workdir=…)`.

1. Нужны точные ключи задач/PR/работ и число воркеров. «Одному» — один список по порядку, «каждую своему» — отдельные дочерние задачи; при неоднозначности спроси. Не бери чужую занятую работу. Для номера доски покажи соответствие номер → ключ и статус. `jwu_todo(session=…, refresh=False, workspace=slug)` / `jwu todo --session <имя> --no-refresh --json` читает кеш без синка, **но сохраняет отображение номеров** (MCP может также зарегистрировать сессию): согласуй получение/запоминание снимка доски до вызова. Если нужен лишь разбор известного ключа, доску не трогай. MCP: `jwu_context(key=…, workspace=slug)`; для известной работы — `jwu_job_handoff(job_id=N, offline=True, save=False, workspace=slug)` / `jwu job handoff N --offline --json`. У `jwu_context` нет одноимённой CLI-команды: используй проверенные части фолбэка **jwu-context**, не выдумывай синтаксис.
2. Подготовь brief: ключи и порядок, вид работы, подходящая проектная инструкция на этап, проверенный репозиторий, существенные решения/грабли и критерий готовности. Например, красная сборка — **jwu-build-failure** с PR и номером запуска; повторное ревью — **jwu-review-queue**; существующая работа — **jwu-continue-job** с выжимкой handoff. Если рабочая папка воркера находится вне репозитория Jwu, до передачи проверь актуальные `SKILL.md` в `<проверенный корень Jwu>/.hermes/skills/<имя>/SKILL.md` и включи абсолютные пути в brief. Укажи: если `skill_view` не видит проектный скил в чате воркера, прочитай проверенный файл через `read_file`; не подменяй его архивной копией. Это не меняет рабочий каталог и привязку воркспейса. Если ни скил, ни исходный файл недоступны, сообщи блокер. Передай точные ограничения пользователя, не передавай секреты, его согласие на выполнение конкретной операции или выводы вместо фактов. Независимые задания можно делегировать параллельно, пересекающиеся — последовательно.
3. Воркер по умолчанию — **отдельный интерактивный чат Hermes в нужном проекте**, видимый в боковом меню. Явное поручение с понятным объёмом и числом воркеров не требует повторного согласия на запуск. `delegate_task` используй только по явной просьбе о фоновом подагенте: он не создаёт отдельный чат. Это не запрещает интерактивному воркеру использовать ограниченный поданализ, если его рабочий процесс это допускает. Не подменяй запуск Codex, Claude или фоновым подагентом, если проектный чат создать не удалось.
4. Для привязки к проекту сверяй ID и workdir. Загрузи **jwu-hermes-orchestrator** (скрипты в git: `<корень Jwu>/.hermes/skills/jwu-hermes-orchestrator/`). Запуск: `scripts/run_with_gateway.sh scripts/worker_launch.py --title … --brief-file …` при заданном `HERMES_SESSION_ID`. Скрипт наследует `model`/`provider` из `session.info` оркестратора и до отправки брифа сверяет ID, вычисленный из запроса создания, профиль, проект, cwd и модель. Не заменяй его ручным `session.create` / `prompt.submit`: создание по заголовку может вернуть чужой существующий чат. `queued` ≠ доставка. Если скрипт не подтвердил маршрут, не отправляй бриф автоматически; дай его пользователю для ручной передачи. Перенос машины: `references/install.md` в том же скилле.
5. Создание чата не захватывает доску. При явном поручении взять пункты проверь маршрут интерактивного чата и совпадение номеров с точными ключами. Сохрани имя сессии показанного снимка (`session` из результата `jwu_todo` или имя, явно заданное при показе) и передай его **без изменений**: `jwu_todo_take(numbers=[…], keys=[…], session=показавшая_доску, for_worker=имя_воркера, workspace=slug)`. `session` идентифицирует снимок оркестратора, `for_worker` — владельца работ; не подменяй одно другим и не полагайся на память MCP после переподключения. Если снимок потерян или номера изменились, покажи доску заново и не бери другой ключ вместо выбранного. CLI без проверки `keys` не заменяет безопасный захват. Прочитай `taken`/`skipped` и точные записи работ. При переносе используй уже заведённые работы и не создавай дубли. Запиши бриф и точный ID воркера в журнал назначенных работ и дай пользователю ссылку. Не резервируй пункты для фонового подагента как для интерактивного чата.
6. Воркер запрашивает разрешения **в своём чате** и сам продолжает очередь после каждого решения. Воркер и оркестратор следуют проверке «перед завершением каждого хода» из `jwu-session-init`: если нужно решение пользователя, предложи следующий шаг и вызови `clarify` сразу; не жди «что дальше?». Если кнопки недоступны, напиши «Жду твоего выбора», нумерованные варианты и что останется без изменений до ответа. Оркестратор не передаёт согласие от имени пользователя и не публикует за воркера.
7. **Обратный отчёт обязателен.** В каждый интерактивный brief включи проверенный ID чата оркестратора и маршрут доставки: в конце воркер отправляет туда одно служебное сообщение со своим ID, итогом по PR/работам и нерешёнными вопросами. Если все назначенные работы закрыты и решений не осталось, **в том же сообщении** он явно просит архивировать только свой чат после завершения ответа. Запись в jwu или ответ в собственном чате не заменяют доставку. При отсутствии маршрута воркер сообщает об этом, не утверждает, что отчёт доставлен, и оставляет свой чат открытым. Оркестратор сверяет отправителя, точную сессию и назначенные работы, ждёт окончания её ответа и архивирует по этой просьбе без повторного вопроса только при отсутствии открытых работ или решений. Затем читает статус обратно. Итог без просьбы — только информация; не закрывай работы за воркера на основании просьбы об архивировании. Сам не перезапускай упавшие задания.

Только если пользователь спрашивает про **существующих внешних воркеров jwu**, покажи `jwu_worker_list(workspace=slug)` / `jwu worker list --json` отдельно от результатов Hermes. `jwu_worker_start(name, task, cwd, jobs, permission_mode, user_approved, workspace)` запускает **Claude Remote Control**, не Hermes; не используй как фолбэк и не запускай здесь. Остановка существующего внешнего воркера — отдельно согласованная операция: `jwu_worker_stop(name=…, force=False, user_approved=True, workspace=slug)` / `jwu worker stop <имя> --yes`. `force=True` / `--force` только после явного согласия на паузу конкретных открытых работ. Перечитай список и состояние этих работ; не трогай чужие процессы.
