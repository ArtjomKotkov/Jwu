# jwu: оркестратор Hermes

Оркестратор разбирает запрос и распределяет работу, не выполняя её за воркеров. Сначала **jwu-session-init**: проверь фактический `workdir`, `source: cwd`, ожидаемые `cwd`/`slug`, правила и пути. Передавай дочерней задаче абсолютную папку нужного репозитория, требуй заново сверить привязку; не считай cwd дочернего процесса или MCP наследуемым. В Hermes используй обнаруженные схемы (обычно `mcp_jwu_jwu_*`); MCP только при совпадении `jwu_workspace_current()` с CLI. Фолбэк: `jwu --workspace <slug> …` с явным `terminal(workdir=…)`.

1. Нужны точные ключи задач/PR/работ и число воркеров. «Одному» — один список по порядку, «каждую своему» — отдельные дочерние задачи; при неоднозначности спроси. Не бери чужую занятую работу. Для номера доски покажи соответствие номер → ключ и статус. `jwu_todo(session=…, refresh=False, workspace=slug)` / `jwu todo --session <имя> --no-refresh --json` читает кеш без синка, **но сохраняет отображение номеров** (MCP может также зарегистрировать сессию): согласуй получение/запоминание снимка доски до вызова. Если нужен лишь разбор известного ключа, доску не трогай. MCP: `jwu_context(key=…, workspace=slug)`; для известной работы — `jwu_job_handoff(job_id=N, offline=True, save=False, workspace=slug)` / `jwu job handoff N --offline --json`. У `jwu_context` нет одноимённой CLI-команды: используй проверенные части фолбэка **jwu-context**, не выдумывай синтаксис.
2. Подготовь короткий бриф: действие, точный ключ задачи или полный PR (`проект/репозиторий#номер`), раздел доски (если выбран оттуда) и дословные исключения пользователя. Не включай номер работы, план, тесты или догадки: воркер сам находит работу по ключу и сверяет факты. Если воркер вне Jwu и `skill_view` не видит проектные правила, передай отдельно проверенный корень `.hermes/skills/` для чтения инструкций, не меняя его рабочего каталога. Не передавай секреты или согласие пользователя на конкретную операцию. Независимые задания можно делегировать параллельно, пересекающиеся — последовательно.
3. Воркер по умолчанию — **отдельный интерактивный чат Hermes в нужном проекте**, видимый в боковом меню. Явное поручение с понятным объёмом и числом воркеров не требует повторного согласия на запуск. `delegate_task` используй только по явной просьбе о фоновом подагенте: он не создаёт отдельный чат. Это не запрещает интерактивному воркеру использовать ограниченный поданализ, если его рабочий процесс это допускает. Не подменяй запуск Codex, Claude или фоновым подагентом, если проектный чат создать не удалось.
4. Загрузи `jwu-hermes-orchestrator`. До создания проверь совместимость локального шлюза и Python payload по `jwu-hermes-orchestrator`. При неизвестной совместимости остановись. Из проверенного родительского чата (`HERMES_SESSION_ID`) запусти `scripts/run_with_gateway.sh scripts/worker_launch.py --create-only --title …` с уникальным заголовком. Это первый этап одного поручения, не пустой тестовый чат. Проверь связанный с Main точный ID и `session.info` созданного чата. Только после сверки проекта, папки и модели отправь короткий бриф в этот же чат: `scripts/run_with_gateway.sh scripts/worker_relay.py send --target ID --title TITLE --project PROJECT_ID --message-file FILE`. Не создавай второй чат для доставки. Если маршрут не подтверждён, сообщи блокер без отправки.
5. Получив поручение, **воркер** проходит `jwu-session-init` в своём workdir: сверяет `source=cwd`, slug и правила. В собственной сессии доски находит точный ключ в указанном разделе и атомарно берёт его по `jwu-todo`. Проверяет `taken`/`skipped` и владельца. При чужом владельце, исчезновении или смене раздела — сообщает и не подменяет пункт. Свою уже взятую работу продолжает без дубля; для задачи вне доски проверяет существующую работу по ключу и при необходимости сам проходит `jwu-start-job`. ID узнаёт сам. Именно воркер сверяет требования, последние комментарии, PR и прежний итог: работу не повторяет. Для изменений сам применяет «От анализа до первой правки» из `jwu-start-job`, согласует и записывает план до исполнения; для простого ревью план правок не нужен. Пустой чат без поручения — только по явной просьбе.

   Main сверяет по точному ID созданного чата проект, workdir и его фактические `model`/`provider` с запрошенными (иначе — с родительскими). При расхождении не отправляет бриф. Отдельно проверяет точный текст в транскрипте. `queued` не означает доставку; доставка не означает взятие. Сообщи ключ, ссылку и подтверждённое состояние: «бриф доставлен; взятие пока не подтверждено» либо «воркер взял» после подтверждения воркера или чтения соответствующей активной работы с его владельцем. Частичный сбой не повод создавать второй чат или брать пункт из Main.
6. Воркер запрашивает разрешения **в своём чате** и сам продолжает очередь после каждого решения. Воркер и оркестратор следуют проверке «перед завершением каждого хода» из `jwu-session-init`: если нужно решение пользователя, предложи следующий шаг и вызови `clarify` сразу; не жди «что дальше?». Если кнопки недоступны, напиши «Жду твоего выбора», нумерованные варианты и что останется без изменений до ответа. Оркестратор не передаёт согласие от имени пользователя и не публикует за воркера.
7. **Обратный отчёт обязателен.** Обычный итог по PR/работам и нерешённые вопросы воркер отправляет в проверенный родительский чат через встроенный `session_mailbox`. Main и воркер используют ту же пассивную почту для рабочих вопросов и ответов в обе стороны. ID чатов и сообщений передавай полями инструмента, не вставляй их в текст. Почта не запускает ход и не заменяет решение пользователя в `clarify`. При недоступном маршруте или отказе инструмента сообщи блокер в своём чате и не подменяй почту отправкой промпта. Запись в Jwu и ответ в своём чате не означают доставки.

**Архив чата воркера. Автоматического маршрута нет.** После завершения поручения и явного согласия пользователя в чате воркера (см. `jwu-close-job`) оставь чат открытым и предложи пользователю архивировать именно этот чат вручную в Hermes Desktop: в меню чата выбери «Архивировать». Не отправляй запрос на архив ни почтой, ни промптом. Main не архивирует чаты по письму, тексту промпта или заявленным метаданным. Обычный итог отправляй отдельно по правилам почты. Не закрывай работы за воркера и не перезапускай упавшие задания.

Только если пользователь спрашивает про **существующих внешних воркеров jwu**, покажи `jwu_worker_list(workspace=slug)` / `jwu worker list --json` отдельно от результатов Hermes. `jwu_worker_start(name, task, cwd, jobs, permission_mode, user_approved, workspace)` запускает **Claude Remote Control**, не Hermes; не используй как фолбэк и не запускай здесь. Остановка существующего внешнего воркера — отдельно согласованная операция: `jwu_worker_stop(name=…, force=False, user_approved=True, workspace=slug)` / `jwu worker stop <имя> --yes`. `force=True` / `--force` только после явного согласия на паузу конкретных открытых работ. Перечитай список и состояние этих работ; не трогай чужие процессы.
