# jwu: переход задачи по процессу

Загрузи `skill_view(name="jwu-session-init")`; без проверенной привязки и правил пройди его заново. Требуй `source="cwd"`, непустой `slug` и совпадающий `cwd` из `jwu workspace current --json` с явным `terminal.workdir` проекта. Соблюдай ⛔ и правила тега. Ниже CLI-команды идут после `jwu --workspace <slug>` с тем же `workdir`. MCP необязателен: только если `jwu_workspace_current` подтверждает тот же `source`, `slug`, `cwd`; передавай `workspace=<slug>` в поддерживаемые вызовы. Если чтения не хватает, уточни через `clarify`, если доступен, иначе спроси в чате.

Только `provider=jira`. GitHub Issues и локальный контур не поддерживаются. Статус виден команде; обратного перехода может не быть.

1. Прочитай задачу (`jwu_task(key)` / `task KEY --json`) и её актуальные переходы `jwu_issue_transitions(key)` / `issue transitions KEY --json`. Покажи `name → to` и ID. Если запрошенного перехода нет или выбор неоднозначен, не выбирай похожий и не пытайся править поле статуса.
2. Покажи точное превью: ключ, текущий статус, выбранный ID и имя перехода, конечный статус. После явного согласия на этот точный переход (в том числе с доски) перепроверь исходный статус и доступность того же перехода. При расхождении покажи новое превью и спроси снова. Затем `jwu_issue_transition(key, target)` / `issue transition KEY TARGET --yes --json`; `TARGET` — строка ID или точное имя (регистр не важен).
3. Перечитай `jwu_task(key)` / `task KEY --json`, сверь `status`, только потом сообщи результат. При неясном исходе не повторяй запись вслепую. Если есть подтверждённая связанная работа — локальная запись `jwu_job_add(job_id, "Статус KEY → STATUS", kind="phase")` / `job add JOB_ID "Статус KEY → STATUS" --kind phase --no-git`. Не двигай задачу заодно с другой операцией.
