# jwu: разбор возврата с тестов

## Overview

Тестировщик написал в задаче на тестах или вернул её в работу. Нужно быстро понять: это
наш баг в правках, регресс, ошибка в ожиданиях теста или не хватает данных — и что
ответить. Разбор делает субагент `qa-triage-sample` (или проектный субагент дежурства /
триажа, если есть); наружу ничего не уходит без подтверждения.

> **MCP-first.** `jwu_context(KEY)` → `jwu_task(KEY)` (комменты, `attachments` с
> `referenced_by`) → `jwu_attachments(KEY, download=True)` → `jwu_pr(...)` / `jwu_pr_diff`
> по PR задачи → субагент. Ответ — `jwu_comment(KEY, text)` только после «да»
> (скилл jwu-task-comment), задача на PR — jwu-pr-task, статус — jwu-task-status.

## Шаги

1. **Что именно вернули.** `jwu_context(KEY)` (статус, решения, последняя работа) и
   `jwu_task(KEY)`: найди комментарии тестировщика после перевода на тесты, их вложения
   (`referenced_by` показывает, какой скриншот к какому комменту). Скачай и прочитай
   через Read: скриншот часто и есть описание бага.
2. **Что менялось.** PR задачи из `pull_requests` → `jwu_pr` и `jwu_pr_diff` по нужным
   файлам; `jwu_branches(KEY)` — где лежит код локально, если надо посмотреть глубже.
   Тестировали на стенде, а стенд есть в `jwu_ssh_servers()` и его инструменты
   (`mcp__ssh-<slug>__execute-command`) доступны — логи стенда за время проверки
   передай субагенту или дай ему имя стенда. Только чтение; секреты в чат не проси.
3. **Субагент триажа.** `Agent` с `subagent_type = qa-triage-sample` (или проектный).
   В промпт: ключ и заголовок задачи, ожидаемое поведение из описания, комментарии QA
   дословно, пути к скачанным вложениям, дифф PR, папки воркспейса с тегами (где искать код).
4. **Вердикт пользователю**, коротко:
   - **наш баг** — где в диффе, как чинить, нужна ли новая работа (jwu-start-job: новый цикл правок);
   - **регресс из целевой ветки** — чем подтверждается, кому это принадлежит;
   - **не баг** — что в ожиданиях расходится с задачей, ссылка на договорённость;
   - **нужны данные / не воспроизводится** — что именно попросить у QA (логи, аккаунт, шаги).
5. **Черновик ответа** тестировщику в 3–6 строк. Показать целиком → «да» →
   `jwu_comment(KEY, text)`. Для SDESK-задач (их читает клиент) — правила jwu-task-comment.
6. **Зафиксировать:** `jwu_note(KEY, "вернули с тестов: …", kind="status")`; если чиним —
   заводи работу (jwu-start-job) и веди её (jwu-track-job); если вернули зря — предложи
   перевести обратно на тесты (jwu-task-status) после «да».

## Чего делать НЕ надо

- Отвечать QA без подтверждения, спорить в комментариях вместо фактов из кода.
- Чинить «на глаз» без воспроизведения по скриншоту/логам — сначала вердикт.
- Смешивать разбор с правками: правки — отдельная работа со своим журналом.
