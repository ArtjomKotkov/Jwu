# jwu: онбординг под удалённую работу

## Overview

Удалённая сессия (Remote Control, телефон) работает через jwu на этой машине. Чтобы это
имело смысл, машина сама должна синкать, слать уведомления и хранить память там, где её
найдёт другая машина. Четыре шага, каждый проверяется `jwu doctor`.

## Шаги

1. **Диагноз.** `jwu doctor` — прочитай проверки; `fail` чинится до всего остального
   (обычно: БД в облаке, нет токена, папки воркспейса не склонированы).
2. **Фоновый синк.** `jwu daemon status`; не установлен —
   `jwu daemon install --interval 600`, затем `jwu daemon status` (служба загружена,
   процесс работает). Лог: `~/.local/share/jwu/daemon.log`. Хочет реже/чаще — интервал.
3. **Telegram.** Нужны токен бота (@BotFather) и chat_id личного чата с ботом. **Спроси**,
   не ищи в файлах. Потом:
   ```bash
   jwu configure --non-interactive --telegram-chat <id> --telegram-token <token>
   jwu notify test
   ```
   Токен в ответе пользователю не повторяй. События по умолчанию — `jwu notify status`.
4. **Память между машинами.** Спроси, есть ли ПРИВАТНЫЙ git-репозиторий под память
   (не проектный!). Есть — `git clone <url> ~/jwu-memory` и `jwu memory sync --repo
   ~/jwu-memory`; нет — предложи создать пустой приватный и повторить. Секреты в память
   не попадают, но репозиторий всё равно приватный: там правила и заметки по проектам.
5. **Бэкап на всякий случай.** `jwu backup --out ~/Desktop` — архив с токенами, напомни
   про защищённый канал и удаление после переноса.
6. **Контроль.** `jwu doctor` ещё раз: демон работает, Telegram ok, память ok, MCP
   зарегистрирован, скиллы актуальны. Скажи, что осталось ручного (перезапуск сессии
   Claude Code после обновления jwu, клонирование недостающих папок).

## Чего делать НЕ надо

- Угадывать chat_id или брать токен из чужих конфигов.
- Класть память в рабочий репозиторий проекта — только отдельный приватный.
- Ставить демон второй раз «для надёжности»: лок пустит только один процесс.
