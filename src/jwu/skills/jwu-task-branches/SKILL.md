# jwu: в какие ветки доехал фикс задачи

> **Воркспейс = где лежит код.** Ветки берутся из репозиториев воркспейса — их список
> приходит в `jwu_workspace_current()` (bash: `jwu workspace paths`). Если нужного
> репозитория в контуре нет, ответа не будет: сначала привяжи его
> (скилл **jwu-workspace-setup**).

## Когда

Дежурный вопрос почти всегда одной формы: «баг известный, но есть ли фикс в версии
клиента». Руками это собирается через `git log --grep`, `git log -S`,
`git branch --contains` и сверку с dev-панелью карточки — здесь всё то же самое
одним вызовом.

## Инструмент

`jwu_task_branches(key, branch_patterns=None)` (bash: `jwu task KEY --branches`,
`--branch-pattern release/*` для своих шаблонов). Только чтение, ничего не меняет
и ничего не фетчит.

Ответ:

- `commits` — коммиты задачи из dev-панели; `prs` — PR с целевыми ветками;
- `repos[].reached` — ветки, куда доехали **все** коммиты задачи;
- `repos[].partial` — куда доехала **часть** коммитов;
- `repos[].missing` — ветки-кандидаты, где фикса нет;
- `dev_ok: false` — dev-панель Jira ответила не полностью.

Ветки идут от свежих к старым; по умолчанию считаются релизными `release/*`,
`release-*`, `hotfix/*`, `support/*`, `master`, `main`, `develop`.

## Как отвечать

1. **Прямо ответь на заданный вопрос**: есть фикс в спрошенной ветке или нет. Не вываливай
   весь список веток, если спросили про одну.
2. **`partial` — говори явно.** Это самый опасный случай: в ветке часть коммитов задачи,
   то есть фикс там неполный и может работать не так, как в релизе.
3. **`dev_ok: false` или пустой `commits`** — это «не знаем», а не «фикса нет».
   Так бывает, когда коммиты не привязаны к задаче. Тогда честно скажи, что по
   dev-панели ответа нет, и предложи поискать по тексту: `git log --grep <KEY>`
   в нужной папке воркспейса.
4. **Клон мог устареть.** Ответ строится по локальному состоянию репозитория: если
   свежей релизной ветки в списке нет вовсе, попроси пользователя сделать `git fetch`
   и повтори.
5. PR со статусом OPEN означает, что фикс ещё нигде: скажи об этом, а не молчи, что
   «в релизе нет».

## Связанные скиллы

- **build-failure** — почему упал билд по ветке/PR.
- **jwu-task-comment** — ответить в задаче тем, что выяснил.
