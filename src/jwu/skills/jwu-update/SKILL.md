# jwu: установка и обновление

## Overview

Обновление jwu — это **не одна команда**. Код едет в трёх местах, и каждое обновляется
по-своему:

| Что | Где живёт | Чем обновляется | Когда подхватится |
|---|---|---|---|
| CLI `jwu` | pipx-venv (копия пакета) | `pipx install --force .` | сразу |
| MCP-сервер `jwu-mcp` | тот же пакет, но **запущенный процесс** | тем же `pipx install` | **только после перезапуска сессии** |
| Скиллы и субагенты | `~/.claude/skills`, `~/.claude/agents` | `jwu install-claude-skills` | сразу (список скиллов обновится) |

Самая частая ошибка — обновить пакет и решить, что всё готово: скиллы в `~/.claude`
остаются старыми, а MCP-сервер продолжает работать со старым кодом в памяти.

## Шаги

1. **Обнови пакет** (из папки репозитория jwu):

   ```bash
   pipx install --force .
   ```

   Из гита: `pipx install --force git+https://github.com/ArtjomKotkov/jwu.git`.
   Для разработки удобнее editable — тогда правки подхватываются без переустановки:
   `pipx install --force --editable .`

2. **Разверни скиллы и субагентов** — это ОТДЕЛЬНЫЙ шаг, без него `~/.claude` остаётся старым:

   ```bash
   jwu install-claude-skills
   ```

   Ставит только те скиллы и агентов, что шипуются с jwu. Проектные субагенты
   пользователя (`reviewer-*` и прочие) не трогает.

3. **Проверь, что установилось именно новое** — по факту, а не по надежде:

   ```bash
   jwu --help | head -30                 # новые команды на месте?
   jwu workspace current --json          # поле jwu_version — версия в этом процессе
   ```

4. **Скажи про перезапуск, если менялся MCP.** Инструменты `jwu_*` живут в процессе
   `jwu-mcp`, запущенном при старте сессии Claude Code. После обновления пакета он всё ещё
   исполняет старый код: новых инструментов не будет, а старые могут работать по старым
   правилам (например, отдавать данные без учёта воркспейса). Лечится только перезапуском
   сессии Claude Code в том проекте.

## Диагностика: «нет инструмента» / «показывает не то»

Признаки старого MCP-сервера: инструмента `jwu_*` нет в списке; `jwu_workspace_current()`
не отвечает; данные не совпадают с тем, что показывает bash `jwu …` из той же папки.

Проверить, когда запущены серверы и из каких папок:

```bash
ps -eo pid,lstart,command | grep jwu-mcp | grep -v grep
lsof -a -p <PID> -d cwd -Fn        # рабочая папка процесса
```

Если время запуска раньше, чем правился код (`stat -f '%Sm' src/jwu/mcp_server.py`) —
сервер старый. **Пока сессия не перезапущена, работай через bash `jwu …`**: CLI всегда
берёт свежий код.

Отдельно: MCP-сервер резолвит воркспейс по **своей** рабочей папке (той, из которой его
запустила сессия). Если проект открыт не из корня — проверь `jwu_workspace_current()`,
поле `cwd`.

## Проверка после обновления

```bash
jwu workspace current      # тот ли контур
jwu auth check             # если в контуре есть Jira/Bitbucket
```

## Чего не делать

- Не считай `pipx install` достаточным — без `jwu install-claude-skills` скиллы старые.
- Не редактируй файлы в `~/.claude/skills/jwu-*` руками: они перезаписываются при
  следующей установке. Правь исходники в `src/jwu/skills/` и переустанавливай.
- Не перезапускай MCP-сервер «убийством процесса» — просто скажи пользователю
  перезапустить сессию Claude Code.
