# jwu: контекст задачи / PR / ветки без разбора работ

## Overview

Работа (job) — это журнал одного цикла правок, его надо искать по id. Контекст — то, что
сессия должна знать, просто открыв задачу или PR: решения, грабли, что осталось, почему
висит. Он живёт заметками по ключу сущности и всплывает сам: в `jwu task` / `jwu_task`,
`jwu pr` / `jwu_pr`, в карточке PR дашборда, в дневном анализе (строка `заметка: «…»`)
и в handoff. Закрытие работы (`jwu job done`) само кладёт выжимку в контекст задачи и PR.

> **MCP-first.** `jwu_context(key)` — заметки + последняя работа + снапшот PR/задачи одним
> вызовом; `jwu_notes(key)` — только заметки; `jwu_note(key, text, kind, pin)` — записать.
> Bash: `jwu notes <ключ>`, `jwu note <ключ> "…" --kind status|decision|gotcha|todo|context`.
> Ключи: задача `PROJ-1`, PR `PROJ/repo#42` (проект/репозиторий#номер), ветка `PROJ-1-fix`.

## Виды заметок

| kind | что это | где видно |
|---|---|---|
| `status` | ОДНА строка «почему висит / что сейчас», закреплена, новая заменяет старую | таблицы `jwu prs`, дневной анализ, карточки |
| `decision` | принятое решение с причиной | карточки, handoff |
| `gotcha` | грабли, на которые уже наступали | карточки, handoff |
| `todo` | отложенное, не привязанное к работе | карточки, handoff |
| `context` | всё остальное; сюда же пишет выжимку `jwu job done` | карточки, handoff |

## Шаги: узнать

1. `jwu_context(key)`. В ответе `status` (если закреплён), `notes`, `last_job` (id, статус,
   последняя запись, ветка и коммит), для PR — `pr` из снапшота, для задачи — `task` и
   `branches` (локальные ветки по ключу: репозиторий, где checkout'нута, ahead/behind,
   незакоммиченное). Только ветки — `jwu_branches(key)` / `jwu branches KEY`.
2. Перескажи в 3–5 строк: статус одной строкой, решения и грабли, что осталось, где стоять
   в git. Если есть незакрытая работа — предложи продолжить её (скилл jwu-resume-job);
   если работ нет — этого контекста достаточно, чтобы начать.
3. Не хватает — только тогда `jwu_pr` / `jwu_task` за живыми данными.

## Шаги: записать

- «Почему висит» / «что сейчас» → `kind="status"`: одна строка, до ~120 символов, без
  подтверждения (локальная память). Пример: «ждём ответа Eugeny по таймауту в obtain_data».
- Решение / грабли / todo → соответствующий kind, текст на 1–2 предложения, с причиной.
- Что-то по ходу текущей работы → это jwu-track-job (`jwu job add`), не заметка: журнал
  работы и контекст сущности — разные вещи, не дублируй.
- В конце сессии по работе — `jwu_job_handoff(job_id, save=True)` либо просто
  `jwu_job_status(job_id, "done")`: выжимка уедет в контекст сама.

## Частые ошибки

- Заводить работу, чтобы записать одну мысль по задаче — для этого заметка.
- Писать status длинным абзацем — это строка в таблице, кратко.
- Ключ PR без проекта/репозитория (`#42`) — не совпадёт с тем, что пишет jwu; бери `pr_note_key`
  формат `PROJ/repo#42` из `jwu_pr` (поле `project`/`repository`/`id`).
