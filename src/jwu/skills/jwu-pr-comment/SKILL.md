# jwu: ответить в PR и поставить статус ревью

## Overview

Работа с телефона или из сессии без клона репозитория: посмотреть дифф PR, ответить
ревьюверу под его замечанием, оставить коммент на строку, поставить свой статус ревью.
Всё пишущее — **внешняя запись**, которую увидят коллеги: только после явного «да».

> **MCP-first.** `jwu_pr(pr_id, project, repo)` — карточка с `comments[]` (id, автор,
> `file:line`, текст), `open_tasks`, `attachments`; `jwu_pr_diff(pr_id, path)` — unified
> diff (большой PR бери по файлам через `path`); `jwu_pr_comment(pr_id, text, reply_to,
> path, line)` — коммент; `jwu_pr_review(pr_id, status, text)` — мой статус.
> Bash-фолбэк: `jwu pr <id> --diff [--path f]`, `jwu pr-comment <id> -m … --reply-to CID --yes`,
> `jwu pr-review <id> approve|needs-work|unapprove --yes`.

## Правила

1. **Текст целиком — пользователю, потом «да».** Покажи, в какой PR, куда (ответ в тред
   #id такого-то автора / строка файла / общий) и полный текст. Без «ок/да/отправляй»
   ничего не уходит. Пользователь правит текст — показываешь снова.
2. **Статус ревью — отдельное подтверждение**, даже если коммент уже согласован.
   Апрув чужого PR — ответственность пользователя: не предлагай «апрувнуть заодно».
3. **Ничего в git.** Ответы и статусы живут в Bitbucket/GitHub; локальный репозиторий
   не трогается, следов jwu там нет.
4. **Только Bitbucket умеет снять апрув** (`UNAPPROVED`). У GitHub `needs-work`
   требует текст (уходит в отзыв); у Bitbucket статус без текста, поэтому текст
   отправляется отдельным общим комментарием — скажи об этом пользователю.

## Шаги: ответить на замечание

1. `jwu_pr(pr_id, …)` → найди комментарий ревьювера: `id`, автор, `file:line`, текст.
   Если к замечанию приложен скриншот (`attachments` с этим `comment_id`) — скачай
   `jwu_pr_attachments(pr_id, download=True)` и прочитай через Read, прежде чем отвечать.
2. Если нужно понять код без клона — `jwu_pr_diff(pr_id, path=<файл>)`.
3. Составь ответ вместе с пользователем (или по его словам). Коротко и по делу: что
   поправлено (коммит/ветка словами, без ссылок на jwu), либо почему не согласен.
4. Превью → «да» → `jwu_pr_comment(pr_id, text, reply_to=<id>)`.
5. Если по замечанию заведена задача PR — закрой её скиллом **jwu-pr-task** (отдельное «да»).

## Шаги: статус ревью

1. Обычно после **jwu-job-review** (ревью субагентом) и показа выводов пользователю.
2. Спроси статус явно: approve / needs-work. Для needs-work собери текст замечаний.
3. Превью (`PR #… → NEEDS_WORK`, текст) → «да» → `jwu_pr_review(pr_id, status, text)`.

## Частые ошибки

- Отправить ответ, не показав текст целиком.
- Апрувнуть PR «раз уж ревью зелёное» без явной просьбы пользователя.
- Ответить общим комментом вместо ответа в тред (`reply_to`) — замечание останется висеть.
