description: Use when the user wants to see what needs doing and hand work out to this session — «что делать», «что по задачам», «покажи задачи», «что горит», «раздай задачи», «делай 1 и 3», «бери все конфликты и падения», «бери правки по ревью», «начинаем разбор ревью», «/jwu-todo». Shows a numbered board from the jwu cache (refreshed through the daemon when older than 30 minutes or when asked): my PRs with conflicts / red builds, review and QA fixes, unfinished tasks, others' PRs waiting for my review — with what is already taken by another session and how long ago. Then takes the chosen numbers or a whole group into jobs atomically and works them one by one in this session. Meant for running several Claude Code sessions in parallel (remote-control) without two of them grabbing the same task.

# jwu: что делать и раздача по сессиям

## Overview

Несколько сессий работают параллельно. Каждая открывает доску, видит, что уже взято
другими, и берёт своё. Доска — из **кеша jwu** (снапшоты синка демона); старше 30 минут или по просьбе — обновляется через демон.
«Взято» = по задаче/PR есть активная работа; взятие атомарное — две сессии одно не возьмут.

> **MCP-first.** `jwu_todo()`, `jwu_todo_take(numbers, group)`.
> Bash: `jwu todo -s <сессия>`, `jwu todo 1 3 -s <сессия>`, `jwu todo -g simple -s <сессия>`.

## Группы

| группа | что в ней | как брать словами |
|---|---|---|
| `simple` 🔧 | мой PR с **конфликтом и/или красной сборкой**, замечаний людей нет — простое | «бери конфликты и падения» |
| `fixes` ✍️ | **правки**: needs work, открытые задачи в PR, задача вернулась с QA (DEFECT, Need Update); конфликт и сборка у них — тоже тут | «бери правки по ревью», «бери возвраты QA» |
| `todo` 📋 | **несделанные** задачи на мне: не начата или в работе, без моего открытого PR (In Review и дальше — сделано, тут их нет) | «бери задачу 5» |
| `review` 👀 | чужие PR ждут моего ревью | «начинаем разбор ревью» |

## Шаги

0. **Правила воркспейса** — **jwu-session-init**, если в этой сессии его ответа ещё нет или
   был `/clear`/компакт. Без правил раздавать работу нельзя.

1. **Имя сессии** — **не спрашивай**. У сессии уже есть имя вроде «Shiny-Gold» (jwu придумал
   его сам, одно на всю сессию); оно в поле `session` ответа и в шапке доски. `session`
   передавай, только если пользователь сам попросил назвать сессию иначе.

2. **Доска.** `jwu_todo()` → выведи поле `markdown` **дословно, целиком, как есть** —
   это готовая сводка таблицами от jwu. ⛔ Не пересказывай её, не перерисовывай таблицы, не
   сокращай колонки, не меняй порядок и не добавляй своих пунктов: номера в ней — те, по
   которым потом берутся задачи. Свой комментарий — максимум одна строка после сводки. Синку больше 30 минут —
   инструмент сам обновит данные перед показом (синк через демон, один на все сессии; до
   нескольких минут — скажи «обновляю данные»). Попросили «обнови», «свежее», «сходи в сеть» —
   `jwu_todo(refresh=True)`. Не обновилось (`refreshed.ok=False`) — покажи, что есть,
   и скажи, что данные от такого-то времени. В строке синка «⏳ идёт обновление» — синк уже
   идёт (другая сессия или расписание): предложи подождать — `jwu_todo(refresh=True)`
   дождётся этого прохода, второй не запустит.
   Помеченное «давно: закрыть или продолжить?» — подскажи **jwu-close-job** или
   **jwu-continue-job** по той работе.

3. **Взять.** По словам пользователя:
   - номера — `jwu_todo_take(numbers=[1, 3])`;
   - группа — `jwu_todo_take(group="simple")` (только свободные пункты группы).
   Покажи, что взято (номер → работа #id, цель) и что пропущено и почему («уже взято сессией
   «…», 15 мин назад»).
   **Статус в Jira.** Среди взятых есть задачи группы `todo` не в работе (Open, To Do,
   Selected for Development) — задай **один** вопрос с галками (AskUserQuestion, multiSelect):
   «Перевести в In Progress?» со списком этих задач. Отмеченные — скиллом **jwu-task-status**
   (это запись в Jira — только отмеченные, без переспрашивания). Не отмеченные — не трогай.

4. **Делать по очереди.** Первую взятую — сразу, остальные — в очередь этой сессии
   (**jwu-queue**, режим main), по одному пункту на работу: «#447 — Конфликт PR #1092».
   По каждой работе: она уже заведена, поэтому **jwu-continue-job** (контекст, рабочая копия,
   план по фазам из jwu-start-job), правки — после «да» по обычным правилам. Цель достигнута —
   **jwu-close-job**, следующий пункт очереди.
   - `simple`: фаза 1 — влить целевую ветку и/или разобрать сборку (**jwu-build-failure**), ревью,
     коммит и пуш с «да».
   - `fixes`: прочитать замечания (`jwu_pr`, задачи PR, коммент QA — **jwu-qa-triage**), правки,
     ревью, коммит, ответы в тредах с «да».
   - `review`: это **jwu-review-queue** по взятым PR.

5. **Режим рабочего.** «Бери конфликты и падения, пока есть», «разгребай правки по одной» —
   после закрытия каждой работы сам: `jwu_todo()` (обновит, если данные старые) →
   `jwu_todo_take(group=…)` берёт **один** следующий свободный пункт группы (передавай
   `numbers=[n]` с первым свободным номером этой группы) → делай → закрывай → снова. Группа
   пуста — скажи «группа разобрана» и остановись. Пользователь пишет «стоп» — доделай
   текущий шаг, запиши `todo` «что дальше» и остановись.

6. **Молчащие сессии.** В шапке доски — «🟢 живые · 💤 молчащие». Пункт, взятый молчащей
   сессией, помечен «💤». Пользователь говорит «освободи Brave-Fox» — `jwu_todo_release("Brave-Fox")`:
   её работы уходят в паузу, задачи снова свободны. Сам не освобождай.

7. **Пользователь в другой сессии** запускает `/jwu-todo` — увидит взятое этой сессией и
   возьмёт остальное. Повторный запуск здесь показывает доску заново (номера обновятся).

## Чего не делать

- Брать пункт, помеченный «взято», — даже если «очень надо»: сначала спроси, не закрыть ли ту работу.
- Синкать самому параллельно демону: обновление — только через `jwu_todo(refresh=…)`.
- Начинать вторую работу, пока первая не закрыта или не отложена записью `todo`.
