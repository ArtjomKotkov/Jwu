# jwu: что делать и раздача по сессиям

**Work Main показывает доску, но не берёт работу.** На «покажи доску» используй штатный показ ниже, на «обнови» — штатное обновление. Сохранение технического снимка (`session`, номера, ключи и разделы) — часть показа, не бронь. Для поручения по номеру бери точный ключ и раздел только из снимка, показанного пользователю. Не обновляй доску для расшифровки старого номера. Снимок потерян — попроси точный ключ/PR или покажи новую доску и дождись нового выбора. Передай через **jwu-orchestrator** ключ/полный PR, раздел и ограничения пользователя. Взятие, журнал и закрытие — только в чате воркера; доставка брифа не подтверждает взятие.

## Доска в рабочей сессии

Несколько сессий работают параллельно. Каждая открывает доску, видит, что уже взято
другими, и берёт своё. Доска — из **кеша jwu** (снапшоты синка демона); старше 30 минут или по просьбе — обновляется через демон.
«Взято» = по задаче/PR есть активная работа; взятие атомарное — две сессии одно не возьмут.

> **MCP-first.** `jwu_todo()`, `jwu_todo_take(numbers, group)`.
> Bash: `jwu todo -s <сессия>`, `jwu todo -g simple -s <сессия>`.

## Группы

| группа | что в ней | как брать словами |
|---|---|---|
| `simple` 🔧 | мой PR с **конфликтом и/или красной сборкой**, замечаний людей нет — простое | «бери конфликты и падения» |
| `build` 🧪 | мой PR **без сборки на последнем коммите, не в очереди CI и без идущих автотестов** (например, после sync-мержа develop) — запустить сборку/тесты. Только в репозиториях, где CI сборки присылает (или по настройке `todo.build.required`) | «запусти сборки», «бери 4» |
| `fixes` ✍️ | **правки**: needs work, открытые задачи в PR, задача вернулась с QA (DEFECT, Need Update); конфликт и сборка у них — тоже тут | «бери правки по ревью», «бери возвраты QA» |
| `demo` 🎬 | задачи в статусах **Dev at stand / Demo** (`todo.statuses.demo`): подготовить и провести демо; рядом — PR и апрувы | «бери демо», «готовим демо по 3» |
| `todo` 📋 | **несделанные** задачи на мне: не начата или в работе, без моего открытого PR (In Review и дальше — сделано, тут их нет) | «бери задачу 5» |
| `review` 👀 | чужие PR ждут моего ревью | «начинаем разбор ревью» |

## Шаги

0. **Правила воркспейса** — **jwu-session-init**, если в этой сессии его ответа ещё нет или
   был `/clear`/компакт. Без правил раздавать работу нельзя.

1. **Имя сессии** — **не спрашивай**. Для воркера выбери своё постоянное уникальное имя по **jwu-start-job** и передавай `session` явно и при показе, и при взятии. При общем процессе MCP имя из шапки само по себе не изолирует чаты.

2. **Доска.** `jwu_todo(session=своя_сессия, workspace=slug)` → выведи поле `markdown` **дословно, целиком, как есть** —
   это готовая сводка таблицами от jwu. ⛔ Не пересказывай её, не перерисовывай таблицы, не
   сокращай колонки, не меняй порядок и не добавляй своих пунктов: номера в ней — те, по
   которым потом берутся задачи. Свой комментарий — максимум одна строка после сводки. Синку больше 30 минут —
   инструмент сам обновит данные перед показом (синк через демон, один на все сессии; до
   нескольких минут — скажи «обновляю данные»). Попросили «обнови», «свежее», «сходи в сеть» —
   `jwu_todo(refresh=True)`. Не обновилось (`refreshed.ok=False`) — покажи, что есть,
   и скажи, что данные от такого-то времени. В строке синка «⏳ идёт обновление» — синк уже
   идёт (другая сессия или расписание): предложи подождать — `jwu_todo(refresh=True)`
   дождётся этого прохода, второй не запустит.
   Помеченное «давно: закрыть или продолжить?» — подскажи **jwu-close-job** или
   **jwu-continue-job** по той работе.

3. **Взять.** Воркер проходит «Вход по поручению с доски» в **jwu-start-job**: проверяет контур, находит точный ключ в том же разделе под собственным `session`, проверяет прежние работы, берёт свободный пункт по своему номеру и `keys`, затем сверяет `taken`/`skipped` и владельца. Например, «P/r#42 из review, только черновик» не разрешает взять другую строку или опубликовать результат. При нескольких выбранных строках номера и ключи идут в одном порядке. Только по прямой просьбе воркер берёт всю группу: `jwu_todo_take(group=…, session=своя_сессия, workspace=slug)` (свободные пункты; для аддона сначала проверь защиту от двойного взятия). При пропуске не переходи ко всей группе.
   **Статус в Jira.** Среди взятых есть задачи группы `todo` не в работе (Open, To Do,
   Selected for Development) — задай **один** вопрос с галками (AskUserQuestion, multiSelect):
   «Перевести в In Progress?» со списком этих задач. Отмеченные — скиллом **jwu-task-status**
   (это запись в Jira — только отмеченные, без переспрашивания). Не отмеченные — не трогай.

4. **Делать по одной.** Первую взятую — сразу, остальные ждут своей очереди как взятые работы
   (по одной на пункт: «#447 — Конфликт PR #1092»); в конце каждой — следующая.
   По каждой работе: она уже заведена, поэтому **jwu-continue-job** (контекст и сверка всего плана с проверками до восстановления копии или стенда), правки — после «да» по обычным правилам. Цель достигнута —
   **jwu-close-job**, следующая взятая.
   - `simple`: фаза 1 — влить целевую ветку и/или разобрать сборку (**jwu-build-failure**), ревью,
     коммит и пуш с «да».
   - `build`: запустить сборку PR в CI. Сначала `jwu_builds(pr)` (несколько PR — одним
     `jwu_query`: цикл по номерам, вернуть `(id, build_state, autotests.summary)`): `autotests` в queued/running —
     уже ждут или идут, запускать не надо; есть источник автотестов (аддон) — меню «запустить
     автотесты PR #…?» и после «да» `jwu_pr_autotests_run(pr, user_approved=True)`. Иначе — так,
     как принято в воркспейсе (правило или гайд — `jwu_rules`, `jwu guide`). Способ требует действия наружу
     (коммит, коммент, кнопка) — с «да». Запустил — запись в журнал и закрыть работу итогом
     «запустил сборку PR #…»: дальше PR вернётся на доску сам («в очереди», «идёт», зелёная).
     Как запускать, неизвестно — спроси пользователя и предложи записать правилом.
   - `demo`: подготовка к показу — что сделано по задаче (журнал, PR), проверить на стенде,
     что фича работает (стенд — по правилам воркспейса), собрать сценарий показа: шаги, данные,
     что показать и что сказать. Итог работы — «подготовил демо по …». Статус задачи — только
     с «да» (**jwu-task-status**).
   - `fixes`: прочитать замечания (`jwu_pr`, задачи PR, коммент QA), правки,
     ревью, коммит, ответы в тредах с «да».
   - `review`: это **jwu-review-queue** по взятым PR.
   - Цель «Разбор возврата QA» (несделанная задача с непрочитанным комментом «↩ …»: вернули в
     работу и ждут ответа) — разобрать коммент (есть аддон со скиллом разбора — подсказка в
     `jwu_addons()`), ответ QA — только с «да». Для исправления сначала сверь план и проверки по **jwu-continue-job**; согласие на ответ не разрешает восстановление копии, стенда или правки.
   - У пункта «↩ автор: текст» — к задаче есть непрочитанный коммент: прочитай его в начале
     работы, даже если цель другая. Отдельной строки «Ответить» у такой задачи нет.
   - «взято (через №N)» — задачу уже ведёт работа по другому её пункту: этот не бери, иди в №N.

5. **Режим рабочего.** «Бери конфликты и падения, пока есть», «разгребай правки по одной» —
   после закрытия каждой работы сам: `jwu_todo()` (обновит, если данные старые) →
   `jwu_todo_take(numbers=[n], keys=[key], session=своя_сессия, workspace=slug)` берёт **один** следующий свободный пункт нужной группы → делай → закрывай → снова. Группа
   пуста — скажи «группа разобрана» и остановись. Пользователь пишет «стоп» — доделай
   текущий шаг, запиши `todo` «что дальше» и остановись.

6. **Молчащие сессии.** В шапке доски — «🟢 живые · 💤 молчащие». Пункт, взятый молчащей
   сессией, помечен «💤». Пользователь говорит «освободи Brave-Fox» — `jwu_todo_release("Brave-Fox")`:
   её работы уходят в паузу, задачи снова свободны. Сам не освобождай.

7. **Пользователь в другой сессии** запускает `/jwu-todo` — увидит взятое этой сессией и
   возьмёт остальное. Повторный запуск здесь показывает доску заново (номера обновятся).

## Чего не делать

- Брать пункт, помеченный «взято», — даже если «очень надо»: сначала спроси, не закрыть ли ту работу.
- Синкать самому параллельно демону: обновление — только через `jwu_todo(refresh=…)`.
- Начинать вторую работу, пока первая не закрыта или не отложена записью `todo`.
