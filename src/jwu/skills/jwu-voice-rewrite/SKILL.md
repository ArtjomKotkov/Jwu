# jwu: переписать текст голосом пользователя

## Overview

Быстрый путь для «перепиши под меня»: текст уже есть — его надо только сделать похожим на
пользователя. Никаких субагентов и сбора фактов: профиль голоса + переписывание прямо в
сессии. Наружу ничего не отправляется — отправку делает профильный скилл, если попросят.

## Шаги

1. **Профиль — один раз за сессию.** Если `profile_md` из `jwu_voice_profile()` уже есть в
   контексте — не вызывай снова. Иначе `jwu_voice_profile()` (bash: `jwu voice show` +
   чтение `profile.md`). Если `agent` в ответе НЕ `voice-writer-sample` — у контура свой
   агент голоса: отдай работу ему (`Agent`, `subagent_type = agent`, `mode: rewrite`,
   исходный текст, канал) и дальше п. 4.
2. **Канал** — из контекста: коммент в PR, ответ в тред, Jira, клиенту в SDESK, коммит,
   сообщение коллеге. Неясно и от канала сильно зависит длина — спроси одним словом;
   иначе бери самый вероятный и назови его.
3. **Перепиши** по правилам профиля для этого канала (ручные правила → «Анализ корпуса» →
   журнал правок):
   - смысл, факты, имена из кода, ссылки и номера — ровно как в исходнике: не добавлять,
     не убирать, не смягчать и не усиливать;
   - меняется только форма: длина, порядок мыслей, обращение, обороты, оформление.
4. **Выдай только текст** — без разбора, что поменял. Если пришлось что-то выкинуть или
   неоднозначное место трактовал — одна строка после текста.
5. **«Не похоже на меня»** — теперь подтяни примеры: `jwu_voice_examples(channel, limit=8)`,
   сравни с ними и перепиши; скажи в одной строке, что было не так. Системное отличие —
   предложи правило в профиль (`jwu_voice_feedback`, только после «да»).

## Чего не делать

- Запускать субагента или читать примеры корпуса без нужды — в этом смысл скилла.
- Менять смысл «чтобы звучало лучше».
- Отправлять текст куда-либо — это делают jwu-pr-comment, jwu-task-comment и т.п. после «да».
