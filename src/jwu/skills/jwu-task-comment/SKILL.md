# jwu: комментарий в задачу Jira/SDESK

> **Воркспейс = где лежит код.** Контур определяется по текущей папке, проверить —
> `jwu_workspace_current()` (bash: `jwu workspace current --json`). Правила контура
> приходят там же в `rules_md`; **записи `⛔ ЗАПРЕТ` обязательны к исполнению** —
> если правило запрещает писать клиенту напрямую, оно главнее этого скилла.

## Главное правило

**Комментарий не отправляется без явного «да» пользователя.** Это НЕ `jwu_note`
(та живёт в локальной памяти jwu) — текст уходит в саму Jira, его увидят люди,
и удалить его через jwu нельзя.

Порядок: **собрать текст → показать целиком → дождаться «да» → отправить.**

## Два случая, разная цена ошибки

| Куда | Кто читает | Что нужно |
|---|---|---|
| Задача Jira (`PROJ-123`) | команда | подтверждение пользователя |
| Задача **SDESK** | **КЛИЕНТ** | подтверждение именно на отправку клиенту + `client_facing=True` |

Признак приходит сам: в ответе dry-run есть поле `client_facing`. Если оно `true` —
скажи пользователю прямым текстом, что комментарий увидит клиент, покажи текст
**дословно** и получи согласие именно на это. Без `client_facing=True` (bash:
`--to-client`) инструмент откажет — так случайно отправленный клиенту черновик
становится невозможен.

## Инструменты

**MCP-first**: `jwu_comment(key, text, client_facing=False, dry_run=True)`.
Bash: `jwu comment KEY -m "…"` либо `jwu comment KEY -F ./answer.md` (файл или `-`
для stdin — так и передавай длинный многострочный текст).

`dry_run=True` по умолчанию: вызов ничего не пишет, а возвращает текст и
`client_facing`. Отправка — отдельный вызов с `dry_run=False` после «да».
В bash: `--dry-run` ничего не отправляет, а отправка требует `--yes`; без него
`--json` вернёт `{"ok": false, "reason": "confirm_required", …}`.

## Алгоритм

1. **Собери текст.** По-русски, **wiki-разметкой Jira Server**: `{code}…{code}` для
   логов и кода, `*жирный*`. Для клиента (SDESK) — без внутренней кухни: без имён
   веток, тикетов разработки, кусков кода и предположений, которые не проверены.
2. **Dry-run** — `jwu_comment(key, text)`.
3. **Покажи текст пользователю целиком**, не пересказ. Для SDESK — с явным
   предупреждением, что его прочитает клиент.
4. **Отправь** после «да»: тот же вызов с `dry_run=False` (для SDESK ещё и
   `client_facing=True`).
5. **Запиши в работу**, если она есть: `jwu_job_add(job_id, "Ответ в <KEY>", kind="note")`.

## Чего делать НЕ надо

- Отправлять черновик, «чтобы пользователь посмотрел в Jira» — смотреть он должен в чате.
- Считать «ответь клиенту» подтверждением текста, которого он ещё не видел.
- Писать в SDESK гипотезы как факты: клиент прочитает их как обещание.
- Ставить упоминания AI-ассистента и любую атрибуцию.
