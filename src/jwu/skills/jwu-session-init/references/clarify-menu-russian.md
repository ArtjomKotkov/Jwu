# Простые меню `clarify` (русский)

Эталоны для воркеров и оркестратора. Правила — в `SKILL.md` § «Меню в Hermes Desktop» и «Простой русский».

## Форма

- **Вопрос:** 1–2 предложения — что решаем (номер работы, PR, этап).
- **Варианты:** коротко, по делу; рекомендуемый первым, в тексте *(рекомендую)*.
- Жаргон расшифровывай в том же choice, не отдельной таблицей в чате.
- **Не** вставляй в вопрос абзац «ни один вариант не разрешает commit/push…», если таких пунктов в меню нет.

## Пример — после второго ревью

**Вопрос:** Как продолжить по #601 и PR #1322 после второго ревью?

- **A** — Локально догнать проверки опросов; очистку не делаем — остаётся блокером *(рекомендую)*
- **B** — Только план по происхождению данных под очистку, без правок в репо
- **C** — Пауза: #601 открыта, рабочая копия без изменений
- **D** — Другое

## Пример — подготовка без публикации

**Вопрос:** Продолжаем готовить #596 к релизу без публикации?

- **A** — Подтянуть develop и перепроверить локально *(рекомендую)*
- **B** — Оставить исправление только на машине, #596 не закрывать
- **C** — Другое

## Словарь (вшивать в текст варианта)

| Внутри команды | Как писать |
|----------------|------------|
| surveys / re-poll | проверки сценариев с опросами |
| cleanup step | шаг «очистка» по задаче |
| cleanup blocker | очистку не делаем сейчас — блокер |
| origin / accounting | происхождение данных, план под очистку |
| sync develop | подтянуть develop, локальные проверки |
| current copy | рабочая копия без изменений |
