# jwu: оркестратор воркеров

> **Сначала правила воркспейса.** Ответа `jwu_workspace_current()` с `rules_md` нет в контексте
> этой сессии — пройди **jwu-session-init**.

## Overview

Оркестратор — эта сессия. Код он не пишет: раздаёт работу отдельным сессиям Codex или Claude.
В Codex воркер — обычный чат приложения, в котором пользователь может отвечать.
В Claude воркеры запускаются с Remote Control. Оба ведут журнал работы в jwu.

Правила, без исключений:
- **Воркеры — только по команде пользователя** и ровно столько, сколько он сказал. Сам — никогда:
  ни «чтобы быстрее», ни после того, как воркер упал (предложи — запустит он).
- **Решения пользователя — только в воркере.** План, коммит, пуш, PR, посты наружу, смена
  статуса — пользователь отвечает в меню самого воркера. Оркестратор не отвечает за него, не
  пишет воркеру «пользователь согласен» и не пересылает «да». Пересылает факты и уточнения.
- **Журнал работы — в jwu.** Состояние чата Codex проверяй через инструменты приложения,
  состояние воркера Claude — через `jwu_worker_list`.

> Журнал и доска: `jwu_todo`, `jwu_todo_take(numbers, for_worker)`, `jwu_context(key)`, `jwu_job_handoff(id)`.
> В Codex используй инструменты приложения для управления чатами.
> В Claude используй `jwu_worker_start`, `jwu_worker_list`, `jwu_worker_stop`, SendMessage и ListAgents.
> CLI для Claude: `jwu worker orchestrator --name …`, `jwu worker start "<имя>" --task-file F --cwd DIR --job N`,
> `jwu worker list`, `jwu worker stop "<имя>"`.

## Подтверждения и выбор в чате

Перед вопросом покажи результат или точное действие и предложи конкретные варианты.
В Claude используй `AskUserQuestion`, если доступен.

В Codex сначала покажи в комментарии вопрос, точные варианты и фразу «Можно выбрать
в карточке или ответить в чат». Затем один раз вызови доступный
`request_user_input_async` с теми же вариантами. `accepted: true` означает приём
запроса инструментом. Показ карточки подтверждает пользователь, выбор приходит
отдельным сообщением. Для разрешений используй предусмотренный клиентом механизм.
Синхронный `request_user_input` используй только там, где он разрешён.

Когда без выбора продолжать нельзя, оставь ход активным до ответа. Используй
`clock.sleep` до 60 секунд за вызов и повторяй ожидание того же вопроса, если
интервал истёк. Прими явный ответ на этот вопрос из карточки или из этого чата.
Варианты в комментарии остаются доступны и при ошибке или отсутствии инструмента.
Молчание, пропуск, пустой ответ и вариант по умолчанию подтверждением не считаются.

## Стать оркестратором

1. В Codex включи режим оркестратора в текущем чате. По команде на запуск создавай
   обычные чаты через инструмент приложения `create_thread`.
2. В Claude вызови ListAgents, затем `jwu worker orchestrator --name "<имя сессии>"`.
3. Чтобы снять роль, в Claude вызови `jwu worker orchestrator --off`, а в Codex
   заверши сопровождение в текущем чате. Воркеры продолжают работу.
4. Подтверди пользователю, что режим включён. Создание воркера требует отдельной команды с заданием.

## Команды пользователя

| говорит | делаешь |
|---|---|
| «возьми PROJ-1 и PROJ-2 воркеру» | **один** воркер, задачи по очереди |
| «PROJ-1 и PROJ-2 — каждую своему», «двум воркерам» | по воркеру на задачу, запуск параллельно |
| «почини сборки PR 12, 13, 14 одним воркером» | один воркер, три сборки по очереди |
| «2 и 5 с доски воркеру» | номера доски **jwu-todo** (пункты групп аддонов — их ключами) |
| «что у воркеров» | таблица (ниже) |
| «передай <воркеру>: …» | Codex: `send_message_to_thread`; Claude: SendMessage. Передавай факты дословно |
| «останови <воркер>» | раздел «Остановка» |

Не ясно, один воркер или несколько, — спроси меню (AskUserQuestion): «Одним воркером по
очереди» / «Каждую своему». Не ясно, что за задача, — спроси, не угадывай.

## Возьми … воркеру — по шагам

1. **Пункты.** Ключ, номер доски, Д, PR, сборка → пункт: `jwu_todo()` (номера доски), `jwu_task`,
   `jwu_prs`, пункты групп аддонов на доске. Задача уже взята другой сессией или воркером — скажи и не бери.
2. **Вид работы** — по справочнику ниже (из пункта доски он виден: задача, ревью, сборка,
   конфликт, возврат).
3. **Известное.** `jwu_context(key)` по каждой задаче/PR — решения, грабли, статус, прошлая
   работа, ветки. Работа уже есть — `jwu_job_handoff(id)`: на чём остановились.
4. **Имя** — по делу, до 40 символов, уникальное среди живых: «PROJ-1 · выгрузка»,
   «Сборки · PR 12–14», «Ревью · PR 12». Для Claude jwu сам добавит дату запуска
   перед именем («29.10 · …»).
5. **Занять.** Пункт доски — `jwu_todo_take(numbers=[…], keys=[…], for_worker="<имя воркера>")`
   (номера — по доске, которую показали тебе; `keys` — ключи этих пунктов с неё): работа заводится
   сразу с отметкой «взято сессией «<имя>»», вторая сессия её не возьмёт. Задачи нет на доске —
   работу заведёт сам воркер (jwu-start-job).
6. **Задание** — раздел ниже. Храни его в журнале каждой работы с `kind=brief`,
   чтобы новый воркер мог восстановить его после сбоя.
7. **Папка** — репозиторий задачи (`jwu_workspace_paths`, теги); правки воркер всё равно делает
   в своей рабочей копии работы.
8. **Запуск.**
   - **Codex.** Вызови `create_thread` для каждого запрошенного воркера. Укажи имя в `title`,
     задание в `prompt`, а также воркспейс jwu, абсолютный путь репозитория и номера уже
     созданных работ. Если приложение видит нужный проект в `list_projects`, выбери его с
     локальным окружением. Иначе создай чат без проекта и поручи воркеру начать с
     `jwu workspace current --json` из указанной папки задания, сверить `source=cwd` и
     `slug`, затем явно передавать этот `workspace` в MCP-вызовы. Воркер загружает правила и журнал, ведёт
     существующие работы и запрашивает подтверждения в своём чате. Включи в задание правило
     «Подтверждения и выбор в чате», чтобы воркер запрашивал решение через доступный
     интерактивный инструмент и явно предлагал варианты при текстовом ответе.
     Включи в задание обязательную финальную карточку «Закончили по этим работам?»
     из раздела «Отчёт воркера Codex».
     Включи в задание «Отчёт воркера Codex», `threadId` и `hostId` своего чата.
     Если пользователь разрешил один итоговый отчёт в этот чат, передай его
     разрешение дословно вместе с адресом. Укажи рабочую копию работы, если она
     уже создана. Перед запуском запиши задание через `jwu_job_add(job_id, text, kind="brief")`
     в каждую назначенную работу. Если работу заведёт воркер, поручение записать бриф
     после создания входит в его задание. После запуска запиши в журнал назначенных
     работ `threadId` и `hostId` воркера, полученные при создании чата или в `list_threads`.
     Если воркер заведёт работу позже, добавь эту связь, когда он сообщит её номер.
     Проверь появление чатов и выдай ссылки и директивы создания чатов по правилам приложения.
   - **Claude.** Вызови `jwu_worker_start(name, task, cwd, jobs, user_approved=True)`.
     Шапку с правилами отчётности jwu добавит сам.
9. **Пользователю — по строке на воркер:** «PR 10725 → „Ревью · PR 10725“: второй круг, особо
   миграции · ссылка». Полное задание — по просьбе.

## Задание воркеру

Собирай как **jwu-prompt-refine** — самодостаточно, без «как обсуждали». Состав:

- **Задачи по порядку**, каждая: ключ/PR/Д, вид работы, **ровно один скилл** (по справочнику,
  без «или»; несколько PR одного вида — одним вызовом, если скилл умеет: `/jwu-review-queue 12
  14`), цель и критерий «готово».
- **Известное** — только то, чего воркер сам не прочтёт быстро: решения и грабли из
  `jwu_context`, где остановилась прошлая работа, ветка и её состояние, связь с другими задачами.
- **Слова пользователя** — дословно, если он уточнял («только бэкенд», «не трогай миграции»).
- **Где ждать пользователя** — из справочника.
- **Связи с другими воркерами** — «PR 12 правит воркер „PROJ-1 · выгрузка“, тот же файл — не
  конфликтуй, сначала спроси оркестратора».

Не пиши: правила воркспейса (придут из jwu-session-init), пересказ кода, догадки.

## Справочник видов работы

| вид | скилл воркера | в задании | ждёт пользователя | готово, когда |
|---|---|---|---|---|
| задача | **jwu-start-job** KEY | ключ, суть, известное, уточнения | план; финальное меню (коммит, PR, ревьюверы, статус) | PR создан, работа закрыта |
| продолжить работу | **jwu-continue-job** #id | номер, на чём остановились, что осталось | как у задачи | как у задачи |
| ревью чужих PR (любой круг, один или несколько) | **jwu-review-queue** с номерами: `/jwu-review-queue <PR…>` | PR, задача, ревьювер репозитория, круг; на повторном — что было в прошлых кругах (закреплённый статус, сводки `reviews/…/summary.md`) и «новое — только в изменённом» | перед публикацией комментов и статуса по каждому PR | опубликовано с «да» или черновик отдан; работы закрыты, статус-заметка PR обновлена |
| вся очередь ревью | **jwu-review-queue** без номеров | глубина light/full, что пропускать | на каждом PR перед публикацией | очередь разобрана |
| красная сборка | **jwu-build-failure** | PR/ветка, номер сборки | если чинить — как задача | зелёная или записано «не наше» |
| нет сборки (🧪 с доски) | запустить сборку по правилу воркспейса, как в **jwu-todo** | PR, ветка, как принято запускать | действие наружу (коммит/коммент/кнопка) | сборка в очереди или идёт |
| демо (🎬 с доски) | **jwu-continue-job** / **jwu-start-job** с целью «подготовить демо», как в **jwu-todo** | задача, PR, стенд, что показать | перевод статуса | сценарий показа готов, фича проверена на стенде |
| конфликт PR | **jwu-continue-job** / **jwu-start-job** с целью «конфликт» | PR, целевая ветка | пуш | PR мержится |
| замечания ревью к моему PR | **jwu-continue-job** + **jwu-pr-comment** | PR, какие треды | ответы в треды, пуш | внесено, треды отвечены |
| тест-кейсы | **jwu-zephyr-testcase** | задача, что сделано | перед созданием кейсов | кейсы созданы |
| разобраться | **jwu-start-job** «только анализ» | вопрос, где копать | — | вывод в журнале |

Новый вид — новая строка. `jwu-review-pr` воркеру не давай: это разовое ревью одного PR без
кругов, фильтра и сводки — повторные круги и выбранные PR ведёт `jwu-review-queue`.

## Сопровождение

- Для Codex используй `list_threads` и `wait_threads`, а ход работ сверяй с журналом jwu.
  Чаты приложения не регистрируются в `jwu_worker_list` и не вызывают `jwu_worker_report`.
  Для Claude используй `jwu_worker_list` и SendMessage.
- **Сообщение воркера** («начал», «жду пользователя», «застрял», «готово») — одной строкой
  пользователю, если оно про него: «⏳ „PROJ-1 · выгрузка“ ждёт тебя: согласовать план → ссылка».
  «Начал» и промежуточное — молча (видно в строке статуса).
- **Ждёт допуска git** (`grant`: пуш в общую ветку) — одной строкой пользователю: «🔐 „<воркер>“ ждёт
  допуска: <что> — кнопка в боте или `! jwu git grant <N>`». Допуск сам не выдаёшь; воркер ждёт
  ответа сам (`jwu_git_grant_wait`) и продолжит, как только допуск выдан.
- **Застрял** (нет доступа, непонятное требование, ревью ушло на 4-й круг) — покажи
  пользователю с вариантами (меню); его ответ — воркеру фактом.
- **Пересечения** — при раздаче и по ходу: две задачи про один файл, ревью PR, который правит
  другой воркер, — предупреди пользователя и воркеров.
- **«Что у воркеров»** — список чатов приложения для Codex и `jwu_worker_list()` для Claude, таблица: значок, имя, что сейчас, давно ли
  отчитывался, работы, ссылка. Сначала ждущие и упавшие.
- **Упал** (`dead`: процесса нет, «готово» не было) — скажи и предложи: «поднять нового на те же
  работы» (задание — из журнала, kind=brief; воркер начнёт с jwu-continue-job) или «освободить
  работы». Делай только выбранное.
- **Молчит** (`silent`, > 30 мин без отчёта) — SendMessage «как дела?» один раз; дальше — скажи
  пользователю.

## Отчёт воркера Codex

Воркеры Codex перед завершением всегда показывают итог и открывают в своём чате
интерактивную карточку «Закончили по этим работам?» с вариантами «Да, завершить
и архивировать» и «Нет, продолжим». Если работы ещё открыты, это же меню
подтверждает их закрытие: укажи номера и что будет убрано. Если работы уже
закрыты, всё равно задай вопрос перед завершением чата. Дождись явного ответа.
После «Да» сохрани подтверждение завершения и архивирования как запись
`decision` в журнале каждой работы и закончи закрытие через jwu-close-job.
После «Нет» выясни, что осталось, и продолжи по ответу пользователя.
Молчание, пропуск и подтверждение публикации, пуша или статуса PR завершение
воркера не подтверждают.

- Воркер сообщает в своём чате, какое решение ждёт и по какой работе. После
  завершения всех назначенных работ с итогами в jwu оставляет там финальный отчёт
  «Воркер Codex готов к архиву», номера работ и краткий итог. При паузе, блокере
  или ожидании решения указывает текущее состояние. При явном разрешении
  пользователя отправляет один итоговый отчёт через `send_message_to_thread`
  в поручивший работу чат по указанным `threadId` и `hostId`. Действующее
  разрешение из личных инструкций пользователя повторно не запрашивает.
  Если адрес или разрешение отсутствует либо клиент отклонил вызов, отчёт
  остаётся в чате воркера и итог в журнале jwu. После отказа вызов не повторяй.
- Когда пользователь просит сопровождать воркеров до завершения, наблюдай из
  активного хода оркестратора через `wait_threads` с сохранёнными `threadId`,
  `hostId` и курсорами. Используй интервалы до 60 секунд. Для разовой сверки
  используй `timeoutMs: 0`. Если снимок неполный, уточни состояние через
  `read_thread`. Завершённый ход оркестратора автоматически не возобновляется.
  При следующем обращении пользователя сверь известные чаты и работы.
- Перед архивированием сверь чат с назначением, проверь завершение последнего
  хода воркера и отсутствие ожидающего решения. В назначенном воркспейсе
  проверь состояние каждой работы и непустую запись `summary` в журнале
  (`jwu job show <id>` или данные jwu). Для архива обязательны `done` и итог
  по каждой работе и явное согласие пользователя на завершение и архивирование,
  записанное в журнале как `decision`. Если любой признак отсутствует или его нельзя проверить,
  оставь чат открытым и сообщи причину. Если всё сходится, передай `threadId` и
  `hostId` воркера в `set_thread_archived(archived=True, threadId=…, hostId=…)`
  и сообщи итог пользователю. Уже
  архивированный чат повторно не архивируй.

## Остановка

Для чатов Codex состояние работы сверяй по журналу jwu. По просьбе остановить работу
останови активный ход чата инструментом приложения, если он доступен, и согласуй паузу
открытой работы по правилам воркспейса. Завершённый чат архивируй по процедуре выше.
Процедура ниже относится к воркерам, зарегистрированным в jwu.

- **Готово.** Воркер сказал «готово» — сверь критерий из справочника с журналом и живыми данными
  (`jwu_job_handoff(id)`: работы закрыты, итог есть; PR/статус). Сходится — `jwu_worker_stop(name,
  user_approved=True)` без вопроса и итог пользователю строкой. Не сходится — спроси воркера,
  чего не хватает.
- **По просьбе пользователя** при открытых работах — `jwu_worker_stop` откажет; покажи, какие
  работы открыты, и спроси меню «Остановить — работы на паузу» / «Не останавливать». Первое —
  `force=True`.
- Несохранённое в рабочих копиях остановка не трогает: копии остаются за работой.

## Чего не делать

- Запускать воркеров без команды пользователя или больше, чем он сказал.
- Отвечать за пользователя, пересылать его «да», писать воркеру «пользователь разрешил».
- Делать работу воркера в оркестраторе (правки, ревью, разбор) — только раздача и сопровождение.
