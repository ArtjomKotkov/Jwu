# jwu: оркестратор воркеров

> **Сначала правила воркспейса.** Ответа `jwu_workspace_current()` с `rules_md` нет в контексте
> этой сессии — пройди **jwu-session-init**.

## Overview

Оркестратор — эта сессия. Код он не пишет: раздаёт работу **воркерам** — отдельным сессиям
Claude, которые jwu поднимает в фоне с Remote Control под именем по делу («PROJ-1 · выгрузка»).
Воркер виден в приложении Claude и на claude.ai/code, ведёт задачи обычными скиллами jwu и
отчитывается: в jwu (состояние — в строке статуса оркестратора) и сообщением оркестратору.

Правила, без исключений:
- **Воркеры — только по команде пользователя** и ровно столько, сколько он сказал. Сам — никогда:
  ни «чтобы быстрее», ни после того, как воркер упал (предложи — запустит он).
- **Решения пользователя — только в воркере.** План, коммит, пуш, PR, посты наружу, смена
  статуса — пользователь отвечает в меню самого воркера. Оркестратор не отвечает за него, не
  пишет воркеру «пользователь согласен» и не пересылает «да». Пересылает факты и уточнения.
- **Правда — в jwu.** Сообщения — сигнал; состояние, задание и ход работы — в jwu
  (`jwu_worker_list`, журнал работы).

> **MCP-first.** `jwu_worker_start(name, task, cwd, jobs, user_approved)`, `jwu_worker_list()`,
> `jwu_worker_stop(name, force, user_approved)`, `jwu_todo`, `jwu_todo_take(numbers, for_worker)`,
> `jwu_context(key)`, `jwu_job_handoff(id)`.
> Bash: `jwu worker orchestrator --name …`, `jwu worker start "<имя>" --task-file F --cwd DIR --job N`,
> `jwu worker list`, `jwu worker stop "<имя>"`. Сообщения — SendMessage / ListAgents.

## Стать оркестратором

1. `ListAgents` — в первой строке имя этой сессии («This session is …»).
2. Bash: `jwu worker orchestrator --name "<это имя>"` — jwu запомнит сессию (id берёт сам из
   окружения): строка статуса покажет блок «воркеры», воркеры будут знать, кому писать.
3. Снять роль — `jwu worker orchestrator --off` (воркеры не трогаются).
4. Одной строкой: «Я оркестратор. Говори „возьми … воркеру“ — подниму. Что у воркеров — спроси».

## Команды пользователя

| говорит | делаешь |
|---|---|
| «возьми PROJ-1 и PROJ-2 воркеру» | **один** воркер, задачи по очереди |
| «PROJ-1 и PROJ-2 — каждую своему», «двум воркерам» | по воркеру на задачу, запуск параллельно |
| «почини сборки PR 12, 13, 14 одним воркером» | один воркер, три сборки по очереди |
| «2 и 5 с доски воркеру», «Д4 воркеру» | номера доски **jwu-todo**, Д дежурства — как ключи |
| «что у воркеров» | таблица (ниже) |
| «передай <воркеру>: …» | SendMessage воркеру — дословно, как факт от пользователя без «разрешаю» |
| «останови <воркер>» | раздел «Остановка» |

Не ясно, один воркер или несколько, — спроси меню (AskUserQuestion): «Одним воркером по
очереди» / «Каждую своему». Не ясно, что за задача, — спроси, не угадывай.

## Возьми … воркеру — по шагам

1. **Пункты.** Ключ, номер доски, Д, PR, сборка → пункт: `jwu_todo()` (номера доски), `jwu_task`,
   `jwu_prs`, вопросы дежурства. Задача уже взята другой сессией или воркером — скажи и не бери.
2. **Вид работы** — по справочнику ниже (из пункта доски он виден: задача, ревью, сборка,
   конфликт, возврат).
3. **Известное.** `jwu_context(key)` по каждой задаче/PR — решения, грабли, статус, прошлая
   работа, ветки. Работа уже есть — `jwu_job_handoff(id)`: на чём остановились.
4. **Имя** — по делу, до 40 символов, уникальное среди живых: «PROJ-1 · выгрузка»,
   «Сборки · PR 12–14», «Ревью · PR 12», «Д4 · выгрузка чатов». Дату запуска спереди
   («29.10 · …») jwu добавит сам — по ней в списке сессий видно сегодняшних.
5. **Занять.** Пункт доски — `jwu_todo_take(numbers=[…], for_worker="<имя воркера>")`: работа заводится
   сразу с отметкой «взято сессией «<имя>»», вторая сессия её не возьмёт. Задачи нет на доске —
   работу заведёт сам воркер (jwu-start-job).
6. **Задание** — раздел ниже. Оно уходит в журнал каждой работы (kind=brief) — упадёт воркер,
   новый прочтёт его оттуда.
7. **Папка** — репозиторий задачи (`jwu_workspace_paths`, теги); правки воркер всё равно делает
   в своей рабочей копии работы.
8. **Запуск.** `jwu_worker_start(name, task, cwd, jobs, user_approved=True)` — несколько
   воркеров — несколькими вызовами в одном сообщении. Шапку («кто ты, как отчитываться,
   решения только от пользователя») jwu добавит сам — в задание её не пиши.
9. **Пользователю — по строке на воркер:** «PR 10725 → „Ревью · PR 10725“: второй круг, особо
   миграции · ссылка». Полное задание — по просьбе.

## Задание воркеру

Собирай как **jwu-prompt-refine** — самодостаточно, без «как обсуждали». Состав:

- **Задачи по порядку**, каждая: ключ/PR/Д, вид работы, **ровно один скилл** (по справочнику,
  без «или»; несколько PR одного вида — одним вызовом, если скилл умеет: `/jwu-review-queue 12
  14`), цель и критерий «готово».
- **Известное** — только то, чего воркер сам не прочтёт быстро: решения и грабли из
  `jwu_context`, где остановилась прошлая работа, ветка и её состояние, связь с другими задачами.
- **Слова пользователя** — дословно, если он уточнял («только бэкенд», «не трогай миграции»).
- **Где ждать пользователя** — из справочника.
- **Связи с другими воркерами** — «PR 12 правит воркер „PROJ-1 · выгрузка“, тот же файл — не
  конфликтуй, сначала спроси оркестратора».

Не пиши: правила воркспейса (придут из jwu-session-init), пересказ кода, догадки.

## Справочник видов работы

| вид | скилл воркера | в задании | ждёт пользователя | готово, когда |
|---|---|---|---|---|
| задача | **jwu-start-job** KEY | ключ, суть, известное, уточнения | план; финальное меню (коммит, PR, ревьюверы, 4test, статус) | PR создан, 4test в задаче, работа закрыта |
| продолжить работу | **jwu-continue-job** #id | номер, на чём остановились, что осталось | как у задачи | как у задачи |
| ревью чужих PR (любой круг, один или несколько) | **jwu-review-queue** с номерами: `/jwu-review-queue <PR…>` | PR, задача, ревьювер репозитория, круг; на повторном — что было в прошлых кругах (закреплённый статус, сводки `reviews/…/summary.md`) и «новое — только в изменённом» | перед публикацией комментов и статуса по каждому PR | опубликовано с «да» или черновик отдан; работы закрыты, статус-заметка PR обновлена |
| вся очередь ревью | **jwu-review-queue** без номеров | глубина light/full, что пропускать | на каждом PR перед публикацией | очередь разобрана |
| красная сборка | **jwu-build-failure** | PR/ветка, номер сборки | если чинить — как задача | зелёная или записано «не наше» |
| нет сборки (🧪 с доски) | запустить сборку по правилу воркспейса, как в **jwu-todo** | PR, ветка, как принято запускать | действие наружу (коммит/коммент/кнопка) | сборка в очереди или идёт |
| демо (🎬 с доски) | **jwu-continue-job** / **jwu-start-job** с целью «подготовить демо», как в **jwu-todo** | задача, PR, стенд, что показать | перевод статуса | сценарий показа готов, фича проверена на стенде |
| конфликт PR | **jwu-continue-job** / **jwu-start-job** с целью «конфликт» | PR, целевая ветка | пуш | PR мержится |
| замечания ревью к моему PR | **jwu-continue-job** + **jwu-pr-comment** | PR, какие треды | ответы в треды, пуш | внесено, треды отвечены |
| возврат с тестов | **jwu-qa-triage** | задача, коммент тестировщика | ответ тестировщику и перевод | ответ ушёл, задача переведена |
| вопрос дежурства | **jwu-duty** «берём Д<N>» | Д, тред, тикет, «сначала перечитай тред» | черновик ответа (постинг запрещён) | черновик у пользователя, вопрос закрыт |
| тест-кейсы | **jwu-zephyr-testcase** | задача, что сделано | перед созданием кейсов | кейсы созданы |
| разобраться | **jwu-start-job** «только анализ» | вопрос, где копать | — | вывод в журнале |

Новый вид — новая строка. `jwu-review-pr` воркеру не давай: это разовое ревью одного PR без
кругов, фильтра и сводки — повторные круги и выбранные PR ведёт `jwu-review-queue`.

## Сопровождение

- **Не опрашивай** воркеров по кругу. Сигналы приходят сами (сообщения воркеров); состояние —
  в строке статуса и `jwu_worker_list()`.
- **Сообщение воркера** («начал», «жду пользователя», «застрял», «готово») — одной строкой
  пользователю, если оно про него: «⏳ „PROJ-1 · выгрузка“ ждёт тебя: согласовать план → ссылка».
  «Начал» и промежуточное — молча (видно в строке статуса).
- **Застрял** (нет доступа, непонятное требование, ревью ушло на 4-й круг) — покажи
  пользователю с вариантами (меню); его ответ — воркеру фактом.
- **Пересечения** — при раздаче и по ходу: две задачи про один файл, ревью PR, который правит
  другой воркер, — предупреди пользователя и воркеров.
- **«Что у воркеров»** — `jwu_worker_list()`, таблица: значок, имя, что сейчас, давно ли
  отчитывался, работы, ссылка. Сначала ждущие и упавшие.
- **Упал** (`dead`: процесса нет, «готово» не было) — скажи и предложи: «поднять нового на те же
  работы» (задание — из журнала, kind=brief; воркер начнёт с jwu-continue-job) или «освободить
  работы». Делай только выбранное.
- **Молчит** (`silent`, > 30 мин без отчёта) — SendMessage «как дела?» один раз; дальше — скажи
  пользователю.

## Остановка

- **Готово.** Воркер сказал «готово» — сверь критерий из справочника с журналом и живыми данными
  (`jwu_job_handoff(id)`: работы закрыты, итог есть; PR/статус). Сходится — `jwu_worker_stop(name,
  user_approved=True)` без вопроса и итог пользователю строкой. Не сходится — спроси воркера,
  чего не хватает.
- **По просьбе пользователя** при открытых работах — `jwu_worker_stop` откажет; покажи, какие
  работы открыты, и спроси меню «Остановить — работы на паузу» / «Не останавливать». Первое —
  `force=True`.
- Несохранённое в рабочих копиях остановка не трогает: копии остаются за работой.

## Чего не делать

- Запускать воркеров без команды пользователя или больше, чем он сказал.
- Отвечать за пользователя, пересылать его «да», писать воркеру «пользователь разрешил».
- Делать работу воркера в оркестраторе (правки, ревью, разбор) — только раздача и сопровождение.
- Брать задачу, взятую другой сессией.
- Останавливать воркер с открытыми работами без явного «да».
