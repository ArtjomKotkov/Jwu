# jwu: настройка воркспейса

## Overview

**Воркспейс** — контур работы в jwu: набор папок + подключённые интеграции (Jira/Bitbucket)
+ свои локальные данные (работы, локальные фичи, заметки, анализы, снапшоты). Данные разных
воркспейсов не пересекаются: домашний pet-проект не видит рабочих задач и наоборот.

Воркспейс определяется **автоматически по текущей папке** — поэтому главное действие этого
скилла — привязать папки. Всё остальное (интеграции, креды) нужно только рабочему контуру.

## Когда

- `jwu` говорит «не понял, в каком воркспейсе работать» либо показывает не тот контур.
- Пользователь заводит новый проект/репозиторий и хочет вести его в jwu.
- Нужно отделить домашние проекты от рабочих.

## Шаги

1. **Посмотри, что есть сейчас:**

   ```bash
   jwu workspace current --json   # что резолвится в этой папке и ПОЧЕМУ (source)
   jwu workspace list             # все воркспейсы
   ```

   `source` объясняет выбор: `cwd` (папка привязана), `active` (последний выбранный),
   `env`, `explicit`, `only`. Если текущая папка уже привязана к нужному воркспейсу — готово.

2. **Уточни у пользователя**, если неясно: это рабочий контур (Jira/Bitbucket) или личный
   (без интеграций)? Не угадывай — от этого зависит, спрашивать ли креды.

3. **Создай воркспейс.** Интеграции объявляются ЯВНО, по умолчанию их нет:

   ```bash
   # личный проект: ничего подключать не надо, работает сразу
   jwu workspace create home-jwu --name "Личное" --path . --no-jira --no-bitbucket

   # рабочий контур
   jwu workspace create work --name "Работа" --path . --jira --bitbucket
   ```

4. **Привяжи остальные папки** (репозиториев может быть несколько):

   ```bash
   jwu workspace add-path ~/dev/backend --label "бэкенд"
   ```

   Одна папка принадлежит ровно одному воркспейсу; у вложенных папок выигрывает самая глубокая
   привязка — так `~/dev` может быть рабочим, а `~/dev/toy` личным.

5. **Только для рабочего контура — доступы:**

   ```bash
   jwu configure -W work          # интерактивно: хосты, логины, токены
   jwu auth check
   ```

   **Скажи пользователю прямо:** токены и пароли хранятся в БД jwu (`~/.local/share/jwu/state.db`)
   **в открытом виде**. Файл закрывается правами 600, но если БД лежит в облачной папке
   (iCloud/Dropbox/…), секреты уедут в облако — jwu об этом предупреждает. Альтернатива —
   держать токены в переменных окружения (`JIRA_TOKEN`, `BITBUCKET_TOKEN`, …): они перекрывают БД.

6. **Проверь результат:**

   ```bash
   jwu workspace show     # папки, интеграции, счётчики; секреты показаны как ****
   ```

## Что дальше

- Личный воркспейс: заводи фичи `jwu feature add "…"` — их ключи (`HOMEJWU-1`) годятся
  как префикс ветки и коммита; работу начинай через **jwu-start-job**.
- Рабочий: обычный цикл — **jwu-start-job** → **jwu-track-job** → **jwu-job-review**.

## Чего не делать

- Не создавай воркспейс молча, если пользователь просто оказался в непривязанной папке —
  сначала покажи `jwu workspace list` и спроси, привязать ли папку к существующему.
- Не переноси чужую папку между воркспейсами без спроса (`remove-path` + `add-path`).
- Не печатай значения секретов (`--show-secrets`) без явной просьбы.

## Связанные скиллы

**jwu-start-job** — начать работу в воркспейсе. **jwu-track-job** — вести её лог.
