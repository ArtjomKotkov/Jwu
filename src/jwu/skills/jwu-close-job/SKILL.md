# jwu: закрыть работу (job)

## Overview

Работу закрывают, когда достигнута её **цель** — та, ради которой её начали (см. заголовок):

| цель работы | критерий «готово» |
|---|---|
| сделать задачу | правки сделаны, ревью пройдено, закоммичено и запушено, PR создан/обновлён |
| конфликт PR | целевая ветка влита, конфликт разрешён, запушено, PR мержится |
| красная сборка | причина найдена и устранена, новая сборка зелёная (или упавшее — не наше и это записано) |
| правки по ревью | замечания внесены, запушено, задачи PR закрыты/отвечены |
| анализ / разбор | вывод получен и записан в журнал, пользователь его видел |

Не по цели («надоело», «перехожу на другое») — это не закрытие: запиши `todo` «что дальше»
и оставь работу открытой (или `jwu_job_status(id, "paused")`).

Закрытие = **итог** (`summary`, его берёт трекинг времени) + выжимка заметкой на задачу и PR + статус `done`. Стандартная уборка безопасных ресурсов работы входит в закрытие без второй карточки.

> **MCP-first.** `jwu_job_close(job_id, summary, cleanup=True)`, `jwu_job_cleanup(job_id,
> dry_run, force)`, `jwu_job_resources(job_id)`, `jwu_job_handoff(job_id)`, `jwu_disk()`.
> Bash: `jwu job done <id> --summary "…" --cleanup`, `jwu job cleanup <id> [--dry-run] [--force]`,
> `jwu job delete <id> [--force]`.

## Предложить закрыть — меню

В **интерактивном чате Hermes Desktop** действует отдельное правило.

**Архив чата — только вручную в Hermes Desktop.** После завершения работы оставь чат открытым. Не предлагай архив сам и не добавляй его в карточку закрытия работы. Если пользователь сам спросил об архиве, укажи «Архивировать» в меню именно этого чата в Hermes Desktop. Не архивируй скриптом и не пересылай просьбу или согласие ни промптом, ни почтой. Архив не меняет Jira и не разрешает уборку файлов.

Обычный итог воркера Hermes отправь в проверенный Main через пассивный `session_mailbox` по **jwu-orchestrator**. Итог не является просьбой об архиве. При сбое почты не подменяй её промптом.

Если точное закрытие уже согласовано и проверенный объём уборки не изменился, не спрашивай снова. Иначе после превью покажи ID, итог, что будет убрано и что останется. Предложи применимые варианты «Закрыть и взять следующее с доски», «Закрыть», «Оставить открытой» через меню клиента (`clarify` в Hermes, иначе доступная форма или текстовый выбор). Следующее — только после подтверждённого закрытия, по правилам **jwu-todo**.

## Шаги

> **Сначала правила.** Ответа `jwu_workspace_current()` с `rules_md` нет в контексте этой
> сессии (новая сессия, `/clear`, компакт) — пройди **jwu-session-init**. Без правил
> воркспейса не начинай, не правь и не закрывай.

1. **Какая работа.** В контексте — она; нет — `jwu_jobs(status="active")`, несколько — спроси.

2. **Цель достигнута?** Сверь по таблице выше с журналом и живыми данными (сборка, PR,
   незакрытые `todo`, `bug` без `bug-resolved`). Не достигнута — скажи, чего не хватает, и
   не закрывай без явного «закрывай всё равно».

3. **Итог — одной строкой простыми словами**, что сделано за всю работу: «перенёс правку
   в 10.8 и починил тесты», «разобрал падение сборки — виноват develop, влил его». Без хешей,
   путей, номеров сборок — это читает человек в сводке дня и в трекинге времени. Отдельно
   его не согласовывай: он показан в вопросе о закрытии (ниже).

4. **Проверь безопасность уборки.** Сверь `jwu_job_resources(job_id)` и `jwu_job_cleanup(job_id, dry_run=True, force=False)` с фактическими путями, содержимым, метками, томами и ссылками на образы, в том числе из остановленных контейнеров. Убирай только своё; не трогай общие кэши, чужие ресурсы и единственный экземпляр обещанного отчёта. Отчёт сначала отдай или сохрани вне удаляемого каталога. Не используй глобальный `prune`.
   Пустой `kept` не доказывает безопасность: отдельно прочитай ветку, HEAD и `git --no-optional-locks status --porcelain` каждой копии, сверь сохранность локальных коммитов по подтверждённой удалённой ветке. Ошибка, сомнение или расхождение с превью — стоп. Перед удалением копии проверь политику `worktree` по пути и ветке (`git policy check worktree --path REF --branch BRANCH --where job`); получи обязательный допуск, при `deny` или неразрешённом `grant` не удаляй.
   `kept` не пуст — останови стандартное закрытие, покажи точные копии и риск, предложи защищённый коммит/пуш, оставить открытой или отдельно подтвердить конкретную потерю. Обычное согласие не разрешает `force`. Повтори превью после изменений.

5. **Закрой и проверь.** По точному согласию `jwu_job_close(job_id, summary="…", cleanup=True)` — стандартная уборка, итог, выжимка и `done`. Если пользователь выбрал закрытие с сохранением перечисленных ресурсов, не запускай массовую уборку: убери только поимённо проверенное и разрешённое, затем закрой с `cleanup=False` / без `--cleanup`. Не выдавай это за устранение ошибки уборки или `kept`, назови всё оставленное. `force=True` допустим только при отдельном явном согласии на точную неизменившуюся потерю и разрешённой политике. При `closed=False`, `cleanup.kept` или ошибках разберись, не повторяй запись вслепую. Перечитай `job show ID --json` и проверь `done`, итог и состояние ресурсов.

6. **Хвосты — одним списком с галками.** Собери, что ещё уместно сделать снаружи, и задай
   **один** вопрос с множественным выбором (AskUserQuestion, multiSelect), а не по вопросу на
   пункт. Варианты — только применимые к этой работе:
   - перевести задачу в статус «<следующий по процессу>» (**jwu-task-status**);
   - шаги аддонов после работы — подсказки в `jwu_addons()` (`after` у `jwu-close-job`);
   - закрыть открытые задачи PR, которые сделаны (**jwu-pr-task**);
   - ответить в треды ревьюеров о сделанном (**jwu-pr-comment**);
   - затрекать время по итогу (**jwu-track-time**).
   После финиша работы (**jwu-start-job**: тексты, пуш, PR уже сделаны) — сделанное
   не предлагай; осталось нечего — вопрос не задавай.
   Отмеченное делай по очереди тем скиллом; тексты наружу — через агента голоса, с показом
   перед отправкой. Не отмеченное — не делай и не переспрашивай.

7. **Скажи итог:** что закрыто, что убрано, сколько места освободилось (`jwu_disk()`).

## Удаление работы

Ошибочная или пустая работа — `jwu job delete <id>`: та же уборка, потом журнал стирается
целиком. Если итог работы уже ушёл в трекинг времени — удалять только после явного «да»
(история пропадёт). Копии с несохранённым — как в шаге 4.

## Чего не делать

- Закрывать без итога: трекинг времени его не найдёт и будет напоминать о «незакрытой» работе.
- Удалять копию с незакоммиченным/незапушенным без явного «да».
- Сносить docker-ресурсы без метки работы «на всякий случай»: уборка трогает только своё.
- Менять статус задачи в Jira/GitHub, закрывать задачи PR, трекать время — без «да».
