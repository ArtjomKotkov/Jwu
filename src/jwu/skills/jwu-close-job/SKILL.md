# jwu: закрыть работу (job)

## Overview

Работу закрывают, когда достигнута её **цель** — та, ради которой её начали (см. заголовок):

| цель работы | критерий «готово» |
|---|---|
| сделать задачу | правки сделаны, ревью пройдено, закоммичено и запушено, PR создан/обновлён |
| конфликт PR | целевая ветка влита, конфликт разрешён, запушено, PR мержится |
| красная сборка | причина найдена и устранена, новая сборка зелёная (или упавшее — не наше и это записано) |
| правки по ревью | замечания внесены, запушено, задачи PR закрыты/отвечены |
| анализ / разбор | вывод получен и записан в журнал, пользователь его видел |

Не по цели («надоело», «перехожу на другое») — это не закрытие: запиши `todo` «что дальше»
и оставь работу открытой (или `jwu_job_status(id, "paused")`).

Закрытие = **итог** (`summary`, его берёт трекинг времени) + **уборка** всего, что создала
работа + выжимка заметкой на задачу и PR + статус `done`.

> **MCP-first.** `jwu_job_close(job_id, summary, cleanup=True)`, `jwu_job_cleanup(job_id,
> dry_run, force)`, `jwu_job_resources(job_id)`, `jwu_job_handoff(job_id)`, `jwu_disk()`.
> Bash: `jwu job done <id> --summary "…" --cleanup`, `jwu job cleanup <id> [--dry-run] [--force]`,
> `jwu job delete <id> [--force]`.

## Предложить закрыть — меню

Цель достигнута (в любом скилле: финиш работы, разбор возврата с тестов, ответ в PR,
разбор сборки) — не спрашивай текстом «закрыть?». Спроси меню (AskUserQuestion):
вопрос «Закрыть работу #<id>? Итог: <одна строка>. Уберу: <копии, стенд, файлы>; оставлю: <что и почему>» и варианты «Закрыть и взять следующее с
доски» (первым, если в сессии работали с доской **jwu-todo**), «Закрыть», «Оставить открытой».
«Взять следующее» — после закрытия **jwu-todo** и первое свободное по приоритету.

## Шаги

> **Сначала правила.** Ответа `jwu_workspace_current()` с `rules_md` нет в контексте этой
> сессии (новая сессия, `/clear`, компакт) — пройди **jwu-session-init**. Без правил
> воркспейса не начинай, не правь и не закрывай.

1. **Какая работа.** В контексте — она; нет — `jwu_jobs(status="active")`, несколько — спроси.

2. **Цель достигнута?** Сверь по таблице выше с журналом и живыми данными (сборка, PR,
   незакрытые `todo`, `bug` без `bug-resolved`). Не достигнута — скажи, чего не хватает, и
   не закрывай без явного «закрывай всё равно».

3. **Итог — одной строкой простыми словами**, что сделано за всю работу: «перенёс правку
   в 10.8 и починил тесты», «разобрал падение сборки — виноват develop, влил его». Без хешей,
   путей, номеров сборок — это читает человек в сводке дня и в трекинге времени. Отдельно
   его не согласовывай: он показан в вопросе о закрытии (ниже).

4. **Что будет убрано.** `jwu_job_cleanup(job_id, dry_run=True)` — список не показывай, если
   `kept` пуст (всё закоммичено и запушено): уборка своего безопасна. Иначе — стенд
   (compose `jwu-job<id>`), контейнеры, вольюмы, сети, образы с меткой `jwu.job=<id>`,
   записанные каталоги кеша, рабочие копии. `kept` не пуст — там копии с незакоммиченным
   или незапушенным: **стоп**. Предложи закоммитить/запушить (по обычным правилам, с «да»)
   или явно подтвердить потерю.

5. **Закрыть.** `jwu_job_close(job_id, summary="…")` — уборка, итог, выжимка, `done` одним
   вызовом. `closed=False` — что-то не убралось (`cleanup.kept` / `cleanup.errors`): разберись
   и повтори. Подтвердил потерю — `jwu_job_cleanup(job_id, dry_run=False, force=True)`, потом
   снова `jwu_job_close`.

6. **Хвосты — одним списком с галками.** Собери, что ещё уместно сделать снаружи, и задай
   **один** вопрос с множественным выбором (AskUserQuestion, multiSelect), а не по вопросу на
   пункт. Варианты — только применимые к этой работе:
   - перевести задачу в статус «<следующий по процессу>» (**jwu-task-status**);
   - написать 4test для QA (**jwu-4test-message**) — если задача уходит в тестирование;
   - закрыть открытые задачи PR, которые сделаны (**jwu-pr-task**);
   - ответить в треды ревьюеров о сделанном (**jwu-pr-comment**);
   - затрекать время по итогу (**jwu-track-time**).
   После финиша работы (**jwu-start-job**: тексты, пуш, PR, 4test уже сделаны) — сделанное
   не предлагай; осталось нечего — вопрос не задавай.
   Отмеченное делай по очереди тем скиллом; тексты наружу — через агента голоса, с показом
   перед отправкой. Не отмеченное — не делай и не переспрашивай.

7. **Скажи итог:** что закрыто, что убрано, сколько места освободилось (`jwu_disk()`).

## Удаление работы

Ошибочная или пустая работа — `jwu job delete <id>`: та же уборка, потом журнал стирается
целиком. Если итог работы уже ушёл в трекинг времени — удалять только после явного «да»
(история пропадёт). Копии с несохранённым — как в шаге 4.

## Чего не делать

- Закрывать без итога: трекинг времени его не найдёт и будет напоминать о «незакрытой» работе.
- Удалять копию с незакоммиченным/незапушенным без явного «да».
- Сносить docker-ресурсы без метки работы «на всякий случай»: уборка трогает только своё.
- Менять статус задачи в Jira/GitHub, закрывать задачи PR, трекать время — без «да».
