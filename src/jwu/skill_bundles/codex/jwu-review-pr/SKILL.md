# jwu: ревью чужого PR из сессии

## Вход по поручению

Воркер, которому назначен PR с доски, сначала проходит «Вход по поручению с доски» в **jwu-start-job** в своей сессии. Используй только подтверждённый ID работы по этому полному `project/repo#PR`; совпадения задачи недостаточно. Если очередь уже проверила бронь, повторно не бери. Прямое `/jwu-review-pr` без назначения не требует брифа или автоматического создания работы.

> **Сначала правила воркспейса.** Ответа `jwu_workspace_current()` с `rules_md` нет в контексте
> этой сессии (новая сессия, `/clear`, компакт) — сначала пройди **jwu-session-init**. Без правил
> воркспейса не действуй: запреты (⛔) в них обязательны.

## Overview

jwu-job-review смотрит СВОЙ локальный дифф до коммита. Этот скилл — про PR коллеги: дифф
берётся через jwu (клон не нужен), разбор делает субагент-ревьювер, а всё, что уходит в
Bitbucket/GitHub (комменты, задачи на комментах, статус), — только после явного «да».

> **MCP-first.** `jwu_pr(pr_id, project, repo)` — карточка: описание, ревьюверы, `comments[]`,
> `open_tasks`, `attachments`, `build_state`; `jwu_pr_diff(pr_id, path)` — unified diff;
> `jwu_pr_attachments(download=True)` — скриншоты; запись — `jwu_pr_comment`,
> `jwu_pr_task_add`, `jwu_pr_review`. Bash-фолбэк: `jwu pr <id> --diff`, `jwu pr-comment`,
> `jwu pr-task add`, `jwu pr-review`.

## Аргументы

`/jwu-review-pr <PR_ID> [reviewer-subagent] [--project P --repo R]`. Субагент — как в
jwu-job-review: обязательная роль из правил, затем совместимая роль из запроса, настройка
репозитория или `reviewer-jwu-sample`. Спроси только при конфликте или недоступной нужной роли. Проект и репозиторий — из `jwu_prs(view="review")`,
если пользователь назвал только номер.

## Шаги

Во всех PR-вызовах используй проверенные `project`, `repo`, `pr_id` и `workspace` (CLI: `--workspace SLUG` и `--project P --repo R`). Номер PR без репозитория при неоднозначности уточни.

1. **Контекст PR.** `jwu_context("PROJ/repo#ID")` (свои прошлые заметки, статус) и
   `jwu_pr(...)`: заголовок, описание, ветки, ревьюверы, комменты, открытые задачи,
   сборка. Скриншоты в описании/комментах — скачай и прочитай через Read.
2. **Задача.** Ключ — из ветки/заголовка (`task_key` в ответе `jwu_pr`); `jwu_task(key)`
   за требованиями и договорённостями. Без задачи — ревью по описанию PR, скажи об этом.
3. **Дифф.** `jwu_pr_diff(pr_id)`; больше ~60 КБ — по файлам через `path` (список файлов
   в поле `files`). В субагент — весь дифф, иначе «потеря правок из target» не проверится.
4. **Субагент.** `Agent` с `subagent_type = <ревьювер>` и промптом как в jwu-job-review
   (задача, метаданные PR без тредов, задач на комментариях и истории прошлых кругов, дифф).
   Пометь: «это ЧУЖОЙ PR, только разбор; сверяй с проверенным target через `git show` в
   подтверждённом клоне». Если нужна свежая база, только вызывающая сессия может выполнить
   разрешённый `git fetch origin <target>` с проверенными remote и ref и сверить полученный
   коммит. Без клона — только дифф. Не переключай ветки, не запускай код PR и не правь копию.
5. **Фильтр замечаний.** `Agent` с `subagent_type` = фильтр контура (`jwu review agents`,
   по умолчанию `review-filter-sample`): выход ревьювера + PR/target/задача, треды и история прошлых кругов. Он оставит
   только то, что внёс ЭТОТ PR (`new` / `made-reachable`), отсечёт натянутое, найдёт
   точное место (`path`, `line` из `jwu_pr_diff(numbered=True)`, либо `reply_to` в тред
   автора) и вернёт факты + предлагаемый статус.
6. **Покажи выводы пользователю**: оставшиеся замечания с `file:line`, отброшенное
   одной строкой на пункт, pre-existing — отдельно. Ничего ещё не отправлено.
7. **Согласуй, что уходит наружу**, по пунктам (тексты — агент голоса, см. ниже):
   - автор спросил в треде — сначала ответ туда (`reply_to`);
   - замечание → `jwu_pr_comment(pr_id, text, path=…, line=…)` (inline; тип строки jwu
     берёт из диффа, `anchored: false` в ответе — сказать и предложить переотправить) или общий;
   - «надо поправить» с чекбоксом → `jwu_pr_task_add(pr_id, text, comment_id=…)`, текст
     до 10 слов формулирует пользователь (скилл jwu-pr-task);
   - статус → `jwu_pr_review(pr_id, "APPROVED"|"NEEDS_WORK", text)` — только если пользователь явно выбрал этот статус и показанный текст; в Bitbucket текст может уйти отдельным комментарием, покажи оба эффекта.
   Покажи полные тексты и цели. Если внешнюю запись не предлагаешь, дай итог без вопроса. Иначе предложи один точный результат для этого PR; согласие на него не спрашивай повторно, пока он не меняется. Согласие только на комментарий не покрывает статус. «Только черновик» — без вопроса и без отправки. Перед записью сверь HEAD и цели; при изменении повтори превью и согласуй изменённое. После записи перечитай PR, сверь тексты, якоря и статус; при неизвестном исходе не повторяй вызовы вслепую.
8. **Локально, по фактическому итогу** (не называй черновик отправленным) — `jwu_note("PROJ/repo#ID", "…", kind="status", pin=True)`: «ревью сделано,
   ждём правок по X» — чтобы day-analyze и следующая сессия знали.

## Текст от имени пользователя (голос)

Содержание текста, который уйдёт наружу от имени пользователя или отдаётся ему «для
копирования», пишешь **ты** (или субагент, который разбирался), а **форму** — агент голоса:

1. Напиши **технический черновик** — полный и точный ответ по существу: что сказать
   (сценарий → следствие → просьба; или что сделано), на что отвечаем, имена из кода,
   цифры, выводы. Стиль не важен, важно, чтобы по содержанию его можно было отправить.
2. `jwu_voice_profile()` → поле `agent` (дефолт `voice-writer-sample`, проектный задаётся
   `jwu voice agent <имя>`). Запусти его через Agent (`subagent_type` = `agent`) и передай
   `channel`, `audience`, `draft` (черновик), `context`, `limits`. Голос **только переписывает
   форму** под пользователя — длину, тон, обращения, привычные выражения, — факты, имена и
   выводы не трогает. Наружу ничего не шлёт.
3. Покажи пользователю текст целиком **в блоке кода** (```` ```text ````, чтобы копировался
   как есть; «что ушло при сжатии», если не пусто, — под ним обычным текстом) → правки →
   явное «да» → отправка этим скиллом.
4. «Не похоже на меня» — запусти агента ещё раз с `recheck` (прежний текст в `previous`,
   слова пользователя в `remark`): он сверит черновик с реальными текстами из корпуса и
   перепишет. Предложит правило для профиля — покажи его пользователю.
5. Обычную правку внеси в черновик, не спрашивая о настройках стиля. Если пользователь просит запомнить правило на будущее, покажи точную формулировку; запись в профиль — только по его согласию (`jwu_voice_feedback`).

Каналы: `pr_comment` (замечание на строку), `pr_reply` (ответ в тред автора), `pr_review_body`; аудитория `colleague`.

## Чего делать НЕ надо

- Отправлять комменты или ставить статус без явного подтверждения на КАЖДЫЙ вид действия.
- Апрувить «раз субагент ничего не нашёл» — решение об апруве принимает пользователь.
- Дублировать уже сделанные коллегами замечания — они в `comments[]`.
- Ревьюить свой PR этим скиллом — там jwu-job-review по локальному диффу.
- Писать автору то, что было в target-ветке до PR (`pre-existing`), и натянутые мелочи.
- Несколько PR подряд — это скилл **jwu-review-queue**.
