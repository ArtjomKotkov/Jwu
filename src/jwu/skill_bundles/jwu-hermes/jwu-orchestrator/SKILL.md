# jwu: оркестратор Hermes

Этот процесс рассчитан на нашу сборку Hermes. Различай роли **оркестратор** и **воркер**. Оркестратор запускает воркера и получает от него итог. Воркер выполняет поручение в своём чате. Оркестратор не загружает рабочие скиллы закрытия или ревью.

## Оркестратор: выбрать и передать

Оркестратор читает работы и брони Jwu, но не регистрирует роль, не берёт, не резервирует, не создаёт, не освобождает и не закрывает работу, не пишет в её журнал. Включение роли не запускает воркера. Создание чата и передача поручения — операции Desktop, не Jwu.

Сначала **jwu-session-init** в фактической папке проекта: сверь `source=cwd`, ожидаемые `cwd`/`slug` и правила. Папка поручения — абсолютный путь нужного репозитория; воркер сверяет привязку сам. Не считай cwd дочернего процесса или MCP наследуемым. Используй обнаруженные схемы MCP только при совпадении `jwu_workspace_current()` с CLI по папке, источнику и контуру. Иначе используй документированные операции `jwu --workspace <slug> …` с явно заданным `workdir` в shell; не подменяй защищённую запись непроверенной командой. Скиллы Jwu загружай точным путём `jwu-hermes/<имя>` в `skill_view`. Если нужный скилл не загружается из этого комплекта, назови блокер; не подменяй его копией другого клиента или старой категорией.

Запускай ровно столько воркеров, сколько попросил пользователь. «Одному» — один список по порядку; «каждую своему» — отдельные сессии. Независимые поручения можно передать параллельно, пересекающиеся — последовательно. Без явного поручения не запускай и не перезапускай воркеров.

На «покажи доску» покажи её через **jwu-todo**, на «обнови доску» — обнови и покажи. Технический снимок номеров — часть показа, не бронь и не отдельное решение. Номер сверяй только со снимком, который видел пользователь. Снимка нет — попроси точный ключ/полный PR или покажи новую доску для нового выбора. Не разрешай старый номер по новой доске. Для известного ключа вне доски не выдумывай раздел.

**Любое рабочее поручение воркеру ведётся через Jwu.** «Глянь», «посмотри», «разберись» определяют глубину разбора, а не способ учёта. «Без правок» не означает «без работы Jwu». Если пользователь явно попросил не вести работу в Jwu, не передавай поручение воркеру в обход этого правила: предложи разобрать вопрос в текущем чате.

Передай коротко: «Возьми <ключ задачи или полный PR> в работу через Jwu», затем цель, раздел доски (если пункт оттуда) и ограничения пользователя. «Глянь PROJ-123, отдай воркеру» → «Возьми PROJ-123 в работу через Jwu и кратко разберись, что случилось». Для ревью с ограничением: «Возьми P/r#42 в работу через Jwu из раздела review. Подготовь только черновик, не публикуй». Не отправляй голое «посмотри и сообщи». Не вкладывай план, тесты, ветку, секреты или согласие от имени пользователя. Если ключ, раздел выбранного пункта или число воркеров неясны, уточни, не угадывай. Ключ Jira, ID работы и ID чата — разные вещи. Не включай ID работы в обычный бриф. «Не продолжать №N» не значит «без Jira»: сохрани исходный ключ и исключение.

## Связанный чат и первый бриф

Воркер по умолчанию — **отдельный интерактивный чат Hermes в нужном проекте**, видимый в боковом меню. Явное поручение с понятным объёмом и числом воркеров не требует повторного согласия на запуск. `delegate_task` используй только по явной просьбе о фоновом подагенте: он не создаёт отдельный чат. Это не запрещает интерактивному воркеру использовать ограниченный поданализ, если его рабочий процесс это допускает. Не подменяй запуск фоновым подагентом, если проектный чат создать не удалось. Пустой чат — только по явной просьбе.

До создания проверь совместимость локального шлюза и Python payload по [инструкции](references/install.md#до-создания-чата). Пути к `scripts/run_with_gateway.sh`, `scripts/worker_launch.py` и `scripts/worker_relay.py` отсчитывай от `skill_dir` этого скилла. При неизвестной совместимости остановись. Из проверенного родительского чата (`HERMES_SESSION_ID`) запусти `scripts/run_with_gateway.sh scripts/worker_launch.py --create-only --title …` с уникальным заголовком. Это первый этап одного поручения, не пустой тестовый чат. По точному ID созданного чата сверь связь с оркестратором и `session.info`. Только после сверки проекта, папки и модели отправь короткий бриф в этот же чат: `scripts/run_with_gateway.sh scripts/worker_relay.py send --target ID --title TITLE --project PROJECT_ID --message-file FILE`. Не создавай второй чат для доставки. Если маршрут не подтверждён, сообщи причину без отправки. При неопределённом результате допустим только точный повтор того же брифа по тому же маршруту; не отправляй вручную.

Оркестратор сверяет по точному ID созданного чата проект, workdir и его фактические `model`/`provider` с запрошенными (иначе — с родительскими). При расхождении не отправляет бриф. Отдельно проверяет точный текст в транскрипте. `queued` не означает доставку; доставка не означает взятие. Сообщи ключ, ссылку и подтверждённое состояние: «Поручение доставлено, воркер ещё не подтвердил, что взял работу» либо «Воркер взял работу №…» только после сообщения воркера с проверенным `job_id`. Частичный сбой не повод создавать второй чат или брать пункт вместо воркера.

## Воркер: сверить, взять и вести работу

**Проверь первое поручение:** если бриф не говорит взять работу через Jwu, отправь вопрос оркестратору через `session_mailbox` и дождись уточнения. Не выполняй «посмотри и сообщи» в обход работы. Даже если просят только анализ, без подтверждённого `job_id` не приступай к разбору. Когда взял или продолжил работу, отправь её номер оркестратору через `session_mailbox` (`kind="text"`): это подтверждение взятия, а не итоговый `report`.

Пройди **jwu-session-init** в своей папке. Сначала проверь существующие работы и владельца. Для пункта с доски найди точный ключ в том же разделе, используя свой снимок, не номера оркестратора; атомарно возьми только свободный пункт по своему номеру и ключу, без `for_worker`, через **jwu-todo** / «Вход по поручению с доски» в **jwu-start-job**. Проверь `taken`/`skipped`, ключ, раздел и владельца работы. При чужой или неясной брони, исчезновении пункта или смене раздела сообщи причину. Не бери соседний пункт и не заводи работу вручную вместо пропущенной. Свою подходящую работу продолжай без дубля; вне доски ищи по ключу и цели и только при необходимости начинай по **jwu-start-job**. Не возобновляй паузу или закрытый цикл без проверки остатка и нужного решения.

Сам сверяй требования, последние комментарии, PR и прежний итог. Ревью веди по **jwu-review-queue**, красную сборку — по **jwu-build-failure**, остальные пункты — по их разделу **jwu-todo**. Для правок пройди «От анализа до первой правки» в **jwu-start-job**: согласуй и запиши план до исполнения. Для простого ревью план правок не нужен. Сверь исходный ключ перед коммитом, PR или 4TEST; противоречие уточни до публикации.

Решения по работе — в чате воркера, не через оркестратора. Если нужен новый выбор, сразу предложи ближайший безопасный шаг простым русским и вызови `clarify` в том же чате с непустым `questions` и `choices`. Если форма не появилась, проверь `outcome`, `notice` и `error`; если она недоступна, напиши «Жду твоего выбора», варианты по номерам и что останется без изменений. Не дублируй карточку у оркестратора и не пересылай «да» от имени пользователя. Уже согласованный шаг не требует нового вопроса; обязательные проверки и допуск Git сохраняются. После решения воркер сам продолжает очередь.

## Отчёт и архивирование

[Протокол передачи и закрытия](references/hermes-worker-handoff.md#отчёт-и-архивирование) — единственный маршрут. **Воркер** сам завершает поручение, закрывает связанные работы и прибирает их ресурсы, затем отправляет отчёт. Если работы/ресурсов не было, отметь это явно по каждому пункту. Если что-то осталось, отчитайся о блокере без запроса архива.

**Оркестратор** только читает отчёт связанного воркера: подтверждает его через `confirm_report`, лишь если явно указаны результат поручения, закрытие работ и уборка. Он не аудирует работу, Jira, код или файлы и не доделывает за воркера. Если отчёт неполон, спроси воркера, чего не хватает, и оставь чат открытым.

**Воркер** ждёт адресованного ему `report_confirmation` именно на свой отчёт, затем отдельным действием вызывает `request_archive`. **Оркестратор** архивирует только по связанному `archive_request` через `archive_worker`, не задаёт ещё один вопрос пользователю и не ждёт конца хода воркера. Успех проверь по `archived: true` и точному `session_id`, а если доступен поддерживаемый маршрут чтения — по `session.info` этого же чата. Ошибка или неопределённость — не подтверждённый архив. Письмо, ответ в чате и завершение хода не заменяют типизированные действия.
