# jwu: готовность к удалённой работе через Hermes

Сначала уточни цель: продолжить существующую сессию, получать уведомления или синхронизировать данные. Это независимые вещи. Для jwu проверь фактический `terminal(workdir=…)`, `jwu workspace current --json` (`source: cwd`, совпадают `slug` и `cwd`) и правила **jwu-session-init**; дальше `jwu --workspace <slug> …`. Это CLI-диагностика, не требует прикреплять MCP. Не считай наличие CLI или исходных скилов признаком регистрации в Hermes (`hermes mcp list`, затем сравни рабочую папку/контур живого MCP с CLI, если он есть).

1. **Диагностика, без запуска.** `jwu doctor --offline --json`, `jwu daemon status --json`, `jwu notify status --json`; сообщи состояние, не выводи chat ID, данные доступа или необработанные логи. При `fail` разбери причину, не исправляй автоматически. Сетевой `jwu doctor --json` — только по согласованной проверке доступов; его проверки MCP/скилов могут относиться к другому клиенту. Если вход в контур не подтверждён, не проверяй Telegram/память на запасном контуре.
2. **Продолжение сессии.** Загрузи `hermes-agent` → `references/remote-access.md` и проверь текущие [Desktop](https://hermes-agent.nousresearch.com/docs/user-guide/desktop) / [Sessions](https://hermes-agent.nousresearch.com/docs/user-guide/sessions). Для браузера — Hermes Desktop **Webapp**, не административный dashboard. `hermes webapp --status`, `hermes gateway status`, `hermes config get webapp.enabled`, `hermes config get webapp.host`; для Tailscale — `tailscale status --json`, `tailscale serve status` (сводка, без дампа топологии). Согласуй конкретный приватный маршрут: VPN (HTTPS внутри tailnet) или SSH-туннель; оставь прослушивание Webapp на loopback. **Никакого** прямого Internet, Funnel, публичной привязки/проброса порта, выключения аутентификации или обхода TLS. Заранее согласуй конкретные изменения (профиль, интерфейс, адрес, порт, auth и перезапуск). Вход должен быть настроен **до** проксирования; пароль задаёт пользователь локально в скрытом интерактивном `hermes dashboard password` или входит через поддерживаемого провайдера. Не проси и не передавай пароли, токены, одноразовые ссылки или ключи — ни в чате, ни аргументами, ни файлами/выводом. Не запускай Webapp, gateway, туннель или демон в ходе диагностики; подай точный план отдельной активации владельцем хоста. Не перезапускай активный gateway принудительно. После активации проверь статус, закрытость маршрута для неавторизованных и попроси владельца подтвердить вход и продолжение **той же** сессии со второго устройства; иначе «не проверено».
3. **Фоновый jwu.** По отдельному запросу предложи `jwu daemon install --interval <секунды>` (по умолчанию 600): системная служба пользователя, автозапуск и синхронизация, не способ доступа к Hermes. Сначала статус; не устанавливай второй экземпляр. Любая установка/изменение требует отдельного согласия на хост, интервал и эффект; после запуска владельцем перечитай статус.
4. **Telegram.** Уведомления jwu не являются управлением существующей сессией Hermes; чаты мессенджера Hermes тоже отдельны. Владелец настраивает доступы локально, Hermes не принимает секреты и не читает их хранилища. `jwu notify test --text <текст>` **отправляет** сообщение; требуется отдельное согласие на конкретный настроенный чат и текст. После отправки — подтверждение получения владельцем, не просто exit 0.
5. **Память и резервирование.** Не смешивай память jwu с Hermes. Только отдельно подтверждённый приватный Git-репозиторий памяти, не код проекта. `jwu memory sync --repo <путь>` запоминает путь, делает pull/импорт/экспорт/commit/push; `--no-push` не делает его read-only. До изменений согласуй каталог, проверенный приватный remote, данные и точные эффекты. Не используй URL с учётными данными; после согласованного синка проверь локальный и, если был push, удалённый ref. Не создавай и не открывай архивы с токенами. Если отдельно нужен бэкап, объясни ограничения `jwu backup --no-secrets --no-extras` (снимает секреты воркспейсов из копии БД, не гарантия безопасности всего архива); владелец проверяет и хранит его локально с ограниченным доступом.

Итог — отдельные статусы для Webapp, демона, уведомлений, памяти и MCP: проверено / ожидает действия владельца / не проверено. Ни одно не доказывает готовность остальных.
