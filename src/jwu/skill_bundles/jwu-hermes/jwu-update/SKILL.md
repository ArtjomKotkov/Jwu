# jwu: обновление CLI, MCP и скилов Hermes

Это три отдельных компонента. Пакет jwu содержит `jwu` и `jwu-mcp`; работающий MCP остаётся старым процессом. Проектная ссылка `.hermes/skills/jwu-hermes` ведёт на исходный комплект в проверенной рабочей копии; `pipx` её не меняет. В профиль этот же комплект ставит отдельная команда `jwu install --for jwu-hermes`. Хук политики Git не появляется от загрузки скилов.

1. **Проверки до записи.** Определи абсолютную папку исходников (отдельно от целевого проекта), `pwd -P`, корень Git и `git status --short`/`git rev-parse HEAD`. Для чтений по проекту: `jwu workspace current --json` с явным `terminal(workdir=…)` без `--workspace`; принимай только ожидаемый `source: cwd`, `slug` и `cwd`, потом **jwu-session-init** и явный `--workspace <slug>`. Для явной первой установки отсутствие CLI ожидаемо; не bootstrap'ь воркспейс заодно. Найди `command -v jwu`, `command -v jwu-mcp` и инвентарь `pipx list --json`; извлеки только путь, версию, режим/источник и имена аддонов, не печатай конфиги или URL с доступами. `jwu update --check --json` — сетевой запрос о релизе, **не** dry-run установки. Для локальной установки сравни подтверждённый checkout и реальную версию пакета. Не предполагай, что `jwu --version` существует или что `workspace current` CLI вернёт `jwu_version`.
2. **Покажи точный план.** Версия и проверенный источник (checkout + HEAD и состояние или конкретный тег), профиль/окружение pipx, editable или нет, аддоны, возможная миграция БД, резервная копия, службы и отдельные изменения Hermes. Для Hermes-only не запускай `jwu update --yes` по умолчанию: комплектный updater создаёт копию БД, переустанавливает пакет/аддоны, вызывает `jwu install` (по умолчанию Claude Code, не Hermes), при установленной службе может переустановить/перезапустить демон. `jwu install --skip-mcp` также не является установкой для Hermes. Если внешний клиент явно в области запроса, проверь точный план `core/update.py` установленной версии; одобри отдельно все его побочные действия, иначе не запускай. Не запускай `jwu update` без `--check` как пробный просмотр.
3. **Установка пакета — лишь после явного согласия на точный план.** Если pipx действительно управляет этим jwu: первая установка из проверенного корня — `pipx install .`, переустановка оттуда — `pipx install --force .` (добавляй `--editable` только если одобрено); для релиза согласуй точный доверенный spec с закреплённым тегом. Для иного менеджера не переезжай на pipx без согласия. Если надо резервирование, отдельно согласуй защищённый каталог и действие; не читай или не переноси архивы с секретами, резервирование с секретами оставь владельцу. `--no-secrets` не обещает очистку всего архива; не делай принудительный restore после ошибки. Перед запуском повторно проверь источник, окружение и отсутствие новых изменений; затем проверь версию в pipx, пути, help нужной команды и сохранность аддонов. Если аддоны исчезли, не переустанавливай их автоматически: согласуй точные источники и режим восстановления. При ошибке не повторяй force вслепую.
4. **MCP — отдельно.** Проверь `hermes mcp list` для нужного профиля. Если MCP отсутствует, продолжай через проверенный CLI; только на отдельный запрос и согласие зарегистрируй локальный stdio-процесс по [референсу Hermes](https://hermes-agent.nousresearch.com/docs/reference/cli-commands), `hermes mcp add <имя> --command <абсолютный-путь-к-jwu-mcp>`, затем перечитай список. После обновления открывай новый сеанс/переподключай по поддерживаемой процедуре текущего Hermes, не убивай процессы и не перезапускай gateway заодно. В новой сессии проверь реально доступные схемы (обычно `mcp_jwu_jwu_*`), `jwu_version()` и `jwu_workspace_current()`: `running`/`installed` не должны расходиться, `cwd`/`source`/`slug` должны совпадать с CLI. При отсутствии схемы, старом коде или неверной папке оставайся на CLI и сообщи, что не проверено. При 401 доступы обновляет пользователь локально; после его согласия можно сделать `jwu_auth_refresh(workspace=slug)` или `jwu --workspace <slug> auth check --json`, не выводя секреты.
5. **Скилы — отдельно.** Для явно одобренной установки скилов в нужный профиль выполни `jwu install --for jwu-hermes`; это только `$HERMES_HOME/skills/jwu-hermes`, без изменений MCP, хуков и частных скиллов. Для доверенного клона проверь ссылку `.hermes/skills/jwu-hermes` на `src/jwu/skill_bundles/jwu-hermes`; доверие через `hermes skills trust <путь>` — только по отдельному согласию. В свежем чате проверь точный путь `jwu-hermes/jwu-orchestrator` через `skill_view` и сравни `skill_dir` с ожидаемым источником. Старые категории не удаляй автоматически. Итог: версии CLI/MCP и отдельно состояние скилов.
