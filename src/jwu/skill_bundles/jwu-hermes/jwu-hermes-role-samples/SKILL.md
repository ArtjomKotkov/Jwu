# Штатные роли jwu в Hermes

Это переносимые инструкции, не отдельные модели или типы субагентов. Сначала выбери имя по правилам подтверждённого воркспейса и вызывающего скилла. Предпочти доверенную Hermes-адаптацию с точно таким именем, если она уже настроена. Если её нет, используй штатную инструкцию только при совпадении имени:

| Имя | `file_path` для `skill_view(name="jwu-hermes/jwu-hermes-role-samples", file_path=…)` |
| --- | --- |
| `reviewer-jwu-sample` | `references/reviewer-jwu-sample.md` |
| `review-filter-sample` | `references/review-filter-sample.md` |
| `voice-writer-sample` | `references/voice-writer-sample.md` |

Если комплект не загружается через `skill_view`, назови блокер, не подменяй его другим источником. Нет точной пользовательской роли — назови ограничение, не подменяй имя. Для голоса без подтверждённой роли можно вычитать текст в текущей сессии по уже прочитанному профилю, не заявляя отдельный проход.

Передай инструкции конкретной роли как `context` отдельного ограниченного `delegate_task` с проверенными входами и минимальным доступом. При недоступной делегации применяй их последовательно и назови проход самостоятельным. Ревьюер, фильтр и голос — разные проходы. Роли возвращают текст и не публикуют, не меняют Git, статусы, CI, профиль или журнал. Артефакт сохраняет вызывающий скилл по правилам своего процесса. Не передавай секреты; голос получает существующий профиль как вход, ему инструменты не нужны. Без профиля верни нейтральный технический черновик.

## Обнаружение в чистой установке

- В доверенном клоне используй `.hermes/skills/jwu-hermes`, вне него — комплект после `jwu install --for jwu-hermes`. Проверь точное имя `jwu-hermes/jwu-hermes-role-samples` и все три reference через `skill_view`.
