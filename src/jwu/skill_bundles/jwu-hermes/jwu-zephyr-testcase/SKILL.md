# jwu: тест-кейсы Zephyr Scale

Загрузи `skill_view(name="jwu-hermes/jwu-session-init")`; без проверенной привязки и правил пройди его. Требуй `source="cwd"`, непустой `slug` и совпадающий `cwd` из `jwu workspace current --json` с явным `terminal.workdir` проекта. Соблюдай ⛔ и правила тега. Ниже CLI-команды идут после `jwu --workspace <slug>` с тем же `workdir`. MCP необязателен: только если `jwu_workspace_current` подтверждает тот же `source`, `slug`, `cwd`; передавай `workspace=<slug>` в поддерживаемые вызовы. Если чтения не хватает, уточни через `clarify`, если доступен, иначе спроси в чате.

Только контур с Jira/Zephyr. Проект кейсов (`zephyr.project`) может отличаться от проекта связанной задачи. Удаления кейсов через jwu нет.

1. Чтение: `jwu_zephyr_context(issue_key, project=…)` → привязанные кейсы, папки-кандидаты, поля, агент и регламент. CLI: `zephyr for-issue KEY`, `zephyr fields [--project PROJECT]`, `zephyr folders [--project PROJECT]`; `zephyr case CASE_KEY`, `zephyr search TQL --limit N` или `jwu_zephyr_case(key)`, `jwu_zephyr_search(query, limit=…)`, `jwu_zephyr_folders(project=…)`. `case`, `for-issue`, `fields` и `search` уже отдают JSON без `--json`; `folders` выводит список. Если проект не настроен, прочитай `zephyr projects --json`, уточни проект, передавай явный проект там, где поддерживается. Отдельная локальная настройка — только по просьбе и после показа значений: `zephyr setup --project PROJECT [--agent AGENT]`.
2. Прочитай карточку (`jwu_task` / `task KEY --json`), журнал (`jwu_jobs(task=KEY)` / `jobs --task KEY --json`, при необходимости `jwu_job_handoff` / `job handoff JOB_ID --json`) и связанный PR. Подтяни регламент целиком `jwu_guide(name="zephyr-testcase-rules")` / `guide show zephyr-testcase-rules`. Если он требуется, но не прочитан, не публикуй. `zephyr rules FILE` — локально загрузить новый регламент, только по отдельной просьбе и после согласования точного текста, затем `guide show`.
3. Кейсы готовит тестировщик: выбранная в `agent` инструкция или `jwu-testing-agent` (в репозитории jwu: `src/jwu/agents/jwu-testing-agent.md`). Используй `read_file` для доступного шаблона; не переноси привязки инструментов из других клиентов. При доступных инструкциях и `delegate_task` передай их вместе с задачей, журналом, существующими кейсами, полями, папками и регламентом. Только черновик, без записей. CLI не выдаёт выбранного агента отдельным чтением; если его или инструкции нельзя выяснить, спроси. Если делегирование недоступно, не выдавай самостоятельный текст за работу тестировщика: представь непубликуемый черновик для проверки либо попроси готовые кейсы. Не дублируй кейсы, бери значения полей из проекта.
4. Покажи таблицу, допущения и **точный payload** каждой внешней записи: проект, папка, полные шаги (действие, тестовые данные, ожидаемое), все поля и связанные ключи. Для изменений — «было → стало». После свежего явного «да» на неизменный план — только эти записи. Если изменилась папка, состав или payload, требуется новое превью.
5. Запись после согласия (`user_approved=True` / `--yes`):
   - Папка: `jwu_zephyr_folder_create(path, project=…)` / `zephyr folder-create PATH --project PROJECT --yes`. Перечитай дерево и сверь путь, прежде чем писать кейсы.
   - Кейс: `jwu_zephyr_create(name, steps, objective=…, precondition=…, folder=…, status=…, priority=…, labels=…, issue_links=[KEY], custom_fields=…, project=…)` / `zephyr create FILE --yes`. CLI JSON принимает `project`, `name`, `steps`, `objective`, `precondition`, `folder`, `status`, `priority`, `labels`, `issueLinks`, `customFields`; у шага `description`, `testData` (если нужны) и `expectedResult`. `-` читает JSON из stdin.
   - Правка: `jwu_zephyr_update(key, …)` / `zephyr update CASE_KEY FILE --yes`; укажи только меняемые поля. `steps` заменяет набор шагов целиком.
   - Связь: `jwu_zephyr_link(key, issue_keys=[…])` / `zephyr link CASE_KEY KEY… --yes`; дополняет `issueLinks`, не заменяет. Для связей пользуйся этим вызовом, не затирай их через общий update.
6. Перечитай каждый кейс по точному ключу, проверь поля, шаги и `issueLinks`; если нужно, перечитай `for-issue`. Верни ключи и доступные ссылки. При частичном или неясном результате не повторяй запись вслепую.
