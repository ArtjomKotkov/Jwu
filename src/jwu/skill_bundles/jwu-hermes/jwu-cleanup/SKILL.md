# jwu: уборка за всеми сессиями

Подтверди папку проекта и привязку (`jwu workspace current --json`, `source: cwd`, ожидаемые `slug` и `cwd`), загрузи правила через **jwu-session-init**. Все CLI-вызовы ниже делай в явном `terminal(workdir=…)`, после проверки — с `jwu --workspace <slug> …`. Имена ниже — исходные MCP-имена; в Hermes используй обнаруженные схемы (обычно `mcp_jwu_jwu_*`). Если MCP не подтверждает ту же папку/контур или не прикреплён, используй CLI. **Sweep глобальный:** даже явный workspace не ограничивает уборку этим контуром. Если просили только один контур или отдельный объект, не применяй глобальные группы.

1. Сними план `jwu_sweep(apply=False, workspace=slug)` или `jwu sweep --json`; место — `jwu_disk(workspace=slug)` или `jwu disk --json` (код 3 означает низкий остаток). Покажи точные ресурсы, пути, работы и контуры по группам, отдельно весь `kept` и причины.

   | Группа | Что изменится |
   |---|---|
   | `closed_jobs` | Только отчёт: ресурсы закрытых работ, включая рабочие копии |
   | `orphan_docker` | Только Docker, опознанный jwu, без живой работы |
   | `orphan_worktrees` | Только отчёт: осиротевшие рабочие копии; это не список worktree Hermes |
   | `temp` | Старые каталоги скачанных вложений |
   | `dead_sessions` | Освобождение захваченных работ с переводом в паузу |
   | `dead_workers` | Удаление записей упавших воркеров jwu; открытые работы переходят в паузу |

2. Спроси в чате, какие **целые** группы применить к показанным объектам; по умолчанию ничего. Разрешённые для применения группы: `orphan_docker`, `temp`, `dead_sessions`, `dead_workers`. Никогда не добавляй `closed_jobs` или `orphan_worktrees` в `groups` / `--only`: sweep может удалить worktree без проверки git-политики для конкретной копии. Это правило действует даже при подтверждении группы и даже если в текущем плане не видно рабочих копий. Не удаляй ресурсы активных/приостановленных работ, не трогай живые процессы и чужой Docker. Для `dead_sessions`/`dead_workers` нужно явное согласие на паузу перечисленных работ. Не принимай отсутствие heartbeat за доказательство, что Hermes-сессия завершена; если владельца не удалось проверить, оставь группу.
3. Непосредственно перед применением сверяй новый план с одобренным; при изменениях показывай его снова. API не принимает снимок/ID плана и пересканирует при применении; если точность нельзя обеспечить (например, идёт параллельная работа), оставь только отчёт. Не передавай пустой `groups` и не опускай `--only`: это может выбрать всё. После явного согласия: `jwu_sweep(apply=True, groups=[…], force=False, user_approved=True, workspace=slug)` или `jwu sweep --only <группа,группа> --yes` (без `--json`: он только показывает).
4. `kept` оставляй. Не используй `force=True` / `--force`. Если нужна только часть группы, sweep для этого не подходит. Удаление одной рабочей копии — отдельная операция с проверкой git-политики и допуска именно для этой копии; не подменяй её ручным удалением или sweep. Не коммить и не пушь в рамках уборки.
5. Повтори план и замер; для паузы проверь точные ID работ. Сообщи фактически исчезнувшие объекты, оставшееся, ошибки и свободное место. При пустом плане ничего не запускай.
