# jwu: коммит-сообщение, без коммита

Если проект и правила не подтверждены, загрузи `skill_view(name="jwu-hermes/jwu-session-init")`. Используй `paths` подтверждённого контура (`jwu_workspace_paths(tag=…)` / `jwu --workspace SLUG workspace paths`), теговые правила и привязанную рабочую копию работы. Если правки в нескольких репозиториях и работа не определяет один — уточни. `terminal` всегда с явным `workdir` нужной подтверждённой папки; CLI jwu — с `--workspace SLUG`, MCP — только при сверенной привязке с `workspace=slug`. Динамические аргументы передавай argv или экранируй каждый отдельно.

**Перед текстом — фаза 4.** Проверь успешное `jwu-job-review` по актуальному локальному diff относительно целевой ветки. Если ревью не было, оно устарело или есть блокеры — не печатай сообщение, укажи, что нужно ревью. Формат из `convention` главнее канона ниже; `⛔` не обходи. Если пользователь сформулировал новое проектное правило, предложи точный текст, но запиши только после отдельного «да»: `jwu_rule_add(title, text, kind, tag, user_approved=True)` / `rule add TITLE --text TEXT --kind KIND [--tag TAG]`; прочитай его через `rules --json` (с тегом при наличии).

1. `git rev-parse --abbrev-ref HEAD`; префикс из начала ветки, строго `^[A-Z][A-Z0-9]+-[0-9]+`. Нет — без префикса и с предупреждением вне блока; для локальной работы с `feature_key` можно предложить этот ключ, не подставляй без согласия. Jira не нужна, локальные ключи работают по той же регулярке.
2. `git diff HEAD --stat`, `git diff HEAD`, `git status --short`: staged + unstaged и новые `??`. При необходимости безопасно прочитай относящиеся к задаче новые файлы: не раскрывай секреты, не угадывай изменения. Нет правок — сообщи, ничего не печатай. Не пропускай файлы из-за усечения вывода.
3. Язык по `git log -10 --pretty=%s`, если в правилах не задан иной. Заголовок одной строкой `<КЛЮЧ>: Краткое описание` либо без префикса, затем пустая строка и `- ` пункты по 10–15 слов, один пункт на изменение или группу. Только факты из diff/status. Никаких `Co-Authored-By` или упоминания ИИ.
4. Технический черновик → `skill_view(name="jwu-hermes/jwu-voice-rewrite")`, только для чтения профиля и прохода формы `channel=commit`, `audience=colleague`. Голос меняет тему и тело, не префикс и не факты. Покажи итог целиком в блоке `text`; правку примени к черновику. Если пользователь просит запомнить правило, покажи формулировку и спроси только о записи в профиль по скиллу голоса. Вывод текста и его правка не разрешают коммит.

Никакого `git add`, коммита, пуша или обхода политики. Фаза 5 — действие вызывающего потока по `jwu-start-job` с его подтверждениями и `jwu_git_commit`; после фактического прохождения фазы вызывающий поток пишет `job add ID 'Фаза 5 — коммит и пуш' --kind phase --status done`.
