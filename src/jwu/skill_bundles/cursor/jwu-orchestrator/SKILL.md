# jwu: оркестратор воркеров

Сначала **jwu-session-init** в фактической папке проекта: сверь `source=cwd`, ожидаемые `cwd`/`slug` и правила. Папка поручения — абсолютный путь нужного репозитория; воркер сверяет привязку сам. Не считай cwd дочернего процесса или MCP наследуемым. Используй обнаруженные схемы MCP только при совпадении `jwu_workspace_current()` с CLI по папке, источнику и контуру. Иначе используй документированные операции `jwu --workspace <slug> …` с явно заданным `workdir` в shell; не подменяй защищённую запись непроверенной командой.

## Оркестратор: выбрать и передать

Оркестратор раздаёт поручения, но не берёт, не резервирует, не создаёт и не закрывает работы за воркера и не пишет в их журналы. Воркер получает ключ, а не уже занятую за него работу.

Запускай ровно столько воркеров, сколько попросил пользователь. «Одному» — один список по порядку; «каждую своему» — отдельные сессии. Независимые поручения можно передать параллельно, пересекающиеся — последовательно. Без явного поручения не запускай и не перезапускай воркеров.

На «покажи доску» покажи её через **jwu-todo**, на «обнови доску» — обнови и покажи. Технический снимок номеров — часть показа, не бронь и не отдельное решение. Номер сверяй только со снимком, который видел пользователь. Снимка нет — попроси точный ключ/полный PR или покажи новую доску для нового выбора. Не разрешай старый номер по новой доске. Для известного ключа вне доски не выдумывай раздел.

Передай коротко: действие, точный ключ задачи или полный PR (`проект/репозиторий#номер`), раздел доски, если пункт оттуда, и ограничения пользователя дословно. Например: «Разбери P/r#42 из раздела review. Только черновик, не публикуй». Не вкладывай план, тесты, ветку, секреты или согласие от имени пользователя. Если ключ, раздел выбранного пункта или число воркеров неясны, уточни, не угадывай. Ключ Jira, ID работы и ID чата — разные вещи. Не включай ID работы в обычный бриф. «Не продолжать №N» не значит «без Jira»: сохрани исходный ключ и исключение.

## Воркер: сверить, взять и вести работу

Пройди **jwu-session-init** в своей папке. В собственной сессии доски найди точный ключ в том же разделе, используя свой снимок, не номера оркестратора. Для поручения «взять» сначала проверь существующие работы и владельца; затем атомарно возьми только свободный пункт по своему номеру и ключу, без `for_worker`, через **jwu-todo** / «Вход по поручению с доски» в **jwu-start-job**. Проверь `taken`/`skipped`, ключ, раздел и владельца работы. При чужой или неясной брони, исчезновении пункта или смене раздела сообщи причину. Не бери соседний пункт и не заводи работу вручную вместо пропущенной. Просьба только посмотреть или объяснить не требует взятия. Свою подходящую работу продолжай без дубля; вне доски ищи по ключу и цели и только при необходимости начинай по **jwu-start-job**. Не возобновляй паузу или закрытый цикл без проверки остатка и нужного решения.

Сам сверяй требования, последние комментарии, PR и прежний итог. Ревью веди по **jwu-review-queue**, красную сборку — по **jwu-build-failure**, остальные пункты — по их разделу **jwu-todo**. Для правок пройди «От анализа до первой правки» в **jwu-start-job**: согласуй и запиши план до исполнения. Для простого ревью план правок не нужен. Сверь исходный ключ перед коммитом, PR или 4TEST; противоречие уточни до публикации.

Решения о плане, публикации, статусе и закрытии принимает пользователь в сессии воркера. Скажи простым русским, что случилось и какой следующий шаг рекомендуешь; открой выбор через инструмент своего клиента, а если формы нет — перечисли варианты и дождись ответа. Не дублируй меню у оркестратора и не передавай согласие от имени пользователя. Сам продолжи очередь после решения; неизменное согласованное действие не переспрашивай. Обязательные проверки и допуск Git сохраняются.

## Запуск в Cursor

Используй отдельную интерактивную сессию Cursor с проверенной папкой, только если можешь создать и проверить её в текущем клиенте. Иначе дай точный короткий бриф для отдельного чата и назови ограничение. Встроенный подагент — не отдельный чат с пользователем; не передавай ему работу, требующую от пользователя решения в собственном чате. Решения принимай в сессии воркера по правилам выше.
