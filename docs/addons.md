# Аддоны

Аддон — отдельный Python-пакет, который подмешивает в jwu свои команды, MCP-инструменты,
скиллы, субагентов, кнопки и команды бота и периодическую работу демона. Так в jwu живёт то,
что нужно не всем: интеграции под конкретную работу, приватные инструменты команды.

## Установка

Аддон ставится в то же окружение, что и jwu:

```bash
pipx inject --force jwu -e ~/path/to/my-addons     # -e — правки в папке видны сразу
jwu install                                        # скиллы и субагенты аддона
jwu daemon install --interval 900                  # демон подхватит задачи и команды бота
```

В сессиях агента переподключи jwu (`/mcp`), чтобы появились инструменты аддона.

## Включить и выключить

```bash
jwu addons list                 # что установлено: версия, состояние, от чего зависит, что не так
jwu addons disable <имя>        # выключить, не удаляя: jwu перестанет его загружать
jwu addons enable <имя>
```

Выключенный аддон даже не импортируется: ни команд, ни инструментов, ни кнопок, ни задач демона.
Список выключенных лежит в `addons.json` рядом с конфигом jwu (`~/.config/jwu/`).

Состояния: **включён**, **выключен**, **сломан** (не импортировался — причина в `jwu addons
list` и `jwu doctor`), **не подключён** (нет аддона, который он требует).

## Зависимости

Аддон объявляет, без каких аддонов он не работает:

```python
REQUIRES = ["chat-source"]
```

Если нужного аддона нет, он выключен или сломан, зависящий не подключается — по цепочке.
`jwu addons disable` не даст выключить аддон, от которого зависят другие, без `--force`.

## Как написать

Точка входа — entry point в группе `jwu.addons`:

```toml
[project.entry-points."jwu.addons"]
my-addon = "my_package.my_addon"
```

Модуль может определить любые из хуков (все необязательны): `register_cli`, `register_mcp`,
`skills_dir`, `agents_dir`, `bot_text`, `bot_commands` + `bot_command`, `callback_prefixes` +
`bot_callback`, `menu_buttons` + `menu_action`, `status_lines`, `board_groups`, `config_sections`,
`secret_slots`, `facades`, `chat_sources`, `daemon_tasks`, `pr_autotests` + `pr_autotests_run`,
`after_hints`, `doctor`.
Сигнатуры и смысл — в начале `src/jwu/core/addons.py`.

## Настройки и секреты аддона

`config_sections() -> ["имя"]` — секция конфига аддона: значения из `config.toml` (`[имя]`) и
из настроек воркспейса (`имя.ключ`) приходят в `cfg.addons["имя"]`. `secret_slots() ->
{"имя.token": "ENV"}` — слот секрета: хранится в секретах воркспейса, читается
`config.get_slot(cfg, "имя.token")`, переменная окружения перебивает.

## Доска «что делать»

`board_groups()` — свои группы доски; встают первыми. Группа — словарь: `group`, `title`,
`items(store, workspace_id, login) -> [{key, title, problems, job_id}]`, `take(store, key,
session) -> job_id` (работа у пункта заводится, только когда его взяли), необязательные
`columns` и `hide_job(job)` (служебные работы аддона доска не предлагает закрыть).

## Автотесты PR

Откуда брать состояние автотестов PR (плагин хостинга, свой CI) — хук `pr_autotests(cfg, pr)
-> dict | None`: `state` (`not_started | queued | running | passed | failed | aborted | unknown`),
по желанию `queued_since`, `typical_ms`, `remaining_ms`, `build_number`, `url`, `reason`,
`finished_at`, `server_time` (ms). `None` — у этого PR источника нет. Ядро кладёт ответ в
`pr.autotests` при синке и показывает в `jwu pr`, `jwu builds`, на доске «что делать» и в
дневном анализе: в очереди или идут — «подождать», не запускали — «запустить».

`pr_autotests_run(cfg, pr, options) -> dict` — запуск (кнопка «Run autotests» и т.п.); его
вызывает `jwu_pr_autotests_run` только после «да» пользователя. Запросы к REST Bitbucket
контура — `addon_api.bitbucket_request(cfg, method, path)`, токен аддону не виден.

## Встроенные аддоны

Часть jwu подключается тем же механизмом и так же выключается:

- **telegram** — фасад бота: уведомления, меню, команды и кнопки идут в Telegram через него.
  `jwu addons disable telegram` — jwu перестаёт писать в Telegram и читать его.

## Фасад бота

Куда jwu пишет уведомления и откуда берёт команды — хук `facades() -> {"имя": фабрика(cfg)}`.
Отправщик говорит HTML-подмножеством Telegram и его inline-клавиатурами, входящие отдаёт в виде
update Bot API: `send`, `edit`, `delete`, `answer_callback`, `get_updates`, `set_commands`,
`get_me`, `close`; поля `chat_id`, `token`, `role`, `offset_meta`. Логика бота (что показать,
команды, меню) — в ядре и от фасада не зависит.

## Источники чатов

Адаптер мессенджера — хук `chat_sources() -> {"имя": фабрика(cfg)}`. Фабрика по конфигу
воркспейса отдаёт источник или `None` (не настроен). Источник реализует `ChatSource` из
`jwu.core.chats`: кто я, комнаты с именами, «что нового» с позиции (`news(cursor)` — сообщения
по комнатам, непрочитанное, личные диалоги), одно сообщение по id. Только чтение: писать в чаты
jwu не умеет. Потребители (слежение за комнатами, упоминания) берут источник по имени и не знают, какой
это мессенджер. Аддон с тем же именем перекрывает встроенный адаптер.

Опираться можно только на `jwu.addon_api` (store для CLI и MCP, контуры с ботом, отправка с
учётом тихих часов, лог демона, запросы к Bitbucket контура). Остальное в `jwu.*` — внутреннее и меняется без предупреждения.

Ошибка в аддоне не роняет jwu: сломавшийся хук помечается, причина видна в `jwu doctor`.
