# История ревью по PR

Каждый круг ревью раньше начинался с нуля. Из-за этого отклонённое поднималось снова, а фикс
прошлого замечания ломал соседний сценарий, и ревьюер об этом не знал. jwu копит находки
всех кругов и всех ревьюеров по PR, их судьбу и отдаёт новому кругу короткую выжимку.

## Источники

- **`local`** — наше ревью. Записи `kind=review` в работах по PR (шапка скилла
  `jwu-job-review`: «Ревьюер: …; PR #N; итерация k; вердикт …» и замечания `[B1] [I1] [M1]`)
  попадают в историю сами. Работа без привязки к PR своих кругов не отдаст: jwu привязывает её
  сам при `jwu_pr_create(from_job=…)` и в синке по ветке, вручную — `jwu_job_link`. Ревью чужих PR (`jwu-review-queue`) записывается после отправки.
- **`external`** — всё внешнее: треды PR на строку кода или с задачами (подпись — автор),
  ревью в CI и другие круги, добавленные через `jwu_review_add`.

Подпись круга (`label`) — свободная: имя агента, логин, «ревью в CI #898». Она нужна только
для показа.

## Как сводятся круги

Одна и та же проблема в разных кругах — одна цепочка. jwu сопоставляет находку с прошлыми
по словам, именам из кода и файлу: у того же ревьюера в соседнем круге хватает половины общих
слов (даже если он назвал другой файл), у разных ревьюеров при разных файлах — почти всех. Ошибся — поправь: `jwu_review_fate([F], "duplicate", same_as=F0)`.

Состояние проблемы:

| состояние | откуда |
|---|---|
| отклонено · вне PR · не подтвердилось | судьба с доводом (`rejected`, `out_of_pr`, `fabricated`) |
| исправлено | `fixed` (с коммитом); тред PR со всеми закрытыми задачами — тоже |
| исправлено, но подняли снова | после `fixed` она снова появилась в круге — проверить регрессию |
| открыто | судьбы нет, и в последнем круге своего ревьюера она есть |
| ушло по ходу кругов | судьбы нет, а ревьюер, который каждый круг смотрит весь PR, в следующем круге её не поднял |

Треды людей «уйти» сами не могут: человек не пересматривает PR целиком каждый круг.

## Внешнее ревью из комментов

Ревью, которое бот оставляет комментом в PR, разбирает аддон (хук `pr_review_rounds`, см.
[addons.md](addons.md)): каждый прогон — круг `external` со своими находками, уровнем и местом.
В синке это происходит само у моих PR, когда сменился head или статус сборки ревью.

## Сравнение и пропуски

- **Последний внешний круг против прошлого** того же ревьюера: новое · повтор · повтор
  отклонённого · исчезло. Строкой в выжимке; коротко — поле `review` у `jwu_builds`,
  `review_history` у `jwu_pr` и «повтор отклонённого: N» на доске «что делать».
- **Наше против внешнего на том же коде**: совпало · только local · только external (отклонённое
  отдельно). Наши круги берутся на том же коммите, а если коммиты не записаны — последние до
  внешнего круга. Коммит к записи ревью прикладывается, когда `jwu_job_add` зовут с `cwd`
  рабочей копии.
- **По каждому внешнему кругу** — `jwu review compare N [--local ревьюер]`: та же сверка для
  всех внешних кругов PR (замена ручных сверок «наше против внешнего»).
- **Пропуски нашего ревью** по всем PR за период — `jwu_review_misses(days)` /
  `jwu review misses --days 30`: что нашёл внешний ревьюер, а наш на том же коде нет, по
  категориям (документация, длина строк, нейминг, права и окружение, конкурентность …) с
  примерами. Это материал для правки описания агента-ревьюера; правит пользователь. Верхние
  категории — строкой в выжимке.

## Выжимка

`jwu_pr_review_history(pr)` · `jwu review history N [--json] [--offline]` · `jwu.pr_review_history(...)`
в `jwu_query`. Блоки: отклонено и почему (не поднимать без нового довода), было исправлено, но
подняли снова, открыто, исправлено на прошлых кругах (не сломано ли), ушло по ходу кругов.
Размер ограничен (`max_chars`, по умолчанию 5000): мелкое в «исправлено» и «ушло» — счётчиком,
не влезшее — «ещё N».

Ревьюер получает выжимку **после** своего независимого прохода, иначе он заякорится на
старом и перестанет искать новое.

## Судьба находки

`jwu_review_fate(["F12"], fate, reason, commit, ref)` · `jwu review fate F12 --fate rejected --reason …`.
`fixed` — с коммитом фикса. `rejected` / `out_of_pr` / `fabricated` — только с доводом: по нему
следующий круг не поднимет замечание снова. Скилл `jwu-pr-comment` ставит судьбу, когда
отвечает в тред.

Всё хранится локально (`state.db`); наружу ничего не пишется.
