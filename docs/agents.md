# Скиллы, субагенты и MCP

Ставятся командой `jwu install` (Claude Code) или `jwu install --for cursor|codex`; срабатывают по
фразам («разбери мой день», «ответь в PR») или слэш-командой. Как идёт работа над задачей
целиком — [Работа над задачей](workflow.md).

## Скиллы

| Скилл | Когда |
|---|---|
| `/jwu-session-init` | первый шаг сессии: воркспейс, правила, активные работы и фичи |
| `/jwu-workspace-setup`, `/jwu-setup-remote`, `/jwu-update` | подключить проект; настроить демон, Telegram и память; обновить jwu |
| `/jwu-context` | «что я знаю по задаче / почему висит PR» — контекст без разбора работ |
| `/jwu-todo` | что делать: конфликты и сборки, правки ревью/QA, несделанные задачи, чужие PR на ревью; взять номера или группу в эту сессию — для нескольких параллельных сессий |
| `/jwu-start-job`, `/jwu-continue-job`, `/jwu-close-job` | начать работу с планом; после «да» на план фазы и ревью идут сами (ревьювер из настроек, до 3 кругов), в конце сразу три текста твоим голосом (коммит, 4test, PR) и один вопрос меню, что публиковать, затем закрытие с уборкой; продолжить или переоткрыть; закрыть |
| `/jwu-queue [add …\|list\|next\|clear\|slots N]` | очередь задач сессии: новые просьбы из чата встают в конец, выполняются подряд в основном потоке или субагентами по слотам |
| `/jwu-job-review <reviewer>` | ревью своих локальных правок до коммита |
| `/jwu-review-pr <id>` | ревью чужого PR: дифф через jwu, замечания и статус после «да» |
| `/jwu-review-queue [light\|full] [N]` | очередь ревью: ревьюеры пулом, фильтр замечаний, черновики, сводка; отправка по одному PR |
| `/jwu-pr-comment`, `/jwu-pr-task` | ответить в PR, поправить коммент или PR, статус; задачи на комментах |
| `/jwu-qa-triage <KEY>` | задачу вернули с тестов: вердикт по коду и черновик ответа |
| `/jwu-build-failure` | почему упал билд PR (Jenkins / Actions) |
| `/jwu-task-create`, `/jwu-task-comment`, `/jwu-task-status`, `/jwu-task-attach`, `/jwu-task-branches` | задачи Jira: создать и править, комменты, статус, вложения; куда доехал фикс |
| `/jwu-track-time` | трекинг времени цепочкой (итоги дня без записи — «покажи, что затрекал бы»); после — ссылки на ворклоги |
| `/jwu-4test-message`, `/jwu-commit-message`, `/jwu-prompt-refine` | инструкция QA; коммит-месседж; промпт для другой сессии |
| `/jwu-duty` | дежурство: обращения поддержки из мессенджера |
| `/jwu-confluence` | читать, создавать и править страницы Confluence |
| `/jwu-cleanup` | уборка за всеми сессиями: стенды и копии закрытых и пропавших работ, docker без работы, старые вложения, замолчавшие сессии; открытое и несохранённое не трогает |
| `/jwu-orchestrator` | оркестратор: по твоей команде поднимает воркеров — отдельные сессии под задачи, пишет им задания по виду работы, показывает их состояние в строке статуса |
| `/jwu-zephyr-testcase` | тест-кейсы Zephyr Scale по задаче: агент пишет, превью, запись после «да» |
| `/jwu-voice-profile`, `/jwu-voice-rewrite` | собрать профиль голоса; переписать текст «как я пишу» |

## Субагенты

Из поставки — безличные образцы; проектные агенты в `~/.claude/agents/` (или
`~/.cursor/agents/`, `~/.codex/agents/` — там TOML) главнее; `jwu backup` сохраняет агентов Claude Code.

| Агент | Что делает |
|---|---|
| `reviewer-jwu-sample` | ревью по чек-листу |
| `review-filter-sample` | второй проход по замечаниям: только то, что внёс PR, без натянутого |
| `jenkins-build-analyst` | разбор падения сборки |
| `qa-triage-sample` | возвраты с тестов |
| `duty-support-sample` | обращения поддержки |
| `voice-writer-sample` | переписывает технический черновик внешнего текста под пользователя (форма, не содержание), сам ничего не отправляет |
| `jwu-testing-agent` | пишет тест-кейсы Zephyr по задаче и регламенту; свой — `jwu zephyr setup --agent NAME` |

## Голос: тексты от твоего имени

Любой внешний текст — коммент или ответ в PR, коммент в Jira, ответ клиенту, текст задачи,
4test — делается в два шага. Содержание пишет тот, кто разбирался (скилл или субагент:
разбор дежурства, фильтр ревью, триаж QA), — технический черновик, полный и точный. Потом
**агент голоса** переписывает только форму: длину, официальность, обращения, привычные
тебе выражения; факты, имена и выводы не трогает, а что ушло при сжатии — показывает.
Результат — тебе в блоке кода, отправка только после «да».

```bash
jwu voice collect [--reset]    # корпус: твои комменты, описания PR, комменты в Jira, коммиты
jwu voice show                 # агент, профиль, корпус, анализ
jwu voice examples pr_reply    # что агент увидит как примеры для канала
jwu voice agent <имя>          # свой агент голоса для воркспейса («-» — дефолт)
```

- Персональное — только локально, в `~/.local/share/jwu/voice/<воркспейс>/`: `profile.md`
  (правила, регистры, примеры; правь руками) и `corpus.jsonl`. В репозиторий и синк памяти не уходит.
- `/jwu-voice-profile` один раз разбирает корпус и сохраняет в профиль правила по каналам;
  дальше агент пишет по профилю, а примеры смотрит, только если ты говоришь «не похоже на меня».
- Правишь черновик — скилл предложит записать правку «было → стало» в профиль.
- Коммиты, написанные ассистентом, и переписка с ним в корпус не попадают.

## MCP

MCP-инструменты повторяют CLI: `jwu_task`, `jwu_pr`, `jwu_pr_diff`, `jwu_context`,
`jwu_branches`, `jwu_day_context`, `jwu_job_handoff`, `jwu_review_queue`, `jwu_voice_*`,
`jwu_confluence_*`, … Пишущие наружу (`jwu_comment*`, `jwu_issue_*`, `jwu_worklog*`,
`jwu_pr_comment*`, `jwu_pr_review`, `jwu_pr_create`, `jwu_pr_update`, `jwu_pr_task_*`,
`jwu_confluence_create|update`) скиллы зовут только после явного подтверждения.

Git — только через jwu, под [политикой git](git.md): чтение `jwu_git_status|diff|log`,
запись `jwu_git_commit|switch|sync|stash|discard|history|push|branch_delete|tag`,
`jwu_job_push`, уборка копий `jwu_git_worktree_remove`, откат `jwu_git_undo`, что можно —
`jwu_git_policy`. Отказ политики — ответ `{blocked, ask_user, retry}`, а не ошибка. Голый
пишущий git из Bash режет хук `jwu-git-guard` (ставит `jwu install`); менять политику и
выдавать допуски агент не может.


## Несколько сессий: доска `/jwu-todo`

Каждая сессия Claude Code (в том числе через remote-control) набирает `/jwu-todo` и видит одну
доску таблицами, собранную jwu из кеша:

| группа | что в ней |
|---|---|
| 🔧 Конфликты и сборки | мой PR с конфликтом или красной сборкой, без замечаний людей |
| ✍️ Правки по ревью и QA | needs work, открытые задачи PR, возврат с QA (конфликт и сборка — тоже тут) |
| 📋 Несделанные задачи | на мне, не начата или в работе, без открытого PR; в работе выше, дальше по приоритету |
| 👀 Ждут моего ревью | чужие PR |
| 📣 Ответить · ➡️ Двигать дальше · 🧹 Закрыть работу | упоминания с вопросом ко мне; PR с собранными апрувами — перевести задачу; работа открыта, а задача закрыта или ушла |

- «делай 1 и 3», «бери все конфликты и падения», «бери правки, пока есть» — сессия заводит
  работы и делает их по одной; взятое другой сессией пропускается (взятие атомарное).
- У сессии имя вроде «Shiny-Gold» — jwu придумывает его сам. Сессии раз в минуту
  отмечаются: в шапке доски 🟢 живые и 💤 молчащие; «освободи <имя>» возвращает задачи
  молчащей сессии.
- Данные старше 30 минут доска обновляет сама — тихим синком через демон (уведомления уйдут
  со следующим обычным синком); «обнови» — обновить сейчас.
- После взятия несделанных задач сессия одним вопросом предложит перевести их в In Progress.
