# Скиллы, субагенты и MCP

Ставятся командой `jwu install` (Claude Code) или `jwu install --for cursor`; срабатывают по
фразам («разбери мой день», «ответь в PR») или слэш-командой.

## Скиллы

| Скилл | Когда |
|---|---|
| `/jwu-session-init` | первый шаг сессии: воркспейс, правила, активные работы и фичи |
| `/jwu-workspace-setup`, `/jwu-setup-remote`, `/jwu-update` | подключить проект; настроить демон, Telegram и память; обновить jwu |
| `/jwu-context` | «что я знаю по задаче / почему висит PR» — контекст без разбора работ |
| `/jwu-start-job`, `/jwu-track-job`, `/jwu-resume-job`, `/jwu-wrap-up` | начать работу с планом; вести журнал; подхватить после потери контекста; закруглить сессию |
| `/jwu-job-review <reviewer>` | ревью своих локальных правок до коммита |
| `/jwu-review-pr <id>` | ревью чужого PR: дифф через jwu, замечания и статус после «да» |
| `/jwu-review-queue [light\|full] [N]` | очередь ревью: ревьюеры пулом, фильтр замечаний, черновики, сводка; отправка по одному PR |
| `/jwu-pr-comment`, `/jwu-pr-task` | ответить в PR, поправить коммент или PR, статус; задачи на комментах |
| `/jwu-qa-triage <KEY>` | задачу вернули с тестов: вердикт по коду и черновик ответа |
| `/build-failure` | почему упал билд PR (Jenkins / Actions) |
| `/jwu-task-create`, `/jwu-task-comment`, `/jwu-task-status`, `/jwu-task-attach`, `/jwu-task-branches` | задачи Jira: создать и править, комменты, статус, вложения; куда доехал фикс |
| `/jwu-analyze-day`, `/jwu-post-analyze-day`, `/jwu-track-time` | план на день; итоги дня; трекинг времени цепочкой |
| `/jwu-4test-message`, `/jwu-commit-message`, `/jwu-prompt-refine` | инструкция QA; коммит-месседж; промпт для другой сессии |
| `/duty-support` | дежурство: обращения поддержки из мессенджера |
| `/jwu-confluence` | читать, создавать и править страницы Confluence |
| `/jwu-voice-profile`, `/jwu-voice-rewrite` | собрать профиль голоса; переписать текст «как я пишу» |

## Субагенты

Из поставки — безличные образцы; проектные агенты в `~/.claude/agents/` (или
`~/.cursor/agents/`) главнее, `jwu backup` их сохраняет.

| Агент | Что делает |
|---|---|
| `reviewer-jwu-sample` | ревью по чек-листу |
| `review-filter-sample` | второй проход по замечаниям: только то, что внёс PR, без натянутого |
| `jenkins-build-analyst` | разбор падения сборки |
| `qa-triage-sample` | возвраты с тестов |
| `duty-support-sample` | обращения поддержки |
| `voice-writer-sample` | пишет внешние тексты голосом пользователя, сам ничего не отправляет |

## Голос: тексты от твоего имени

Любой внешний текст — коммент или ответ в PR, коммент в Jira, ответ клиенту, текст задачи,
4test, коммит — скиллы не сочиняют сами: собирают факты, отдают **агенту голоса**,
показывают результат и отправляют только после «да».

```bash
jwu voice collect [--reset]    # корпус: твои комменты, описания PR, комменты в Jira, коммиты
jwu voice show                 # агент, профиль, корпус, анализ
jwu voice examples pr_reply    # что агент увидит как примеры для канала
jwu voice agent <имя>          # свой агент голоса для воркспейса («-» — дефолт)
```

- Персональное — только локально, в `~/.local/share/jwu/voice/<воркспейс>/`: `profile.md`
  (правила, регистры, примеры; правь руками) и `corpus.jsonl`. В репозиторий и синк памяти не уходит.
- `/jwu-voice-profile` один раз разбирает корпус и сохраняет в профиль правила по каналам;
  дальше агент пишет по профилю, а примеры смотрит, только если ты говоришь «не похоже на меня».
- Правишь черновик — скилл предложит записать правку «было → стало» в профиль.
- Коммиты, написанные ассистентом, и переписка с ним в корпус не попадают.

## MCP

MCP-инструменты повторяют CLI: `jwu_task`, `jwu_pr`, `jwu_pr_diff`, `jwu_context`,
`jwu_branches`, `jwu_day_context`, `jwu_job_handoff`, `jwu_review_queue`, `jwu_voice_*`,
`jwu_confluence_*`, … Пишущие наружу (`jwu_comment*`, `jwu_issue_*`, `jwu_worklog*`,
`jwu_pr_comment*`, `jwu_pr_review`, `jwu_pr_create`, `jwu_pr_update`, `jwu_pr_task_*`,
`jwu_confluence_create|update`) скиллы зовут только после явного подтверждения.
