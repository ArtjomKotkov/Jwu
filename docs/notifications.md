# Синк, демон и уведомления

## Синк и дельты

`jwu sync` тянет мои задачи, упоминания и PR (с конфликтами, сборками и задачами на
комментах), кладёт снапшот и считает **дельты** — что изменилось с прошлого раза:
`new_comment`, `status_change`, `returned_from_testing`, `qa_comment`, `new_pr`,
`new_pr_comment`, `new_pr_commit`, `reviewer_approved`, `reviewer_needs_work`, `new_conflict`,
`build_failed`/`build_fixed`, `new_pr_task`/`pr_task_resolved`, `pr_all_approved`,
`pr_ready_to_merge`, `gone`/`pr_gone`. Дельты копятся до `jwu changes --clear`.

## Демон

Делает синк регулярным без открытого дашборда:

```bash
jwu daemon run --once               # один проход руками
jwu daemon install --interval 600   # службой: launchd (macOS) / systemd --user (Linux)
jwu daemon kick                     # внеплановый проход прямо сейчас
jwu daemon status · jwu daemon uninstall
```

Один процесс на машину. Раз в `--interval` секунд (от конца прошлого прохода) обходит все
контуры с Jira или GitHub: синк → уведомления → ответы боту. Ошибка одного контура пишется в
лог (`~/.local/share/jwu/daemon.log`) и не мешает остальным. Служба стартует при входе и
перезапускается сама; итог последнего прохода — в `jwu daemon status` и `jwu doctor`.

## Telegram

После **каждого** сетевого синка важные события уходят одним сообщением, ключи — ссылками
на задачу и PR. Если нового нет — бот молчит.

Что приходит — все события синка, кроме «готов к мержу»:

- проблемы: конфликт, красная сборка, needs work, новая задача в PR;
- задачи: новые, смена статуса, вернули с тестов, комментарии (и QA), решена, ушла из выборки;
- PR: **новый PR на ревью**, комментарии, коммиты, апрувы, все апрувы собраны, сборка
  позеленела, задача в PR закрыта, PR пропал (смержен / отклонён), упоминания.

Сообщение делится на два блока: **МОЁ** (я исполнитель, мой PR или задача моего PR) и
**УЧАСТВУЮ** (автор задачи, ревьюер, наблюдаю, упомянули). Под ключом — роль и на ком
задача (`👁 наблюдаю · исп. Иванов`); у смены статуса — ещё и кто перевёл
(`👤 исполнитель · перевёл Мария · на мне`).

Внизу чата одна кнопка «📋 Меню»: по ней приходит меню кнопками (🗂 Что делать, синк,
статус, мои задачи, что застряло, что сделал сегодня, упоминания, Matrix, уведомления);
переходы — в том же сообщении. На любое нажатие бот отвечает сразу («⏳ принято»),
ошибка приходит текстом — молчание значит, что демон не работает.

**🗂 Что делать** — доска «что делать» по группам, по запросу.

Бот двусторонний: между проходами демон держит long polling (`--poll-interval`, 25 с), на
команды реагирует сразу.

| Команда | Что делает |
|---|---|
| `/sync` | проход сейчас; по окончании — итог по каждому контуру («нового нет» / «есть новое» / ошибка) |
| `/status` | когда был последний проход и что накопилось |
| `/stuck` | что застряло по порогам |
| `/tasks` | сводка моих задач по статусам из последнего синка, число моих PR и PR на ревью |
| `/mentions`, `/seen` | непрочитанные упоминания; пометить прочитанными |
| `/duty` | дежурство за комнатой Matrix: вкл / выкл |
| `/personal` | личное: непрочитанное из диалогов 1:1 и упоминания в чатах, вкл / выкл |
| `/matrix` | настройка Matrix кнопками: оба тумблера, комната дежурства |

Ответ на уведомление становится заметкой-контекстом по ключу из него, `ACME-1 текст` —
заметкой по `ACME-1`. Чужие чаты игнорируются.

```bash
jwu configure --non-interactive --telegram-chat <chat_id> --telegram-token "$TELEGRAM_BOT_TOKEN"
jwu notify status · jwu notify test · jwu notify poll
```

### Резервный бот

У Telegram бывают сбои отдельного бота: запросы к нему висят или получают 502, а другие боты
работают. На этот случай — второй бот:

```bash
jwu configure --telegram-backup-token <токен второго бота от @BotFather>
```

Резервному боту один раз напиши `/start` (иначе он не может писать первым); `chat_id` тот же.

- Основной не ответил (нет связи, таймаут, 5xx) — сообщение уходит через резервный; основной
  считается лежащим 5 минут, потом jwu пробует его снова.
- Демон опрашивает оба бота отдельно: кнопки и команды работают и в резервном, отвечает тот бот,
  в котором нажали.
- Меню резервного бота помечено «🛟 резервный бот» и начинается с кнопки «🩺 Проверить основной
  бот»: ожил — уведомления сразу возвращаются в него.
- `jwu doctor` проверяет оба бота.

## Что присылать и когда не беспокоить

В боте: «📋 Меню» → «🔔 Уведомления». На первом экране — **общие** тихие часы (для всех
воркспейсов) и список воркспейсов с кратким итогом; в терминале — `jwu notify settings`.

**Что присылать — по воркспейсу.** Группа открывается кнопкой, внутри — каждое событие
отдельно (✅ / 🔕) и «выключить всю группу».

| группа | события |
|---|---|
| 🔧 Сборки и конфликты (`builds`) | конфликт, сборка упала, сборка позеленела |
| ✍️ Мои PR (`my_prs`) | needs work, апрув, все апрувы, задача в PR и её закрытие, комменты и коммиты в PR |
| 👀 PR на ревью мне (`review`) | новый PR на ревью |
| 📋 Задачи (`tasks`) | новая, статус, комментарий, решена, новый PR по задаче, ушла из моих |
| 🧪 QA (`qa`) | вернули с тестов, комментарий QA |
| 📣 Упоминания (`mentions`) | упоминания в Jira и PR |
| 👥 «Участвую» (`participate`) | всё по чужим задачам и PR, где я участник |

**Не беспокоить** — сколько угодно диапазонов и дни целиком, по местному времени компьютера (пояс ворклогов воркспейса на них не влияет).
Кнопками — готовые варианты («с 22 до 08», «обед 13–14»), «✏️ Ввести свои» — бот попросит
прислать текстом, например `10-16, 22-08` или `22:30-07:45`. Общие часы действуют везде, где
воркспейс не задал свои; у воркспейса можно «как в общих», свои или «выключить».

Всё, что пришлось на тишину, — синк, дежурство, личное, место на диске —
копится и приходит одним тихим сообщением «🌙 Пока было тихо», когда тишина кончилась.
Тишину пробивают только запросы допуска git и ответы бота на твои команды.

```bash
jwu notify settings                                   # что включено, тихие часы, сколько отложено
jwu notify settings --off participate --off tasks     # выключить группы (--on — вернуть)
jwu notify settings --kind-off new_pr_commit          # одно событие (--kind-on — вернуть)
jwu notify settings --global --quiet "22-08" --quiet-days sat,sun   # общие тихие часы
jwu notify settings --quiet "10-16, 22-08"            # свои у этого воркспейса; --inherit — как в общих
```

## Matrix: дежурство и личное

Две независимые слежки, обе приходят в Telegram:

- **Дежурство** (`/duty`) — одна комната целиком: все новые чужие сообщения.
- **Личное** (`/personal`) — без всякого дежурства: непрочитанное из диалогов один на один и
  упоминания меня в остальных чатах. Прочитал в Element до проверки — не придёт. Личка в Element
  обычно зашифрована (E2E): текста jwu не видит и пишет, кто и сколько — «🔒 2 новых сообщения —
  открой Element»; ключей шифрования jwu не хранит.

Настройка — `/matrix`, вся кнопками: оба тумблера и выбор комнаты дежурства. Комнаты идут по
страницам, личные диалоги в выбор не попадают. Список берётся из кеша, заново — только
кнопкой «🔄 обновить список». Первый выбор комнаты сразу включает дежурство.

Демон проверяет вместе с опросом бота, раз в ~25 с, одним запросом `/sync` на обе слежки.
Новое подряд не плодит сообщений: если последнее в чате — уведомление дежурства не старше
15 минут, бот дописывает в него (подряд от того же человека в том же треде — без повторной
шапки). Правка сообщения в Telegram не звенит — звенит только первое.

```
🟢 дежурство · support-room
👤 Иван Петров  🧵 в треде «Не грузится виджет на сайте…»  ↩️ мой тред
   посмотрел логи, там 502 от…

💬 личные
👤 Ольга
   привет, глянь PR

📣 упоминание · Релизы
👤 Пётр
   Саша, релиз сегодня?
```

Метки в дежурстве: `ответ мне`, `мой тред` (тред начал я), `упоминание`. Свои сообщения
пропускаются. Позиция сдвигается только после отправки: лёг Telegram — сообщения придут
позже, а не пропадут. Matrix только читается, писать в него клиент jwu не умеет.

Доступ: конфиг matrix-mcp на этой машине подхватывается сам. Свой —
`jwu configure --non-interactive --matrix-host … --matrix-token …` (или `JWU_MATRIX_URL`,
`MATRIX_TOKEN`). Из терминала:

```bash
jwu duty                             # что включено
jwu duty rooms [--all] [--refresh]   # комнаты из кеша; --refresh — перечитать
jwu duty room <номер|id|название>    # комната дежурства
jwu duty on · jwu duty off           # дежурство
jwu duty personal on|off             # личное
jwu duty check                       # новое прямо сейчас (в Telegram не шлёт)
```

Скилл `/jwu-setup-remote` проводит через doctor → daemon → Telegram → синк памяти.
