# Code Mode: jwu_query

Когда агенту нужно несколько чтений подряд или выжимка из большого ответа, он не зовёт
инструменты по одному, а пишет короткий Python-скрипт против API jwu. Скрипт выполняется в
песочнице, в контекст агента приходит только итог. Идея — Code Mode Cloudflare и «Code execution
with MCP» Anthropic.

```python
rows = []
for p in jwu.prs("mine", with_conflicts=False, with_builds=False):
    ci = jwu.builds(p.id, p.project, p.repository)
    rows.append((p.id, ci.build_state, (ci.autotests or {}).get("summary")))
rows
```

Замер на реальных данных: «сборки и автотесты по 15 моим PR» — 16 вызовов и ~49 тыс. символов
ответов через инструменты, через `jwu_query` — ~0,7 тыс.; «задача + PR + замечания + сборки» —
~17,5 тыс. → ~3 тыс.

## Что умеет

- `jwu_query(code)` — выполнить скрипт; итог — переменная `result` или последнее выражение, плюс
  `print`. В ответе ещё `calls`: какие методы вызваны и сколько весил каждый ответ.
- `jwu_query_help()` — шпаргалка: методы `jwu.*`, сигнатуры, лимиты, пример. Методы — те же
  функции, что у инструментов `jwu_*` (задачи, PR, дифф, сборки и автотесты, работы, заметки,
  контекст, упоминания, ветки, Confluence, Zephyr …), ответы — словари с доступом через точку.

## Только чтение

В API скрипта нет записи. Комменты, пуши, переходы задач, ворклоги, правила — по-прежнему
отдельными инструментами `jwu_*` после «да» пользователя; параметры чтения, которые что-то
сохраняют (скачать вложения, сохранить заметки передачи), в скрипте прибиты.

## Песочница

Скрипт идёт в отдельном процессе `python -I` с пустым окружением (токенов там нет) и jwu не
импортирует. Объект `jwu` только пересылает вызовы в MCP-сервер, тот исполняет методы из белого
списка. Запрещено (audit hook): открывать файлы, импортировать то, что не загружено заранее
(доступны json, re, math, datetime, collections, itertools, statistics), запускать процессы,
сеть, менять файлы и папки. Лимиты: 200 вызовов, 90 с на скрипт, 20 с процессорного времени,
итог до 20 тыс. символов.

Это барьер против обхода проверок записи jwu, а не изоляция от злонамеренного кода: у агента и
так есть Bash. Хук git и запрет прямого доступа к базе jwu скрипт не обходит.

## Метрики

Каждый вызов MCP-инструмента jwu записывается локально, без аргументов и содержимого: какой
инструмент, сессия, воркспейс, время, размер ответа, успех. У `jwu_query` — ещё вызовы внутри
скрипта и вес их сырых ответов. Хранится 30 дней.

```bash
jwu stats tools [--days 7] [--workspace work] [--json]   # отчёт
jwu stats tools --reset                                  # начать замер с нуля
```

В отчёте: какие инструменты съедают контекст, сколько сэкономил `jwu_query`, и **упущенные
цепочки** — три и больше чтений одной сессии подряд (в пределах минуты) мимо `jwu_query`. По ним
видно, в какой скилл дописать подсказку.
