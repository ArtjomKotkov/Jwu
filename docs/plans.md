# Планы

План — дерево шагов к одной цели с зависимостями, ожиданиями и доказательствами. Он отвечает на
«что дальше, что ждёт меня, что уже сделано и чем это проверено» — без пересказа из памяти сессии.
В воркспейсе может быть несколько планов; один можно поставить в фокус. Предложение и дальнейшие
этапы — [proposals/plans.md](proposals/plans.md).

```bash
jwu plan create "Новый движок" --goal "вся механика — через движок" --rule "агенты на opus" --need code
jwu plan add PLAN-1 "Сервер" --key 4а
jwu plan add PLAN-1 "Фронт" --key 4б --after 4а
jwu plan now                      # что идёт, что ждёт тебя, что стоит и почему, что можно брать
jwu plan next                     # какие шаги можно брать прямо сейчас
jwu plan show PLAN-1              # дерево шагов, правила, последние события
jwu plan step PLAN-1/4а -s doing --job 61
jwu plan step PLAN-1/4а -s done --evidence "tests:pytest 40 passed@job:61"
```

Агент делает то же через MCP: `jwu_plan_create`, `jwu_plan_step_add`, `jwu_plan_step`, `jwu_plan`,
`jwu_plan_now`, `jwu_plan_next`, `jwu_plan_edit`.

## Шаг

- **Ключ** — свой («4а») или следующий номер; адрес — `PLAN-1/4а`. Подшаги — `parent`.
- **after** — какие шаги должны быть сделаны раньше, в том числе из другого плана (`PLAN-2/5`).
  Круг — отказ.
- **waits** — чего ещё ждёт: вопрос владельцу, владелец, внешнее событие, ресурс. Снимается
  `resolve_waits`.
- **Состояние** ставится руками: todo, doing, review, done, dropped. «Заблокирован» и «ждёт
  владельца» jwu вычисляет сам из `after` и `waits`.
- **executor** — main, owner или `agent:<имя>`. Шаги владельца `jwu plan next` не раздаёт.
- **links** — работы шага (`jobs`), коммиты, файлы, задача, рабочая копия. По файлам `next` не
  выдаёт два шага на одни и те же файлы.
- **where** — куда дошло: none, branch, main, stand, prod.

## Что jwu не даст

- **«Готово» без доказательства.** Нужно хотя бы одно, плюс виды из `needs` плана и шага (`code` —
  tests или build, `ui` — browser или screenshot). Ссылку jwu проверяет:
  - файл должен существовать;
  - коммит должен быть в репозиториях воркспейса;
  - у работы (`job:<id>`) для tests должна быть запись test-pass.
- **«Готово» с остатком.** Непустой `leftovers` — отказ, пока каждый пункт не стал шагом.
- **Начать раньше времени.** В doing — только когда всё из `after` сделано и ожидания сняты.
- **Тихо откатить основу.** Вернуть сделанный шаг, на котором уже строят, — только с `force`.
- **Молча освободить зависимых от отменённого шага.** Зависимые остаются «ждёт отменённый шаг»,
  пока их не отвяжут или не отменят.

Когда шаг закрылся, ответ говорит, какие шаги освободились.

## Шаги и работы

- `jwu_job_start(step="PLAN-1/4а")` заводит работу сразу на шаг. К уже заведённой работе шаг
  привязывается через `links={"jobs": [id]}`.
- У шага может быть несколько работ.
- Передача работы (`jwu_job_handoff`) показывает её шаг: что сделать, правила плана, чего ждёт и
  какие доказательства нужны для «готово».
- Все изменения шага пишутся в журнал плана: в `jwu plan show` видно, кто и когда что менял.
