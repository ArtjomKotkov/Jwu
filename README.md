# jwu

CLI для **Jira Server / Data Center** + **Bitbucket Server** с локальной памятью
(кэш задач/PR, дельты между синками, заметки) — и набор скиллов для Claude Code.

- **Воркспейсы** — независимые контуры (рабочий, личный): свои папки, свои интеграции,
  свои данные. Определяется автоматически по текущей папке. Папки можно помечать
  тегами (`legacy-бэкенд`, `новая-версия`) — по ним понятно, где что лежит.
- Задачи по фильтрам: мои активные / упоминания / ждут моего ревью (PR).
- Живой TUI-дашборд с авто-обновлением.
- «Работы (jobs)» — журнал работы над задачей (фазы, баги, тесты, решения).
- **Локальные фичи** — мини-трекер для контуров без Jira: тот же журнал работ,
  ключи в формате `HOMEJWU-1` (годятся как префикс ветки и коммита).

---

## 1. Установка

Требуется **Python 3.10+**. Ставим как CLI-приложение через [pipx](https://pipx.pypa.io):

```bash
# из git
pipx install git+https://github.com/ArtjomKotkov/jwu.git

# или из локальной копии репозитория
cd jwu && pipx install .
```

Для разработки — poetry: `poetry install`, запуск `poetry run jwu …`.

## 2. Сделать доступным как `jwu`

pipx кладёт бинарь в `~/.local/bin`. Один раз добавь его в PATH и перезапусти шелл:

```bash
pipx ensurepath
```

Проверка:

```bash
jwu --help
```

Обновить после изменений — **два шага** (второй легко забыть):

```bash
pipx install --force .       # CLI и MCP-сервер
jwu install-claude-skills    # скиллы и субагенты в ~/.claude
```

MCP-сервер живёт процессом: новые инструменты `jwu_*` появятся только после перезапуска
сессии Claude Code. Для разработки удобнее `pipx install --force --editable .` — тогда
правки кода подхватываются без переустановки. Есть скилл `/jwu-update`, который делает
это и проверяет результат.

## 3. Воркспейсы и конфигурация

### Воркспейс

**Воркспейс** — контур работы: набор папок + подключённые интеграции + свои локальные данные
(работы, фичи, заметки, анализы, снапшоты). Данные контуров не пересекаются.

Активный воркспейс определяется в таком порядке: флаг `-W/--workspace` → переменная
`JWU_WORKSPACE` → **текущая папка** (если она привязана; у вложенных выигрывает самая глубокая
привязка) → последний выбранный (`jwu workspace use`) → единственный. Не определился —
CLI объяснит, что делать, а `jwu dashboard` откроется на экране выбора.

```bash
jwu workspace list                 # все контуры
jwu workspace current              # что резолвится здесь и ПОЧЕМУ
jwu workspace create home-jwu --name "Личное" --path . --no-jira --no-bitbucket
jwu workspace use work             # активный для команд вне привязанных папок
jwu workspace show                 # папки, интеграции, счётчики, настройки (секреты — ****)
```

### Папки и теги — «где что лежит»

Папки воркспейса отвечают на вопрос, **где находится код проекта**: скиллы ищут и правят
только в них. Теги объясняют, что есть что, когда репозиториев несколько.

```bash
jwu workspace add-path ~/dev/backend --tag legacy-бэкенд --tag django
jwu workspace add-path ~/dev/backend-v2 --tag новая-версия
jwu workspace tag ~/dev/front --add фронт          # пометить уже привязанную
jwu workspace paths                                # все папки с тегами
jwu workspace paths --tag legacy-бэкенд            # найти нужную
```

Теги видны и в дашборде (вкладка «Структура»), и агенту — через `jwu_workspace_paths(tag=…)`.

### Правила воркспейса

Папки и теги говорят, ГДЕ лежит код. Правила — то, что знает о проекте человек, но не знает
код: что нельзя делать, как поднять стенд, где что лежит. Они хранятся рядом с контуром и
**сами приезжают в контекст при работе над любой задачей**, так что пересказывать их каждую
сессию больше не нужно.

Пять типов: `constraint` (⛔ запрет), `howto` (🛠 как делать), `convention` (📐 соглашение),
`gotcha` (⚠ грабли), `info` (ℹ справка). Правило либо общее для контура, либо привязано
к тегу папки — тогда оно относится только к этому репозиторию.

```bash
jwu rule add "Не пушить в develop напрямую" --kind constraint
jwu rule add "Как поднять стенд" --kind howto --tag legacy-бэкенд --file -   # текст из stdin
jwu rules                      # всё
jwu rules --tag legacy-бэкенд  # правила этого репо И общие (общие действуют везде)
jwu rule show 2 · jwu rule edit 2 --kind info · jwu rule rm 2
```

Агент получает контекст проекта одним куском — и в `jwu_workspace_current()`, и в ответе
`jwu_job_start()` (то есть правила и структура доезжают до первой правки, даже если скилл
поленился): `paths` с тегами и `known_tags` — JSON, его фильтруют; `rules_md` — готовый
markdown, его читают и исполняют. Общие правила там целиком, у правил конкретных
репозиториев — только заголовки; полный текст берётся вторым вызовом `jwu_rules(tag=…)`,
когда уже понятно, где правим. Иначе инструкция по стендам уезжала бы в контекст каждого
скилла, включая те, что до кода не доходят. Записи `⛔ ЗАПРЕТ` скиллы обязаны соблюдать,
а не обходить молча.

В дашборде правила живут на вкладке **Правила** (нижний ряд, сразу за «Структурой»):
`enter` — карточка с полным текстом, `N` — добавить, `e` — править, `D` — удалить.
Так «поправь в legacy-бэкенде» перестаёт быть загадкой.

Интеграции объявляются **явно** при создании (`--jira/--no-jira`, `--bitbucket/--no-bitbucket`).
В контуре без Jira её команды не молчат, а отказывают с подсказкой; вкладки Jira/PR в дашборде
скрываются, вместо них — «Фичи».

### Доступы

Визард спрашивает хосты, логин, токен/пароль и путь до БД, сохраняет в **активный воркспейс**
и проверяет связь:

```bash
jwu configure            # текущий воркспейс
jwu configure -W work    # конкретный
jwu auth check
```

Настройки и секреты воркспейса хранятся **в БД jwu** (`~/.local/share/jwu/state.db`).
Секреты лежат там **в открытом виде**; файл закрывается правами 600, каталог бэкапов — 700.

> ⚠️ Не держи БД в облачной папке (iCloud/Dropbox/Google Drive): туда уедут токены.
> jwu предупредит об этом сам. Нужен облачный синк — задавай токены переменными окружения.

**Переменные окружения перекрывают БД** (удобно на серверах и в CI):
`JIRA_TOKEN`, `SDESK_TOKEN`, `BITBUCKET_TOKEN`, `JENKINS_TOKEN`.

Неинтерактивно (CI/серверы):

```bash
jwu configure --non-interactive \
  --jira-host https://jira.acme.com --jira-user alice --jira-token "$JIRA_TOKEN" \
  --bitbucket-host https://git.acme.com --bitbucket-token "$BITBUCKET_TOKEN"
```

Если перед Jira стоит nginx Basic-гейт — `--gate-user/--gate-password`.

### Переезд со старой версии

Ничего делать не нужно: при первом запуске старый `~/.config/jwu/config.toml` и секреты из
системного keyring переносятся в воркспейс **«Работа»** (`work`), все накопленные работы и
снапшоты достаются ему же. Перед структурной миграцией снимается копия БД
(`~/.local/share/jwu/backups/state.db.pre-v<N>-<дата>`). Keyring **не чистится** и остаётся
фолбэком на чтение, поэтому откат на прежнюю версию jwu ничего не ломает.
Перенести вручную: `jwu workspace migrate`.

**Путь до БД** остаётся глобальным (`[storage].db_path` в config.toml, `jwu configure --db-path …`
или env `JWU_DB_PATH`) — её надо найти до того, как известен воркспейс. jwu раз в день делает
локальный бэкап и проверяет целостность. Не запускай jwu на двух устройствах одновременно
поверх одной БД в облаке (риск конфликта файла).

### Размер БД и чистка снапшотов

Снапшоты задач и PR нужны только для сравнения соседних синков, но копятся вечно — на
рабочей базе это десятки тысяч строк и гигабайты файла, которые вдобавок каждый день
копирует бэкап. Поэтому jwu **раз в день сносит снапшоты старше 30 дней** — но только если
файл БД перевалил за 256 МБ и только **после** сегодняшнего бэкапа (чистка необратима).

Сохраняется всё, на чём держится расчёт дельт: свежайший снапшот каждой задачи и PR,
свежайший снапшот с достоверной dev-панелью и последние надёжные прогоны каждой вкладки.
Иначе следующий синк объявил бы половину задач новыми, а половину — ушедшими.

`VACUUM` (пересборка файла, десятки секунд на гигабайте) делается только когда после
чистки освободилось больше 25% файла.

```bash
jwu db stats                 # сколько занимает и из чего состоит
jwu db prune                 # сухой прогон: что удалилось бы (по умолчанию)
jwu db prune --apply         # собственно удалить
jwu db prune --apply --vacuum
jwu db vacuum                # вернуть освободившееся место ОС
```

## 4. Дашборд и авто-синк

```bash
jwu dashboard            # TUI из памяти (быстро, без сети)
jwu dashboard --sync     # сначала синхронизировать всё, потом открыть
jwu dashboard -a         # авто-обновление (см. ниже)
```

Режим `-a` (`--auto-update`):
- локальные вкладки (Работы/Фичи) — из памяти каждые **5с** (`--fast-interval`);
- сетевые таблицы (задачи/PR) — фоновый синк каждые **10 мин** (`--slow-interval`);
- открытый детальный экран — раз в **60с** (`--detail-interval`).

Дашборд открывается на том воркспейсе, где ты его закрыл: его держат одним окном и
переключают руками (`W`), поэтому папка запуска для него не указ. Всем остальным командам,
скиллам и MCP папка по-прежнему важнее — они работают в контексте проекта, из которого их
позвали. Перебить и то и другое можно флагом `-W`.

Вкладки идут **двумя рядами**. Наверху — **Workspace**, выбор контура: это единственное,
что не зависит от того, какой воркспейс активен. Внизу — всё его содержимое: **Структура**
(дерево папок) и **Правила** (что агент обязан знать о проекте) идут первыми — с них
начинают в незнакомом контуре, — дальше **Мои задачи**/**Упоминания** (при подключённой
Jira), **PR: мои**/**PR: на ревью** (при Bitbucket), **Фичи** (наоборот, только там, где
Jira нет) и **Работы** (всегда). Ряд, которому активная вкладка не принадлежит, приглушён.
`[` и `]` листают все видимые вкладки подряд, обоими рядами.

Панель **Изменения** (`b`) показывает изменения только активной вкладки и группирует их
по сущностям: заголовок «ключ: название» и под ним список того, что в ней случилось
(новые комментарии, смена статуса, апрувы, конфликт). `c` — очистить активную вкладку,
`C` — все.

**Упоминания** — это сами упоминания, а не задачи: каждое найденное `[~логин]` в комментарии
становится отдельной записью один раз и дальше не меняется, за задачей никто не следит.
Непрочитанные помечены точкой, счётчик на вкладке — это их число; карточка задачи тянется
из сети только при заходе внутрь (`enter`), и он же снимает пометку.

На вкладке **Работы** строки разбиты по дням: заголовок дня — черта во всю таблицу с
подписью «Сегодня — 30.07.2026» (сначала словами, потом дата; свежесть видна цветом),
а закончившийся день отбит от следующего пустой строкой. Разбивка работает при сортировке
по времени (по умолчанию); отсортируешь по другой колонке — черты пропадут.

На вкладке **Структура** папки показаны деревом: `→`/`←` (или мышь) раскрывают и сворачивают,
у каталогов-репозиториев виден маркер `имя/ветка`, рядом — теги папки. Структура
переиндексируется в фоне, интервал — `--index-interval` (по умолчанию 120 с).

Экран по умолчанию занят только данными: панель **Изменения** скрыта (`b` — показать/убрать),
поиск задачи — модалка по `/`, а легенда клавиш — модалка по `?`. Легенда собирается под то
окно, где ты стоишь: сверху клавиши текущей вкладки или карточки, ниже общие. Внизу остаётся
одна строка состояния — синк, память, кто ты.

Клавиши: `?` — легенда, `/` — поиск задачи, `b` — панель изменений, `enter` — детали,
`o` — открыть (браузер или файловый менеджер), `y` — скопировать ключ, `Y` — меню копирования,
`R` — синк всего, `c` — очистить изменения вкладки, `W` — быстрый выбор воркспейса,
`N` — создать (воркспейс, фичу или правило — по вкладке), `a` — добавить папку,
`D` — удалить/отвязать выбранное, `q` — выход.

**Буфер обмена (`y` / `Y`):** `y` — сразу ключ Jira (или ключ задачи у работы); `Y` — модалка с
атрибутами (URL, markdown-ссылка, заголовок и др. — набор зависит от контекста). Навигация ↑↓ /
`j` `k`, копирование — `enter`, клик или горячая клавиша пункта. jwu использует
[pyperclip](https://pypi.org/project/pyperclip/)
— он уже ставится вместе с пакетом. На **macOS** и **Windows** дополнительно ничего не нужно. На
**Linux** нужна утилита для работы с clipboard в вашей сессии:

| Среда | Пакет |
|---|---|
| X11 | `xclip` или `xsel` |
| Wayland | `wl-clipboard` (команда `wl-copy`) |

Примеры: `sudo apt install xclip` (Debian/Ubuntu, X11), `sudo apt install wl-clipboard` (Wayland).
Без этих утилит копирование покажет ошибку в уведомлении TUI.

Без TUI: `jwu sync` — разовый полный синк.

## 5. Скиллы и субагенты для Claude

В репозитории шипуются и **скиллы** (`src/jwu/skills/<имя>/SKILL.md`), и **дефолтные субагенты**
(`src/jwu/agents/<имя>.md`) — можно взять прямо из git.

**Claude Code** — установить одной командой (копирует скиллы в `~/.claude/skills` и субагентов
в `~/.claude/agents`, обновляя существующие):

```bash
jwu install-claude-skills                   # каталог скиллов — флагом --dest
                                            # каталог агентов — флагом --agents-dest
                                            # пропустить агентов — флагом --skip-agents
```

**Другой агент / не Claude** — скорми содержимое нужного `SKILL.md` из `src/jwu/skills/`
своему инструменту (это обычные markdown-инструкции, без привязки к Claude).

### Вызов скиллов в Claude Code

Подхватываются **автоматически по фразам-триггерам**, либо явно слэш-командой:

| Скилл | Когда / как |
|---|---|
| `/jwu-workspace-setup` | «подключи jwu к этому проекту», «jwu не видит мою папку» — завести/подключить воркспейс (`jwu init`), привязать репозитории, расставить теги |
| `/jwu-update` | «обнови jwu», «нет инструмента jwu_*», «скилл не подхватился» — переустановка пакета + скиллов и диагностика старого MCP-сервера |
| `/jwu-start-job` | «начни работу по ABC-123», «проанализируй задачу» — анализ + план + создание работы (последняя фаза = ревью) |
| `/jwu-resume-job` | «на чём остановились», после очистки контекста — восстановить состояние работы |
| `/jwu-track-job` | «запиши баг/решение/прогон тестов», «отметь фазу done» — лог прогресса |
| `/jwu-job-review <reviewer-subagent>` | «прогони ревью», «code review этого PR» — запуск явно указанного субагента-ревьювера с контекстом задачи+PR+диффа; результат пишется в работу записями `--kind review` (шапка с якорями `[B*]/[I*]/[M*]`) + детальные `remark`/`bug`/`warning`/`constraint` |
| `/jwu-commit-message` | «напиши коммит», «коммит-месседж» — генерирует текст из текущих изменений (staged + unstaged); префикс `EXAMPLE-1111:` подставляется из имени ветки, нет префикса → без него; печатает текст, `git commit` делает пользователь |
| `/jwu-analyze-day` | «разбери мой день» — план по задачам и PR на сегодня |
| `/jwu-post-analyze-day` | «что я сделал сегодня» — итоги для трекинга времени |

### Дефолтные субагенты

| Субагент | Когда |
|---|---|
| `reviewer-jwu-sample` | Универсальный код-ревьювер по 10-пунктовому чек-листу (баги, безопасность, нейминг, миграции, потеря правок из target, и пр.). Используется `/jwu-job-review` как дефолт, если для проекта нет более специфичного ревьювера. |

Свой проектный ревьювер (напр. `reviewer-myproject-django`) добавляется как обычный субагент
Claude Code в `~/.claude/agents/` и вызывается тем же скиллом: `/jwu-job-review reviewer-myproject-django`.

## Команды

Глобальный флаг `-W/--workspace <slug>` (или env `JWU_WORKSPACE`) выбирает воркспейс
для любой команды; без него он определяется по текущей папке.

| Команда | Что делает |
|---|---|
| `jwu workspace …` | воркспейсы: `list`/`create`/`use`/`current`/`show`/`add-path`/`remove-path`/`tag`/`paths`/`rename`/`delete`/`migrate` |
| `jwu feature …` | локальные фичи: `add`/`list`/`show`/`status`/`edit`/`rm` (алиас `jwu features`) |
| `jwu rule …` | правила воркспейса: `add`/`list`/`show`/`edit`/`rm` (алиас `jwu rules`) |
| `jwu changes` | дельты с прошлого синка |
| `jwu configure` | настройка хостов/логинов/секретов воркспейса (`-W`), путь до БД |
| `jwu db …` | файл БД: `stats` / `prune` (по умолчанию сухой прогон) / `vacuum` |
| `jwu dashboard` | живой TUI (`--sync`, `-a`) |
| `jwu auth check` | проверка доступа к Jira и Bitbucket |
| `jwu sync` | разовый синк вью + PR, снапшот в память, расчёт дельт |
| `jwu tasks --view mine\|mentions` | список задач (есть `--jql`) |
| `jwu task ABC-123` | полная карточка: описание, комменты, dev-панель |
| `jwu prs --view mine\|review` / `jwu pr <id>` | PR с ревьюерами и статусом конфликта |
| `jwu note KEY "…"` / `jwu notes KEY` | заметки по задаче |
| `jwu job …` | работы: `start`/`add`/`show`/`done` и т.д.; якорь — задача Jira, локальная фича (`--feature`) либо ничего |
| `jwu install-claude-skills` | развернуть скиллы в `~/.claude/skills` и дефолтных субагентов в `~/.claude/agents` |

У большинства команд есть `--json` (для интеграции с агентами).
